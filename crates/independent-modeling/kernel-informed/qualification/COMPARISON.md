# Геометрическое сравнение clean и kernel-informed

Дата: 2026-10-30. Среда: macOS ARM64, Rust stable 1.98.1.

Источник чисел: исполняемый `compare_kernels`; полные данные в
[comparison.json](comparison.json). Это сравнение собственных реализаций и
представлений, без запуска Plasticity и без измерения скорости.

| Сценарий | Чистая база | Новое ядро |
|---|---|---|
| Цилиндр r=2, h=5 | 32-сегментная сетка, объём 62.428903045161 | Сохранённая рациональная граница, аналитическое измерение 62.8318530717959 |
| Ошибка объёма цилиндра относительно 20π | 0.402950026635 | Формула совпадает с аналитическим reference в binary64 |
| Смена display resolution цилиндра | Тело представлено сеткой | 48 / 400 треугольников при неизменных 6 faces и 12 edges |
| Loft несовпадающих узлов | Отказ | Common refinement, 6 spans, максимальная ошибка границ по 201 точке 9.1551e-16 |
| Пересечение кубов при повороте 45° | Эквивалентного API нет; box CSG осевой | Объём 6.62741699796952, ошибка 3.5527e-15; manifold display mesh |
| Разность convex solids | Нет соответствующего API для повёрнутых тел | 4 convex pieces, ошибка сохранения объёма 8.8818e-16 |

Для объёма цилиндра показан переход от суммирования треугольников к аналитической
формуле для поддерживаемого класса тел, а не нулевая ошибка всех операций ядра.
Чистая Curve/Surface рациональная математика уже использует те же определения:
сравнение не объявляет её вычисление точек менее точным.

Кольцевая экструзия сохраняет 10 faces и два контура каждой cap; её display mesh
замкнута. Общий профиль с произвольными отверстиями не реализован.

Новый loft сохраняет заданные профили, но остаётся piecewise ruled по секциям.
Convex difference возвращает разложение с внутренними интерфейсами, не единую
сшитую внешнюю boundary. Числа относятся только к этому набору сценариев.
