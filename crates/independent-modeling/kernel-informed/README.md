# modeling-kernel-informed

Отдельное геометрическое ядро. Оно не зависит от `modeling-informed` и не содержит
документ, undo/redo, фоновые задачи или display cache. Общие рациональные Curve /
Surface, математика и Mesh взяты из собственного замороженного `modeling-clean`.
Поверх них независимо написаны новые геометрические алгоритмы и представления.
Существующие `nurbs-core` / `brep-core` и любые проприетарные библиотеки не используются.

## Отличия от чистой версии

| Задача | Чистая база | Это ядро |
|---|---|---|
| Экструзия круга как тела | Faceted cylinder либо открытая рациональная боковая поверхность | Замкнутая сохранённая граница: две плоские trimmed caps, четыре рациональные боковые поверхности, вершины/рёбра/coedges |
| Кольцевой профиль | Нет прямой рациональной solid-extrusion операции | Два граничных контура; отверстие в обеих caps; восемь боковых поверхностей |
| Экструзия полигона | Сеточное тело в XY с положительной высотой | Сохранённые плоские поверхности и топология; произвольная ортонормальная рабочая плоскость и непараллельный вектор, включая отрицательное направление |
| Изменение детализации | Сетка и есть тело | Отдельная тесселяция неизменного тела и карта triangle → source face |
| Loft разных базисов | Отказ при разных степенях/узлах | Нормализация доменов, common span partition, рациональное Bezier degree elevation без подгонки |
| Пересечение тел | CSG только осевых боксов | Halfspace clipping выпуклых planar polyhedra, включая повёрнутые боксы и призмы |
| Вычитание выпуклого тела | Только осевые боксы | Разложение разности на части с непересекающимися внутренностями; сохранённые внутренние интерфейсы |

Изменение точности отображения не меняет исходные кривые, поверхности и топологию.
Объём экструзии вычисляется по площади профиля и нормальной компоненте вектора,
а не по display mesh. Это различие представлений, не доказательство численного
превосходства всех операций и не результат сравнения с самим Plasticity.

## B-rep экструзии

`brep::Profile::{polygon,disk,annulus}` создают проверяемые профили. Polygon
принимает один простой контур без отверстий; Disk/Annulus используют рациональные
квадратичные дуги. Annulus — строго концентрическая пара окружностей, не общий
профиль с произвольными holes. Профиль сохраняет material-left ориентацию.

`Body::extrude` сохраняет carrier surfaces и trimming wires как coedge loops.
Плоские cap carriers покрывают bounding rectangle; область грани задаётся её
контурами, а не всем прямоугольником carrier. `BoundaryTrack` сопоставляет каждую
исходную граничную кривую нижнему/верхнему ребру и боковой грани.

`Body::audit` проверяет замкнутые индексированные контуры, противоположное
использование каждого ребра и endpoint gaps в заданном допуске. Это аудит данного
конструктора, не сертификат произвольного импортированного trimmed B-rep.
Новые тела нельзя получить путём подмены carrier сеткой.

`tessellate(chord_tolerance, max_segments)` вычисляет круговую сегментацию из
формулы sagitta и возвращает source-face mapping. `boundary_chord_deviation`
описывает отклонение круговой хорды в вещественной арифметике; это не строгий
binary64 Hausdorff-сертификат. Ограничение max_segments относится к окружности.

```rust
use modeling_kernel_informed::brep::{Body, Profile, Frame};
let body = Body::extrude(
    Profile::annulus([0.0, 0.0], 3.0, 1.0)?,
    Frame::xy(), [0.0, 0.0, 4.0], 1e-9,
)?;
assert_eq!(body.faces().len(), 10);
assert_eq!(body.faces()[0].loops.len(), 2);
let display = body.tessellate(0.01, 4096)?;
assert!(display.mesh.topology().is_closed_manifold());
# Ok::<(), modeling_kernel_informed::Error>(())
```

## Совместимость loft

Все профили сохраняют своё направление и соответствие параметров, выбранное
вызывающим кодом. Домен нормализуется к [0,1]; собираются все knot spans;
каждый span переводится в Bezier-форму и повышается в однородных координатах до
общей степени. Подгонки по семплам нет. Сборка использует C0 knot multiplicity;
сама геометрия может сохранять более высокую гладкость исходных кривых.

Профили с разрывом отказываются, а не автоматически «исправляются». Loft остаётся
piecewise ruled по секциям: это не smooth variational loft, не G2 solver и не
closed solid loft с автоматически найденными caps.

## Planar clipping

`planar::Convex` принимает замкнутые выпуклые многогранники с outward CCW faces.
Проверяет planarity, convex halfspaces, indexed incidence и положительный объём.
`clip` сохраняет одну сторону плоскости; `intersection` применяет плоскости второго
тела. Контакт только по грани/ребру/точке regularizes to empty. Origin каждой
выходной грани сохраняет authored/clip-plane provenance; clip-plane tags задаёт
вызывающая операция и они не являются глобальными постоянными IDs.

`subtract_partition` возвращает набор closed convex pieces и отдельно overlap.
Внутренние интерфейсы остаются: это не готовая единая сшитая boundary разности.
Нет union/XOR произвольных planar solids, clipping криволинейных граней, автоматики
healing или nonconvex B-rep Boolean. Узкие/неразрешимые случаи могут отказываться.

Допуски operands должны совпадать. При реальном разрезе вершины в tolerance band
проецируются на секущую плоскость. Проверка не использует exact predicates и не
обещает устойчивость во всём диапазоне floating point. Предел: 256 faces, 512
points на face, 16384 face-point occurrences. Аффинное преобразование сохраняет
численный допуск в мировых единицах; подходящий допуск выбирает вызывающий код.

## Сравнение и проверки

```sh
cargo +stable test -p modeling-kernel-informed
cargo +stable clippy -p modeling-kernel-informed --all-targets -- -D warnings
cargo +stable run -p modeling-kernel-informed --example compare_kernels -- target/kernel-comparison
python3 verify_clean.py
```

Команды запускаются из родительского workspace. Пример сохраняет JSON и OBJ,
сравнивая представления и доступные входы; это не speed benchmark и не запуск
Plasticity. См. [источники решений](PROVENANCE.md). Чистый baseline не изменён.
