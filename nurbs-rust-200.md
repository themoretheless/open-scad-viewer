# 200 самых нужных вещей для NURBS в Rust

Список для разработчика, который реализует NURBS-геометрию на Rust (CAD-вьюер уровня OpenSCAD). Основа — «The NURBS Book» (Piegl & Tiller), ссылки на алгоритмы даны по нумерации книги (A2.1 и т.д.). Статус Rust-крейтов проверен поиском на октябрь 2026.

## Часть I. Кривые и базовая математика (1–100)

### Базовая математика (1–16)

1. **Вектор vs точка** — разделяйте `Vector3` и `Point3` (как в nalgebra): точки транслируются, векторы нет; ловит половину багов CAD-геометрии на этапе компиляции.
2. **Однородные координаты** — точка NURBS хранится как (w·x, w·y, w·z, w); кривая в R³ — проекция 4D B-сплайна на гиперплоскость w=1.
3. **Проективное деление** — евклидова точка = xyz/w; делайте деление один раз в конце, а не после каждой операции.
4. **Многочлены Бернштейна** — B_{i,n}(t) = C(n,i)·tⁱ·(1−t)^{n−i}, базис кривых Безье, из которого «вырастают» B-сплайны.
5. **Разбиение единицы** — Σ B_{i,n}(t) = 1 для всех t; гарантирует аффинную инвариантность, удобно как property-тест реализации.
6. **Алгоритм де Кастельжо** — рекурсивная линейная интерполяция точек Безье; численно устойчивее прямого вычисления по Бернштейну.
7. **Цветок (blossom / полярная форма)** — симметричная мульти-аффинная форма полинома; теоретический ключ к knot insertion и соединению сегментов.
8. **Схема Горнера** — оценка полинома за n умножений-сложений; для малых степеней быстрее и стабильнее явных степеней.
9. **Вектор узлов (knot vector)** — неубывающая последовательность {u₀..u_m}, m = n + p + 1 (n+1 контрольных точек, степень p); валидируйте инвариант в конструкторе.
10. **Knot span** — интервал [u_i, u_{i+1}); на нём кривая — один полиномиальный сегмент, ровно p+1 базисных функций не равны нулю.
11. **Формула Кокса–де Бура** — рекурсивное вычисление N_{i,p}(u) через N_{i,p−1} и N_{i+1,p−1}; ядро всего evaluation. Реализуйте итеративную «треугольную» таблицу, не рекурсию.
12. **Локальная поддержка** — N_{i,p}(u) ≠ 0 только на [u_i, u_{i+p+1}); движение одной контрольной точки меняет локальный участок — используйте для инкрементальных обновлений.
13. **Правило 0/0 = 0** — при вырожденных узлах в рекурсии возникает 0/0; по определению результат 0. Обрабатывайте явно, иначе NaN.
14. **FindSpan (бинарный поиск интервала, A2.1)** — span-индекс для u за O(log n); кэшируйте span между последовательными вызовами при сэмплировании.
15. **BasisFuns (A2.2)** — все p+1 ненулевых базисных функций одним проходом; стандарт де-факто для evaluation-ядра.
16. **Сравнение узлов с epsilon** — узлы из STEP/IGES почти совпадают, но не бит-в-бит; кратность считайте через epsilon, не `==`.

### Определение и вычисление кривой (17–30)

17. **B-сплайн кривая** — C(u) = Σ N_{i,p}(u)·P_i.
18. **NURBS кривая** — C(u) = Σ N_{i,p}·w_i·P_i / Σ N_{i,p}·w_i; без весов это обычный B-сплайн.
19. **RationalBasisFunction** — R_{i,p}(u) = N_{i,p}·w_i / Σ N_{j,p}·w_j; рациональные базисы тоже образуют разбиение единицы.
20. **Оценка в однородном пространстве** — сначала 4D B-сплайн C^w(u) = Σ N_{i,p}·(w_i·P_i, w_i), затем деление на w: единый код для рационального и нерационального случаев.
21. **Алгоритм де Бура** — прямая оценка повторной линейной интерполяцией контрольных точек (аналог де Кастельжо); устойчив, удобен для отладки против Cox-de Boor.
22. **Производные базисных функций** — N′_{i,p} = p·(N_{i,p−1}/(u_{i+p}−u_i) − N_{i+1,p−1}/(u_{i+p+1}−u_{i+1})).
23. **DersBasisFuns (A2.3)** — одна треугольная таблица: базис + все производные до k-го порядка; фундамент касательных, кривизны, офсетов.
24. **CurveDerivsAlg1 (A4.2)** — производные кривой как производные 4D B-сплайна; для рационального случая — правило частного к A_k/w.
25. **Годограф** — C′(u) сама B-сплайн степени p−1 с точками p·(P_{i+1}−P_i)/(u_{i+p+1}−u_{i+1}) и укороченным вектором узлов.
26. **Производные на концах** — у clamped-кривой C′(u_min) = p/(u_{p+1}−u₁)·(P₁−P₀): касательная вдоль первой ноги полигона; полезно для сшивки G1.
27. **Контрольный полигон** — ломаная через P_i; кривая в его выпуклой оболочке и «утирается» в него с ростом кратности узлов.
28. **Variation-diminishing** — любая плоскость пересекает кривую не чаще, чем контрольный полигон; используется в подсчёте перегибов.
29. **Аффинная инвариантность** — преобразование кривой = преобразование контрольных точек; никогда не трансформируйте сэмплированные точки.
30. **Эндпоинт-интерполяция** — clamped-вектор (кратность p+1 на концах) проводит кривую через P₀ и P_n; стандарт для интерактивного редактирования.

### Операции с вектором узлов (31–44)

31. **Кратность узла** — повтор s раз снижает гладкость до C^{p−s}; кратность p — C⁰-излом, p+1 — разрыв.
32. **Clamped vs unclamped** — clamped: кратность p+1 на концах (кривая касается концов полигона); unclamped/periodic — для замкнутых гладких кривых.
33. **Uniform vs non-uniform** — равномерные узлы дают предсказуемую параметризацию; неравномерные — контроль формы.
34. **Нормализация вектора узлов** — приведение к [0,1] упрощает сравнение и сериализацию; для открытых кривых иногда удобнее физические длины.
35. **Валидация вектора** — неубывание, m = n+p+1, кратность внутренних узлов ≤ p; дешёвая проверка при десериализации.
36. **Knot insertion (A5.1)** — добавление узла не меняет кривую, но даёт новый полигон; базовый инструмент редактирования и разбиения.
37. **Формулы Бёма** — новые точки при вставке: α_i·P_i + (1−α_i)·P_{i−1}; вставка p раз кладёт точку на кривую.
38. **Вставка до полной кратности** — доведение внутреннего узла до кратности p делит кривую на две независимые части; основа split/subdivide.
39. **Knot refinement (A5.4)** — одновременная вставка множества узлов; эффективнее последовательных вставок при тесселяции и объединении.
40. **Knot removal** — удаление узла с минимальным изменением формы; точно возможна, только если кривая допускает повышенную гладкость на узле.
41. **Критерий удалимости (A5.8)** — узел удалим, если отклонения восстановленных точек в пределах допуска; итерируйте до tolerance.
42. **Merge knot vectors** — при объединении кривых приведите обе к общему вектору через refinement (как дроби к общему знаменателю).
43. **Устранение нулевых промежутков** — узлы полной кратности создают пустые span'ы; нормализуйте вход из STEP перед вычислениями.
44. **Совместимость для операций** — поточечные операции над кривыми требуют одинаковой степени и вектора узлов: сначала elevation, потом refinement.

### Операции со степенью (45–50)

45. **Degree elevation** — та же кривая степенью p+1 с n+p+2 точками; полигон сходится к кривой при повторном повышении.
46. **Elevation для Безье** — P′_i = (i/(p+1))·P_{i−1} + (1−i/(p+1))·P_i; простейший случай.
47. **Конвейер elevation** — разбить на Безье → повысить каждый сегмент → удалить лишние узлы; практичнее прямого алгоритма.
48. **Degree reduction** — в общем случае приближённая; минимизируйте макс. отклонение и проверяйте допуск.
49. **Оценка ошибки понижения** — максимальное расстояние по Безье-сегментам; отклоняйте результат выше допуска.
50. **Приведение степеней перед булевыми** — сначала поднимите младшую (elevation точен, reduction — нет).

### Аппроксимация и интерполяция (51–62)

51. **Глобальная интерполяция** — ленточная система N_{i,p}(ū_j)·P_i = Q_j; кривая проходит через все точки; LU с частичным выбором.
52. **Параметризация по длинам хорд** — ū_k ∝ накопленным длинам хорд; стандартный выбор по умолчанию.
53. **Центростремительная параметризация** — ū_k ∝ Σ√|Q_j−Q_{j−1}|; устойчивее при резких поворотах данных.
54. **Выбор узлов усреднением (A9.1)** — внутренние узлы как средние p соседних параметров; отражает распределение данных в геометрии.
55. **Обусловленность системы** — плохая параметризация даёт петли и осцилляции; виновата не математика, а ū.
56. **Интерполяция касательных** — добавление строк-производных для заданных касательных на концах.
57. **Периодическая интерполяция** — для замкнутых кривых: циклическая система без clamped-кратностей (в curvo — `try_periodic_interpolate`).
58. **Least squares** — минимизация Σ|Q_k − C(ū_k)|² при h < n контрольных точек; нормальные уравнения (NᵀN)P = NᵀQ.
59. **Итеративное добавление узлов** — начиная с минимума точек, вставлять узел там, где превышен допуск.
60. **Knot removal как компрессия** — интерполировать, затем удалять узлы в пределах допуска (fit-and-simplify); часто компактнее fit-and-refine.
61. **Веса при аппроксимации** — взвешенный least squares задаёт «доверие» точкам.
62. **Проверка по максимальной норме** — CAD-допуски задаются на worst case, не на среднеквадратичную ошибку.

### Анализ кривой (63–74)

63. **Касательная и скорость** — T = C′/|C′|; |C′| — скорость параметризации, сильно меняется вдоль кривой.
64. **Репараметризация по длине дуги** — таблица (s, u) + линейная интерполяция; дешёвый стандарт для равномерного сэмплирования.
65. **Длина дуги** — ∫|C′(u)| du; квадратура Гаусса–Лежандра по Безье-сегментам точнее и быстрее Симпсона.
66. **Кривизна** — κ = |C′×C″|/|C′|³; знак через ориентированную нормаль для 2D — нужен для офсетов и перегибов.
67. **Радиус кривизны** — ρ = 1/κ; проверяйте |C′| и κ на вырожденность перед делением.
68. **Кручение** — τ = (C′×C″)·C‴/|C′×C″|²; для плоских кривых тождественно нуль (хороший тест реализации).
69. **Репер Френе** — (T, N, B) из C′, C″; вырождается при κ=0.
70. **Уравнения Френе–Серре** — T′ = κN, N′ = −κT + τB, B′ = −τN; основа sweep-операций.
71. **RMF (rotation-minimizing frame)** — вместо Френе для sweep'ов: устраняет паразитное закручивание; метод double reflection (Wang et al.).
72. **Точки перегиба** — κ меняет знак; ищите через variation-diminishing на контрольном полигоне.
73. **Экстремумы кривизны** — корни dκ/du; нужны для fairing и porcupine-графиков качества.
74. **Разбиение по гладкости** — храните кривую как список C∞-участков между узлами кратности p; упрощает интегрирование и пересечения.

### Преобразования и проекции (75–81)

75. **Смысл весов** — w_i > 1 тянет кривую к P_i, w_i < 1 отталкивает; валидируйте w_i > 0.
76. **Перспективная проекция как родная операция** — умножьте однородные контрольные точки на матрицу камеры 4×4; деление выполнит растеризатор.
77. **Конические сечения** — окружность/эллипс точно представимы квадратичной NURBS (9 точек, веса cos(θ/2) для дуг); стандартный тест evaluation.
78. **Ближайшая точка (point inversion, A6.1)** — Ньютон по f(u) = C′·(C−Q) со стартом из грубого сэмплирования.
79. **Начальное приближение** — сэмплируйте, найдите ближайший сэмпл, уточните Ньютоном; иначе прыжки в чужие минимумы.
80. **Критерии остановки Ньютона** — |C(u)−Q| < ε₁ (точность) и |cos угла| < ε₂ (ортогональность) — оба из A6.1.
81. **Проекция на плоскую кривую** — в 2D используйте ориентированное расстояние и знак кривизны (толщина/offset для 2D-примитивов).

### Разбиение и субдивизия (82–87)

82. **Разбиение на Безье-сегменты** — вставка каждого внутреннего узла до кратности p → массив Безье; универсальная предобработка для пересечений, тесселяции, bounding box.
83. **Де Кастельжо-бисекция** — разбиение при t=0.5 даёт два полигона и точку деления за один проход.
84. **Адаптивная тесселяция** — рекурсивно делите Безье, пока полигон не «плоский» (расстояние промежуточных точек до хорды < ε).
85. **Split по параметру** — вставка узла u* до кратности p делит NURBS на две кривые с общей точкой; основа trim-операций.
86. **Отсечение хвостов (clamping)** — приведение unclamped-кривой к clamped вставкой узлов на концах; нужно перед экспортом.
87. **Стабильная субдивизия** — делите через де Кастельжо/вставку узлов, а не перевычислением базиса: ошибка не накапливается.

### Пересечения и экстремумы (88–93)

88. **Свойство выпуклой оболочки** — кривая на [u_i, u_{i+p+1}) лежит в hull точек P_{i−p}..P_i; основа отсечений и picking'а.
89. **AABB контрольного полигона** — валидный (чуть завышенный) бокс кривой; строится бесплатно.
90. **Пересечение кривая–прямая** — корни (C(u)−A)·N = 0; для Безье — полином, субдивизия + Ньютон.
91. **Пересечение кривая–кривая** — рекурсивная субдивизия с отсечением по AABB, затем Ньютон на (u, v); касательные касания — особый случай.
92. **Ньютон 2D для (u,v)** — минимизация |C(u)−D(v)|², система из двух уравнений ортогональности; якобиан из C′, D′, C″, D″.
93. **Экстремумы кривой** — корни C′·d = 0; для bounding box по оси ищите корни компонент C′.

### Rust-специфика кривых (94–100)

94. **curvo (mattatz)** — актуальная библиотека NURBS на nalgebra-генериках: интерполяция, периодические кривые, ближайшая точка, пересечения, деление по длине дуги; лучший референс архитектуры.
95. **truck / monstertruck** — CAD-ядро: `truck-geometry` (KnotVector, BSplineCurve, NURBSCurve), трейт `ParametricCurve`; активная линия — форк `monstertruck`.
96. **Fornjot** — B-rep CAD-ядро; mainline-разработка завершена автором — источник идей (fj-math), не зависимость.
97. **nalgebra vs glam** — nalgebra (генерики по размерности/скаляру) для геометрического ядра; glam (f32+SIMD) для рендер-пути; конвертация на границе.
98. **f64 в ядре, f32 в отображении** — вставка узлов, пересечения, Ньютон — на f64; понижение до f32 только для VBO/GPU; генерик `T: FloatingPoint` позволяет тестировать оба.
99. **AoS vs SoA** — ядро: AoS (`Vec<Point3<T>>` + `Vec<T>` весов); SoA-проекция только в горячем цикле тесселяции; `#[repr(C)]` для zero-copy в GPU-буферы.
100. **Ошибки и робастность** — `Result`-конструктор с валидацией (m = n+p+1, w_i > 0, неубывание узлов), typed-ошибки через `thiserror`, epsilon-сравнения через `approx`, Ньютон с лимитом итераций и `Err(NonConverged)` вместо паники.

## Часть II. Поверхности, продвинутые операции и экосистема (101–200)

### Фундамент NURBS-поверхностей (101–115)

101. **Тензорное произведение** — S(u,v) = ΣᵢΣⱼ Nᵢ,ₚ(u)Nⱼ,q(v)Pᵢⱼ: две независимые B-сплайн-структуры по u и v (The NURBS Book, гл. 4).
102. **Контрольная сетка** — двумерный массив (n+1)×(m+1) точек Pᵢⱼ; в Rust — плоский `Vec` + страйды.
103. **Векторы узлов U и V** — два неубывающих массива длиной n+p+2 и m+q+2; валидируйте длины при конструировании.
104. **Базисные функции** — рекурсия Кокса–де Бура; для степени ≤3 выгодны развёрнутые формулы или BasisFuns (A2.2).
105. **Однородные координаты** — рациональность через 4D (wx, wy, wz, w) и деление в конце: единый код для B-сплайнов и NURBS.
106. **Веса** — wᵢⱼ > 0 всегда; нулевые/отрицательные веса — источник NaN, проверяйте на входе.
107. **Clamped-узлы** — кратность p+1 на концах проводит поверхность через угловые точки сетки; для CAD-примитивов почти всегда нужный вариант.
108. **FindSpan (A2.1)** — двоичный поиск спана; кэшируйте между вызовами при сканировании по параметру.
109. **Оценка точки SurfacePoint (A4.3)** — сначала базисы по u и v, затем двойная свёртка; не вычисляйте полную матрицу базисов.
110. **DersBasisFuns (A2.3)** — единый проход: базис + производные до порядка k; основа всех дифференциальных операций.
111. **Производные рациональной поверхности (A4.4)** — правило частного в однородных координатах; частая ошибка — дифференцировать как нерациональную.
112. **Нормаль = ∂S/∂u × ∂S/∂v** — нормализуйте после произведения; зафиксируйте конвенцию ориентации (правило правой руки).
113. **Вырожденные нормали на полюсах** — на сфере/конусе производные вырождаются в стянутых рядах; считайте нормаль по соседним точкам.
114. **Непрерывность и кратность узлов** — внутренний узел кратности k снижает гладкость до C^(p−k); p — стык C⁰, p+1 — разрыв.
115. **Вставка узлов (A5.1/A5.3)** — основа разбиения на патчи Безье, локального уточнения и вырезания изокривых.

### Построение поверхностей (116–130)

116. **Линейчатая поверхность (ruled)** — линейная интерполяция между совместимыми кривыми.
117. **Экструзия (extrude)** — копия кривой, сдвинутая на вектор.
118. **Поверхность вращения (revolve, A8.1)** — круги рациональными квадратичными дугами с весами cos(θ/2); точные цилиндр, конус, сфера, тор.
119. **Лофтинг/скиннинг (A10)** — интерполяция набора профилей поверхностью по v.
120. **Совместимость кривых перед лофтом** — одна степень (elevation) + общий вектор узлов (merge + insertion), иначе сетка разъедется.
121. **Sweep по одной направляющей** — профиль ориентируется кадром вдоль пути; опасность — вырождение кадра при нулевой кривизне.
122. **Sweep по двум направляющим** — профиль масштабируется и ориентируется двумя рельсами; контролирует закрутку лучше Frenet.
123. **Патч Кунса** — поверхность по четырём границам: S = ruled_u + ruled_v − билинейный член.
124. **Поверхность Гордона** — обобщение Кунса на сетку пересекающихся кривых.
125. **Скиннинг с касательными условиями** — производные на концах профилей дают G¹-стыковку с соседями.
126. **Swing-поверхность** — профиль «поворачивается» вокруг направляющей; частный случай между sweep и revolve.
127. **N-сторонние патчи** — NURBS четырёхсторонни; треугольники/n-угольники — вырожденные стороны или тримминг.
128. **Плоскость как билинейная поверхность** — степень 1×1, 4 точки; не храните аналитические плоскости отдельно при унифицированном ядре.
129. **Цилиндр и конус через revolve** — конус имеет вырожденную вершину (полюс), см. п. 113.
130. **Точная сфера и тор** — только рациональные квадратичные NURBS; типичная сфера — 9×(2..5) контрольных точек с весами.

### Аппроксимация и интерполяция поверхностей (131–140)

131. **Параметризация точек** — равномерная, хордовая, центростремительная; это половина качества фиттинга.
132. **Глобальная интерполяция кривой (A9.1)** — ленточная система; LU-разложение.
133. **Интерполяция поверхности по сетке (A9.4)** — сначала строки кривыми, затем их контрольные точки столбцами.
134. **Аппроксимация МНК (A9.6)** — нормальные уравнения + регуляризация при фиксированных узлах.
135. **Усреднение узлов (A9.8)** — стандартная эвристика размещения внутренних узлов по параметрам данных.
136. **Сглаживание (fairing)** — член энергии ∫‖S″‖² в МНК убирает волнистость зашумлённых данных.
137. **Регулярная сетка vs scattered** — регулярная решётка → прямая интерполяция; scattered → сначала параметризация.
138. **Число контрольных точек vs допуск** — итеративно: аппроксимация → проверка → вставка узлов в худших спанах.
139. **Удаление узлов (A5.8)** — сжатие переусложнённых поверхностей в пределах допуска.
140. **Повышение степени (A5.9)** — для совместимости перед лофтом/булевыми.

### Анализ поверхностей (141–150)

141. **Первая фундаментальная форма (E, F, G)** — метрика, длины и углы на поверхности.
142. **Вторая фундаментальная форма (L, M, N)** — нужны вторые производные.
143. **Гауссова кривизна K = (LN−M²)/(EG−F²)** — классификация точек: эллиптическая/гиперболическая/параболическая.
144. **Средняя кривизна H** — индикатор «седловатости», вход для физики оболочек.
145. **Главные кривизны k₁, k₂ = H ± √(H²−K)** — радиусы скругления при филлетах.
146. **Умбилики (k₁ = k₂)** — точки сферичности; сингулярности поля главных направлений.
147. **Изокривые u/v = const** — извлекаются фиксацией параметра (строка/столбец сетки); основа каркасного рендера.
148. **Площадь поверхности** — ∫∫√(EG−F²) du dv квадратурами Гаусса по спанам.
149. **Инверсия точки (point inversion)** — ближайшая (u,v): Ньютон от грубого семпла; для проекций и тримминга.
150. **Нормальная кривизна (теорема Мёнье)** — связывает кривые и поверхности через вторую форму.

### Тесселяция для рендеринга (151–162)

151. **Равномерная сетка (u,v)** — N×M оценок + два треугольника на ячейку; baseline и LOD-0.
152. **Адаптивное разбиение по кривизне** — рекурсивное деление патча по допуску хорды и нормалей.
153. **Допуск по высоте хорды (deflection)** — в единицах модели, пересчёт под zoom.
154. **Допуск по углу нормалей** — именно его видно на бликах даже при малом deflection.
155. **Разбиение на патчи Безье** — вставкой узлов до кратности p; каждый патч триангулируется независимо.
156. **Тримминг** — кривые обрезки в (u,v); CDT 2D-домена (crates `spade`, `earcutr`), проекция вершин на поверхность.
157. **Бесшовность между патчами** — трещины от разной дискретизации рёбер; тесселяция рёбер первыми + stitching.
158. **UV-координаты** — натуральные (u,v) домена; для CAD-подсветки достаточно параметрических UV.
159. **Аналитические нормали** — для CAD-рендера берите из производных, не сглаженные по сетке.
160. **Ориентация и winding** — единый порядок обхода по направлению нормали; инверсия ломает culling и булевы.
161. **GPU-тесселяция в wgpu** — аппаратных стадий нет: compute-шейдер с оценкой базисов или CPU-тесселяция с аплоадом.
162. **LOD в вьюере** — 2–3 уровня тесселяции на поверхность, переключение по экранному размеру.

### Булевы/CSG и B-rep (163–170)

163. **B-rep vs mesh для CSG** — точные булевы на B-rep; OpenSCAD-подобные системы исторически на мешах — проще и робастнее.
164. **Урок OpenSCAD/CGAL** — булевы на точной арифметике (rationals); либо точные предикаты, либо катастрофы с плавающей точкой.
165. **NURBS→меш перед булевыми** — прагматичный маршрут: тесселяция с мелким допуском + mesh-boolean (подход Manifold).
166. **Точные предикаты** — orientation/in-circle через расширенную точность; crate `robust` (порт Shewchuk).
167. **Многообразность** — булевы требуют 2-манифолдных входов; проверяйте до операции.
168. **Допуски и швы (healing/sewing)** — импортированный B-rep почти всегда имеет зазоры; сшивание рёбер — обязательный препасс.
169. **Топология half-edge** — vertex/edge/wire/face/shell/solid; не смешивайте геометрию и топологию в одном крейте.
170. **Операторы Эйлера** — MEV/MEF/KEV…; стройте булевы только через них, иначе топология развалится.

### Продвинутые операции (171–180)

171. **Офсет поверхности** — S + d·n в общем случае не NURBS; аппроксимация сетки + фиттинг в допуск.
172. **Офсет кривой** — точный офсет нерационален; конвейер: сэмплирование → фиттинг, контроль самопересечений.
173. **Пересечение поверхность–поверхность (SSI)** — marching: стартовые точки подразбиением, шаг по касательной с коррекцией Ньютоном.
174. **Пересечение кривая–поверхность** — S(u,v) = C(t): Ньютон 3×3 + стартовая сетка.
175. **Филлеты «катящимся шаром»** — радиус ограничен min главной кривизны; pipe-поверхность + тримминг.
176. **Блендинг (blend)** — G¹/G²-патч между поверхностями; лофт с касательными условиями.
177. **Силуэтные кривые** — n·v = 0; view-dependent, считаются на кадр.
178. **Силуэты для CAD-рендера** — чёткие рёбра + силуэты = «чертёжный» вид; проще постпроцесс по нормалям/depth.
179. **Расширение и антримминг** — продление за границу экстраполяцией сетки; untrim восстанавливает домен.
180. **Разрез по изокривой** — вставка узла до кратности p делит поверхность без изменения формы.

### Обмен данными (181–187)

181. **IGES 126/128** — entity 126: рациональная B-сплайн-кривая; 128: поверхность.
182. **IGES 144/143** — Trimmed/Bounded Surface; без них поверхности придут необрезанными.
183. **STEP: b_spline_surface_with_knots** — AP203/AP214: `b_spline_surface`, `rational_b_spline_surface`, `uniform/quasi_uniform/bezier_surface`.
184. **STEP: тримминг и грани** — `trimmed_curve`, `surface_curve`, `curve_bounded_surface`, `advanced_face` с p-кривыми.
185. **STEP: единицы и допуски** — всегда читайте `si_unit` и `uncertainty_measure_with_unit`; классическая беда — мм vs дюймы.
186. **Экспорт STL** — только меш; допуск 0.01–0.1 мм, binary STL (ASCII раздувается в 5–7 раз).
187. **OBJ и 3MF** — OBJ формально имеет `cstype bspline`, но читатели понимают только полигоны; 3MF — меш-формат; экспортируйте тесселяцию.

### Экосистема Rust (188–196)

188. **truck → monstertruck** — B-rep/NURBS-ядро (geometry, topology, modeling, shapeops, рендер на wgpu); активный форк `monstertruck` (T-splines, fillet, healing).
189. **curvo** — `mattatz/curvo`: NURBS на nalgebra, интерполяция, extrude/loft/sweep/revolve, адаптивная тесселяция, опциональные rayon/serde — лучший «лёгкий» референс.
190. **fornjot — проект закрыт** — код (0BSD) полезен как референс по fj-math, не как зависимость.
191. **crate `nurbs`** — минималистичный; учебный референс API, функционально уступает curvo.
192. **crate `splines`** — Catmull-Rom и т.п. для анимации UI; не NURBS и не CAD.
193. **bezier-rs** — 2D-Bézier из проекта Graphite; для эскизов и UI, не для 3D NURBS.
194. **Новые ядра** — `brepkit` (B-rep для Rust/WASM, AGPL — проверьте лицензию) и свежие проекты 2025–2026.
195. **nalgebra vs glam** — nalgebra для ядра (генерики, LU/SVD), glam для рендера (f32, SIMD); обычно нужны оба.
196. **wgpu** — стандарт рендеринга (truck/monstertruck, bevy): меши + line-рендер рёбер + pick через offscreen-color-pass.

### Производительность и робастность (197–200)

197. **Параллельная тесселяция с rayon** — патчи независимы: `par_iter()` по поверхностям даёт почти линейное ускорение.
198. **f64 для геометрии, f32 для GPU** — конвертация на границе VRAM; origin-relative координаты против дрожания больших моделей.
199. **Стратегия допусков** — иерархия: представление (~1e-12), модельный допуск (~1e-6…1e-4), экранный допуск; никогда `==` на float, crate `approx`.
200. **Сериализация и кэширование** — derive `serde` для сетки/узлов/весов; кэш тесселяций по хэшу геометрии.

## Часть III. Продвинутые кривые, алгоритмы и инженерия ядра (201–275)

201. **PH-кривые (Pythagorean-Hodograph)** — скорость через кватернионы/полиномы: длина и офсеты в радикалах без численного интегрирования.
202. **Рациональные PH-офсеты** — точные офсеты как рациональные B-сплайны через единичные нормали, без аппроксимации выборкой.
203. **PH quintic Hermite-интерполяция** — квинтические PH-сплайны по G1-данным концов; квадратичная система в комплексном поле.
204. **Клотоида (спираль Корню)** — интегралы Френеля: ряд Тейлора при малом аргументе, асимптотика при большом, авто-переключение ветвей.
205. **G2-переходные спирали** — стыковка прямая/дуга/дуга клотоидами из условий непрерывности κ и dκ/ds (Euler spiral solver).
206. **Би-спирали** — Hermite G2 двумя клотоидными сегментами, итеративно (Ньютон) по условиям на концах.
207. **Minimum Variation Curves (MVC)** — минимизация ∫(dκ/ds)²ds линейной системой по контрольным точкам — «честные» кривые.
208. **Энергетический фэйринг** — энергия растяжения+изгиба как квадратичная форма; минимизация при ограничениях.
209. **Критерии честности** — гребёнка кривизны и её производной; интегральные метрики для автоконтроля качества.
210. **Прямое манипулирование кривой** — перетаскивание точки НА кривой: минимальное смещение контрольных точек через псевдообратную матрицу базиса.
211. **Многоточечное редактирование** — одновременное перемещение нескольких точек на кривой через LSQ с ограничениями-равенствами.
212. **Мёбиусова репараметризация** — t′=(at+b)/(ct+d) для рациональных кривых с пересчётом узлов и весов без изменения образа.
213. **Нормализация весов** — приведение к w₀=wₙ=1 Мёбиусовой репараметризацией для сравнения и слияния кривых.
214. **Вейвлет-редактирование B-сплайнов** — грубый базис + детали уровней (lifting scheme); правка грубого уровня с сохранением деталей.
215. **Мультирезолюшн-детали** — детализирующие коэффициенты как дельты контрольных точек; локальные правки не ломают глобальную форму.
216. **Сети кривых** — поверхности по сетям: интерполяция сети → заполнение ячеек (Gordon/Coons) с контролем G1.
217. **N-сторонние заплатки** — веер с центральной точкой, Gregory-патчи или разбиение на четырёхсторонние с проверкой G1.
218. **Gregory-патчи** — внутренние точки как рациональные функции угловых параметров для G1-стыковки n-сторонней заплатки.
219. **Детекция симметрии кривых** — оси зеркальной/вращательной симметрии сравнением с отражённой копией (ICP-подобная минимизация).
220. **Детекция особых точек** — точки возврата, самопересечения, |r′(t)|≈0 через результанты производных.
221. **SVG path → NURBS** — парсинг M/L/C/Q/A/Z; кубики/квадратики повышением до единого B-сплайна с накоплением узлов.
222. **SVG-дуги → рациональные кривые** — endpoint → центральная форма → рациональные квадратичные Безье ≤90°.
223. **Контуры шрифтов (TrueType)** — квадратичные Безье с on/off-curve: неявные on-curve точки между соседними off-curve, повышение до кубиков.
224. **Ориентация контуров глифов** — внешний CCW, дыры CW; чётно-нечётное правило заливки.
225. **Размерно-управляемые кривые** — именованные размеры (длина, угол, радиус) с пересчётом контрольных точек через дифференцируемую цепочку.
226. **2D-скетч-солвер: граф ограничений** — примитивы и ограничения (совпадение, касание, размер) бипартитным графом; Ньютон–Гаусс.
227. **Степени свободы скетча** — DOF через декомпозицию графа (Laman); сигнал о недо-/переопределении до солвера.
228. **Численный скетч-солвер** — разрежённый якобиан (faer/sprs) + демпфированный Левенберг–Марквардт.
229. **Морфинг кривых** — выравнивание степеней и узлов (elevation + merge), интерполяция точек и весов в однородном пространстве.
230. **Согласование параметризации при морфинге** — совмещение характерных точек (концы, экстремумы κ) против «скольжения».
231. **Оптимизация узлового вектора** — итеративное перемещение внутренних узлов для минимизации ошибки; штраф за сближение узлов.
232. **Адаптивная вставка узлов по ошибке** — greedy refinement в интервалах с максимальной ошибкой.
233. **Удаление избыточных узлов** — после булевых/репараметризации: удаление с контролируемой погрешностью.
234. **Ленивые вычисления с dirty-флагами** — кэш точек/длины/AABB с инвалидацией по флагу (once_cell-паттерн).
235. **Архитектура parametric-кэша** — ключ = (id, версия, параметр запроса); версия инкрементируется при мутации.
236. **Инкрементальная перестройка** — при правке одной точки пересчитывать только затронутые спаны (локальность базиса).
237. **Двухуровневое версионирование** — «топологическая» версия (узлы/степень) и «геометрическая» (точки); раздельная инвалидация.
238. **Квантизация контрольных точек** — fixed-point int32 + веса f16 для хранения/сети; документируйте максимальную ошибку.
239. **Дельта-кодирование сеток** — разности соседних точек + varint/zstd; на порядок меньше для гладких кривых.
240. **Хеширование геометрии** — xxh3/blake3 от канонической сериализации для дедупликации и кэширования операций.
241. **Дедупликация подкривых** — одна копия по хэшу + инстансы с трансформациями (flyweight) для шрифтов/массивов.
242. **Property-based тесты (proptest)** — инварианты: ΣNᵢ≡1, локальная поддержка, выпуклая оболочка, аффинная инвариантность.
243. **Метаморфные тесты** — вставка узла/повышение степени не меняют образ; реверс параметризации даёт те же точки.
244. **Фаззинг ядра (cargo-fuzz)** — парсеры (STEP/IGES/SVG) и численные процедуры на панику/бесконечный цикл.
245. **Golden-file тесты vs geomdl/OpenNURBS** — эталоны в JSON, сравнение с допуском 1e-9 в CI.
246. **Регрессионные снапшоты (insta)** — снапшоты сериализованных результатов; ревью диффами при рефакторинге.
247. **Criterion-бенчмарки** — BasisFuns, de Boor, тесселяция; throughput-метрики, baseline для regression detection.
248. **Профилирование до оптимизации** — samply/flamegraph на реалистичных моделях; оптимизировать только подтверждённые точки.
249. **Miri и UB-дисциплина** — `cargo +nightly miri test` для unsafe; цель — ноль unsafe в математическом ядре.
250. **Панико-устойчивость** — запрет паник в публичном API (clippy::panic), Result везде; проверки делений и индексаций.
251. **Обусловленность систем фиттинга** — контроль cond(NᵀN); QR/SVD вместо нормальных уравнений при плохой параметризации.
252. **Регуляризация фиттинга** — член Тихонова λ‖P″‖² / сглаживание вторых разностей против шума.
253. **Взвешенный LSQ** — веса точек через масштабирование строк; проверка вырождения при нулевых весах.
254. **Батч-оценка (SoA)** — xs/ys/zs/ws раздельно для векторизации при тысячах параметров за вызов.
255. **Параллельная оценка (rayon)** — par_chunks с размером чанка, амортизирующим накладные расходы.
256. **SIMD-оценка базисов** — 4/8 параметров одновременно (std::simd), особенно кубики с фиксированной степенью.
257. **GPU-оценка в wgpu** — compute-шейдер: узлы/точки в storage buffer, бинарный поиск спана на GPU.
258. **WGSL de Boor** — vec4<f32> однородные координаты, единая степень 3 с паддингом против дивергенции ветвлений.
259. **WASM SIMD** — target-feature=+simd128, std::simd; тест численной эквивалентности со scalar-путём.
260. **Таксономия ошибок (thiserror)** — SingularSystem, KnotVectorInvalid, NotConverged{iterations}, OutOfDomain{param} — с контекстом, без строк.
261. **Структура Limits** — централизованные бюджеты (max_iterations, tolerances, max_degree) с консервативными дефолтами.
262. **Шкалы допусков** — эффективный допуск от масштаба сцены (bbox diagonal × relative_tol); не зашивать 1e-9 в код.
263. **Типы Point3/Vector3** — различие на уровне типов; миграция инкрементально через newtype-обёртки.
264. **Scalar f64 в ядре** — generic Scalar: Float или type alias; рендер-граница f32.
265. **Канонизация кривых** — нормализованный вектор узлов [0,1], округление до допуска, сортировка кратных узлов перед сравнением/хешированием.
266. **Сериализация с версионированием** — поле version, явные степень/узлы/точки/веса; миграции отдельным слоем.
267. **Разрежённые якобианы** — sprs/faer для больших систем; ленточная структура решается за O(n·p²).
268. **Ленточное решение** — ширина полосы 2p+1; ленточный LU/Cholesky вместо плотного решателя.
269. **FindSpan с кэшем** — бинарный поиск + hint последнего интервала; O(1) амортизированно при монотонном параметре.
270. **Стратегии инверсии точки** — грубая выборка → Ньютон; fallback на квадратичное приближение при |r′·r″|≈0.
271. **Робастный Ньютон с bracketing** — Ньютон + бисекция (Brent-подобно): гарантированная сходимость в 1D.
272. **Детерминизм вычислений** — фиксированный порядок редукций (tree reduction), документированный fast-math.
273. **Логирование (tracing)** — spans/events с итерациями и невязками; выключаемо feature-флагом.
274. **API-стабильность (semver)** — публичные трейты Curve/Surface отделены от внутренностей; внутреннее — #[doc(hidden)].
275. **Документация-до-реализации** — doc-comment с формулировкой, допусками, инвариантами и ссылкой на источник как спецификация для тестов.

## Часть IV. Поверхности, B-rep, форматы и интеграции (276–350)

276. **T-splines: суть** — T-стыки сеток без выравнивания рядов; внедрять только при реальной потребности в локальном уточнении.
277. **T-splines → NURBS** — конвертация в тензорные патчи разбиением по T-точкам (knot insertion); одна функция `tspline_to_patches()`.
278. **Когда НЕ нужны T-splines** — механические детали из примитивов и булевых; не тащить зависимость ради редких форм.
279. **Catmull-Clark → NURBS** — квад → bicubic B-spline патч; экстраординарные вершины — спецпатчи или ограничение валентности.
280. **NURBS → Catmull-Clark** — контрольная сетка bicubic патча как квад-сетка; круговая совместимость subdivision-core ↔ nurbs-core.
281. **Экстраординарные вершины** — аппроксимация несколькими патчами (3 патча на вершину) вместо точного представления.
282. **Сегментация облака точек** — region growing по кривизне и нормалям до фиттинга, иначе глобальный фит размоет рёбра.
283. **Quad-ремешинг перед сплайнами** — ориентированное по направлениям кривизны квад-ремеширование как скелет патч-структуры.
284. **Feature-preserving реверс** — сначала острые рёбра (угол нормалей), потом фиттинг внутри регионов — не наоборот.
285. **Разложение на примитивы** — RANSAC плоскостей/цилиндров/конусов до свободного фиттинга; аналитика точнее и компактнее.
286. **Девелопабельные поверхности** — проверка K≈0 по выборке перед развёрткой; недевелопабельную разворачивать нельзя.
287. **Развёртка (unrolling)** — ruled-поверхности: триангуляция вдоль образующих с сохранением длин; 2D-профиль для листового металла.
288. **Метрика искажений развёртки** — ratio площадей 3D/2D на элемент; тепловая карта цены развёртки.
289. **UV для текстур** — параметрическое (u,v) ≠ равномерная текстура; опция репараметризации по длине дуги.
290. **Геодезические на поверхности** — ОДУ kg=0 численно (RK4) в параметрической области с первой/второй формами.
291. **Геодезический офсет** — смещение кривой на поверхности по геодезическому расстоянию, не по (u,v)-сетке.
292. **Рельсы для блендинга** — guide-кривые как кривые на обеих поверхностях через общий контактный контур.
293. **Экстраполяция поверхности** — extend взрывается при высоких степенях: лимит доли диапазона + валидация самопересечений.
294. **Шов периодической поверхности** — канонический диапазон u∈[0,1] с нормализацией при каждом доступе.
295. **Тесселяция через шов** — совпадение вершин на u=0 и u=1 (один источник или post-weld), иначе цилиндры светятся щелью.
296. **Нормали на шве** — аналитически с замкнутым параметром, не из треугольников.
297. **Валидация watertight** — конвейер: Эйлер → парность рёбер → ориентация → самопересечения → отчёт по каждому пункту.
298. **Дефектуризация** — удаление мелких фасок/отверстий: пометка по площади/радиусу, схлопывание, перестройка соседей, журнал для отката.
299. **Подавление фич** — флаг suppressed в дереве фич без пересчёта последующих шагов, не удаление узла.
300. **Сечение NURBS-тела плоскостью** — прямой слайсинг: curve-on-surface на каждой грани, сшивка в замкнутые 2D-контуры.
301. **Direct slicing vs mesh slicing** — B-rep точнее, но дороже; меш для предпросмотра, прямой для экспорта слоёв.
302. **Полилинии из сечений** — сэмплирование кривых слоя с толерансом хорды против микросегментов.
303. **Адаптивная высота слоя** — из максимальной кривизны пересечённых поверхностей; диапазон [min,max] принтера.
304. **PH-кривые для фрезеровки** — точный рациональный офсет для траекторий CNC вместо приближённых.
305. **Офсет контура для toolpath** — raw offset → удаление петель (clipping через winding number) → G-код.
306. **G-код из сплайнов** — biarc fitting (G1-дуги) или линейные сегменты по толерансу; G5.x поддерживают не все контроллеры.
307. **glTF-экспорт** — NURBS не хранится: тесселяция + параметрическое описание в extras для round-trip.
308. **USD-экспорт** — NurbsPatch нативно; проверять поддержку целевым Hydra-делегатом.
309. **X3D NURBS-узлы** — NurbsPatchSurface/NurbsCurve нативно; веб-экспорт без потери точности для X3D-aware зрителей.
310. **DXF SPLINE** — степень/узлы/точки/веса напрямую; проверять флаг rational (group 73/74).
311. **DXF-версии** — минимум AC1027 (AutoCAD 2013) для корректных SPLINE.
312. **SVG-экспорт чертежа** — проекции в cubic Bézier сегменты; NURBS → Bézier декомпозиция по узлам.
313. **PDF тех-чертёж** — тот же Bézier-пайплайн + масштаб листа и толщины линий в pt; встроенные шрифты.
314. **Hidden-line removal** — силуэты + видимые рёбра через z-buffer с id-атрибутом; сегментация кривых по видимости.
315. **IFC для BIM** — IfcBSplineSurface / IfcFacetedBrep / IfcAdvancedBrep по требованиям приёмника.
316. **Объём/центроид/инерция** — теорема о дивергенции: сумма интегралов по граням (Гаусс-квадратура по патчам); никаких вокселей.
317. **Проверка массовых свойств** — золотой тест: объём сферы = 4/3πr³ с 1e-6; расхождение = ошибки ориентации граней.
318. **Измерения в viewer** — точка-поверхность через проекцию (Ньютон со стартом из тесселяции); углы между нормалями.
319. **Пикинг: GPU id-buffer** — offscreen-текстура с цветом-id на грань/ребро: O(1); точность уточнять проекцией на поверхность.
320. **Пикинг: ray casting** — луч → меш (BVH) → уточнение Ньютоном на аналитической поверхности.
321. **Снаппинг** — иерархия: вершина > ребро > грань; центры дуг из аналитики рациональной кривой, не из тесселяции.
322. **Undo/redo командный паттерн** — execute()/revert(); дельты состояния вместо полных снимков B-rep.
323. **Снапшоты vs дельты** — периодический снапшот + журнал дельт; чистый журнал = O(N) откат, чистые снапшоты = память.
324. **Дерево фич (DAG)** — ссылки на грани/рёбра через устойчивые id, иначе перестройка ломает ссылки.
325. **Topological naming** — постоянные id по происхождению (фича + локальный индекс + хэш контекста); никогда по позиции в массиве.
326. **Перестройка по параметру** — dirty-флаги по DAG от изменённой фичи; кэш результата узла по хэшу входов.
327. **Инкрементальная тесселяция** — кэш меша на патч; перетесселяция только зависимых патчей (dirty-region по id грани).
328. **Crash recovery** — serde-снапшот после каждой команды; восстановление при старте с версией схемы.
329. **Версионирование схем** — schema_version в каждый снапшот; миграции явными функциями.
330. **Ленивая загрузка** — сначала AABB-дерево и грубый LOD; точные патчи по видимости/близости камеры.
331. **Стриминг геометрии** — тесселяция чанками по граням с приоритетом frustum; NURBS-описание целиком (оно компактно).
332. **Инстансинг** — дедупликация по хэшу (патчи + толеранс), одна копия + массив трансформов; типично для крепежа/массивов OpenSCAD.
333. **Квантизация кэша мешей** — int16/int32 в локальном AABB + scale/offset: 2–4× экономия.
334. **zstd для кэшей** — уровень 3–6; lz4 если узкое место в декомпрессии.
335. **Размер WASM-бинарника** — opt-level="z", lto, codegen-units=1, panic="abort", strip; мерить `cargo bloat`.
336. **Граница зависимостей ядра** — nurbs-core/brep-core без wgpu/serde-wasm; платформенные крейты — адаптеры; ядро компилируется и в wasm32.
337. **Потоки под WASM** — rayon только через wasm-bindgen-rayon + SharedArrayBuffer (COOP/COEP); однопоточный fallback.
338. **Атомики и буферы** — неизменяемые Arc-снимки геометрии; мутабельный shared state — источник гонок при параллельной тесселяции.
339. **Золотые модели OpenSCAD** — интеграционные тесты: рендер/объём/площадь эталонных .scad с golden-значениями; эталоны в LFS.
340. **Сравнение геометрии в тестах** — метрики (Hausdorff, объём, число граней), не побайтово.
341. **Property-тесты ядра** — eval(u,v) в AABB контрольных точек; insert_knot сохраняет кривую (выборки до/после).
342. **Лицензионная гигиена** — AGPL (brepkit) заражает бинарник включая wasm; MIT/Apache (curvo, nalgebra, glam) безопасны.
343. **Аудит зависимостей** — `cargo deny` в CI: запрет copyleft, дубликатов, yanked-крейтов.
344. **Trim-целостность** — после split/extend перевалидировать замкнутость/ориентацию/вложенность контуров в (u,v); 90% багов булевых здесь.
345. **Рациональные дуги для кругов** — отверстия/цилиндры рациональными квадратичными кривыми (веса cos θ), не аппроксимацией.
346. **Непрерывность на стыках** — после склейки проверять G0/G1; «полосы» на стыках — нарушенная G1 при разной параметризации.
347. **Параметрический диапазон как данные** — никогда не предполагать [0,1]; domain из узлового вектора; нормализация на границе API.
348. **Толеранс-стек** — машинный (1e-12) < геометрический (1e-9·scale) < топологический (1e-6·scale) < тесселяционный.
349. **Масштаб модели** — нормализация единиц на импорте (STEP хранит явно, STL — нет); смешение масштабов ломает толерансы и булевы.
350. **Профилирование ядра** — бенчмарки на реальных моделях (criterion натив, тайминг wasm): eval, булевы, тесселяция отдельно.

## Часть V. Продвинутая численность и инженерия кривых (351–400)

351. **Имплицитизация через результанты** — имплицитизация плоских рациональных кривых результантом Сильвестра/Безу: точный тест «точка на кривой» без итераций.
352. **Реконструкция по кривизне** — восстановление плоской кривой из κ(s): θ(s)=∫κ ds, позиция эйлеровыми интегралами (Френеля) с контролем накопления ошибки.
353. **Offset-тримминг через медиальную ось** — глобальные самопересечения офсетов: точки, где ближайшая точка не совпадает с исходной, обрезать.
354. **Офсеты переменного радиуса** — offset с r(t) как скалярным B-сплайном; контроль r(t)+1/κ(t) > 0 и отклонения.
355. **Bézier clipping** — обрезка по «жировым линиям» (Sederberg–Nishita) вместо равномерной бисекции: квадратичная сходимость на гладких пересечениях.
356. **Интервальная арифметика в базисе** — evaluate с Interval<f64> (аффинная форма) для сертифицированных границ значений и производных на сегменте.
357. **Error-free transformations** — TwoSum/TwoProd (FMA) в суммах de Boor и однородной нормализации: ошибка ~2u от результата.
358. **Kahan-суммирование базиса** — компенсированное суммирование (Kahan/Neumaier) при взвешенном суммировании контрольных точек.
359. **Double-double fallback** — фича-флаг `dd` для оценки с <1e-28 относительной точности (верификация, не рантайм).
360. **Интервальные NURBS** — интервальные контрольные точки для представления неопределённости входа и пропагации оболочки через операции.
361. **Сертификаты ошибок по цепочке** — каждая операция возвращает оценку погрешности; суммарный audit certificate всей цепочки.
362. **Число обусловленности базиса де Боора** — граница cond(B) ≤ d·2^d; отвергать узловые конфигурации сверх порога.
363. **Стабильность повторной вставки узлов** — алгоритм Осло вместо повторного одношагового de Boor; тесты роста ошибки на 1000+ вставках.
364. **Overflow-safe веса** — масштабирование строки весов общей степенью двойки (frexp/ldexp) против переполнения в гомогенных вычислениях.
365. **Матрицы конверсии базисов** — явные матрицы Bézier↔степенной↔Hermite по сегментам; proptest round-trip < 1e-12.
366. **Алгоритм Осло** — общая вставка множества узлов за один проход через дискретные B-сплайны; основа refine/elevate.
367. **Дискретные B-сплайны** — стабильные рекуррентные дискретные сплайн-коэффициенты для конверсии узловых векторов без обращения матриц.
368. **Lane–Riesenfeld** — оценка равномерных B-сплайнов схемой subdivide-and-average; пригодно для GPU и fixed-point.
369. **Условия Шёнберга–Уитни** — валидация t_i ∈ supp(N_i) (порог min N_i(t_i)); отклонение вырожденных схем до решения СЛАУ.
370. **Blossoming на практике** — полярные формы для вставки узлов, повышения степени и перемены вектора единым механизмом; тесты симметричности/мультиаффинности.
371. **Оскулирующие коники** — коника по точке, касательной и кривизне (rho-параметризация, shoulder point) для конических сегментов.
372. **Выбор шва замкнутых кривых** — перенос начала параметризации periodic-кривых (seam relocation) по максимуму кривизны/длине сегмента.
373. **Реверс и переориентация** — reverse: u′ = a+b−u, зеркаление точек и производных; бит-в-бит evaluate(rev(C))(a+b−t) = evaluate(C)(t).
374. **Продление по оскуляции** — extension с согласованием G²/C² и отчётом о стабильности; предупреждение при росте коэффициентов экстраполяции.
375. **Расстояние Фреше** — дискретный и непрерывный (free-space диаграмма) Fréchet для сравнения кривых в тестах соответствия.
376. **Мэтчинг по сигнатуре кривизны** — выравнивание по инвариантной сигнатуре κ(s) (и τ(s)) с DTW; инвариантно к параметризации и движениям.
377. **Топологически безопасное упрощение** — запрет смены гомотопического класса: тест самопересечений и расстояний до других кривых.
378. **Полигональная аппроксимация с сертификатом** — адаптивная хордовая дискретизация с интервально доказанной границей ≤ ε.
379. **Компенсация крутки сверх RMF** — распределение остаточной крутки по длине пропорционально κ (double-reflection + torsion-proportional).
380. **Sweep с морфингом профилей** — интерполяция профилей по s с выравниванием узлов и степеней перед интерполяцией точек.
381. **no_std-ядро** — оценка базиса и de Boor в no_std-подкрейте (libm, без alloc): статические буферы для степени ≤ const N.
382. **Const-generic степень** — `BasisFuns<const D: usize>`: развёртывание циклов, устранение bounds-check на горячем пути.
383. **Оценка без аллокаций** — evaluate-API принимают `&mut [f64]`-буферы; тест с `#[global_allocator]`-счётчиком «не аллоцирует».
384. **Fixed-point NURBS** — прототип оценки в Q32.32 (i64) для embedded/FPGA; отчёт точности против f64 на golden-моделях.
385. **Дифференциальное тестирование** — харнесс: одинаковые операции через своё ядро и curvo/truck, сравнение с допуском на известные расхождения.
386. **Reproducible builds** — rust-toolchain.toml, Cargo.lock, CI-проверка бит-идентичности WASM-артефакта (два билда → один хеш).
387. **cargo vet / supply chain** — audits.toml для зависимостей ядра; запрет новых unaudited-зависимостей в геометрических крейтах.
388. **Галерея-примеров как тесты** — каждый пример в examples/ исполняется в CI и сравнивается с golden-выводом; документация из тех же файлов.
389. **Документация-пайплайн** — doctest исполняются; формулы из docs-as-spec выгружаются в mdbook; CI падает при рассинхроне.
390. **Устойчивость к денормалам** — FTZ/DAZ-осознанные тесты: координаты ~1e-310 не дают NaN; предварительное масштабирование входа.
391. **Согласованные производные** — все производные против конечно-разностной оценки с адаптивным шагом (√ε·|x|).
392. **Мономиальный тест точности** — property: B-сплайн степени ≤ d точно воспроизводит мономы (тождество Марсдена).
393. **Marsden identity как инвариант** — (s−t)^d = Σ N_i(t) ψ_i(s) как property-тест базиса для случайных узловых векторов.
394. **Стабильность find_span на границах** — u == max knot, кратные узлы, политика «правого» интервала; детерминизм на кратном узле.
395. **Рациональная оценка Хорнером в 4D** — один проход de Boor в однородных координатах до деления; веса не делить по ходу.
396. **Диагностика вырожденных весов** — валидатор: w_i ≤ 0, w_i → 0/∞, смешение знаков; отдельные коды ошибок.
397. **Бэктрекинг ветвей пересечений** — после Bézier clipping собирать все ветви, дедуплицировать по (t1,t2) с tolerance-метрикой; отчёт о пропущенных кратных корнях.
398. **Численная производная узлового вектора** — выполнимость knot removal оценивать до операции (норма изменения точек, Boehm projection).
399. **Сертифицированный тест плоскости/линейности** — «кривая плоская/прямая» через интервальную норму точек к плоскости, не eps на точках.
400. **Конфигурационные пределы IEEE-режима** — закрепить тестом поведение при -0.0, NaN, ±∞ на входе: валидация или детерминированная пропагация.

## Часть VI. Поверхности, B-rep-операции и приложения (401–450)

401. **SSI topology: loop detection** — граф замыкания кривых пересечения в параметрических пространствах обеих поверхностей; петли vs ветви на границы.
402. **Tangential surface contacts** — при касательном контакте переключаться с marching на квадратично-скорректированный шаг с проверкой смешанного произведения.
403. **Singular SSI points** — классификация касаний (bipoint, isolated, crossing) рангом Якобиана F=0, ∇F=0; локальная топология ветвления.
404. **Offset self-intersection trimming** — самопересечения офсета: клиппинг областей |d| < min радиуса кривизны, подрезка по медиальной оси.
405. **Offset validity precondition** — максимально допустимое смещение = min радиус главных кривизн (уточнение Ньютоном); отказ заранее.
406. **Variable-radius fillets** — R(t) кубическим сплайном вдоль рёберной цепочки; филлет как sweep сечения переменного радиуса.
407. **Chordal fillets** — фиксированная хорда: R(t) = chord/(2·sin(θ(t)/2)) из угла между гранями.
408. **Rolling-ball vs disk blend** — оба режима; тест расхождения на неортогональных рёбрах.
409. **Spine-guided blends** — сечения в плоскостях, перпендикулярных спайну, а не рёбрам; критично на наклонных углах.
410. **Setback/vertex blends** — угловой патч со setback-точками на сходимости ≥3 филлетов; заполнение n-sided Gregory-патчем.
411. **Thicken with openings** — thicken до солида с гранями-исключениями; смещать выбранные грани, сшивать боковые стенки.
412. **Shell failure reporting** — структурированный диагноз: какие грани самопересеклись, предложение исключить их.
413. **Draft-angle analysis** — распределение угла нормаль/разъём; раскраска граней (недостаточный/достаточный/negative draft) + отчёт.
414. **Demolding check** — лучевой тест вдоль разъёма от каждой точки; пересечение = зона застревания; тепловая карта.
415. **Undercut detection** — поднутрения: нормаль·разъём < 0 при затенении луча; группировка в связные регионы.
416. **Wall-thickness analysis** — луч по антинормали до ближайшего пересечения; поле толщины; подсветка зон ниже порога.
417. **Linear/circular feature patterns** — паттерны на уровне фич: переоценка топологических ссылок на экземпляр + сшивка с солидом.
418. **Pattern on curved faces** — раскладка паттерна по (u,v)-сетке несущей поверхности с проекцией и локальной переориентацией.
419. **Mirror feature with sewing** — отражение фичи + union+sew при контакте копии с оригиналом.
420. **Mesh→B-rep upgrade** — RANSAC-сегменты (плоскости/цилиндры/конусы/сферы) заменяются аналитическими/NURBS гранями с p-кривыми на границах.
421. **Cylinder/cone recognition from facets** — ось и радиус МНК по нормалям; валидация по RMS и порогу угла.
422. **Non-manifold cellular models** — generalized cellular topology: рёбра с >2 гранями, coedges с per-face ориентацией, явная маркировка в API.
423. **Selective simplification** — коллапс мелких граней (площадь < ε·средней) в соседние с re-trim; сохранение габаритов и массовых свойств.
424. **Small-edge/sliver heal** — рёбра короче tol или углы < min_angle объединять; проверка валидатором топологии (Эйлер–Пуанкаре).
425. **Trimmed-surface meshing via CDT** — p-кривые тримов как constrained edges в CDT в (u,v), удаление внешних по чётности, подъём в 3D с контролем отклонения.
426. **P-curve quality repair** — до CDT: снаппинг разрывов швов, удаление самопересечений и вырожденных сегментов, репараметризация швов.
427. **Quad-dominant meshing** — естественная (u,v)-параметризация граней → quad-сетка, треугольники у trim-границ; сглаживание нодов в 3D с проекцией.
428. **FEA-oriented adaptive sizing** — h(x) = min(h_curv(r), h_feature, h_user); сглаживание градиента |∇h| ≤ 0.3.
429. **STEP assemblies/products** — NEXT_ASSEMBLY_USAGE_OCCURRENCE-дерево: экземпляры, трансформации, имена; сохранение иерархии при round-trip.
430. **PMI basics (STEP AP242)** — размеры, GD&T-рамки, семантические ссылки на грани (PRESENTATION + SEMANTIC); overlay в viewer.
431. **JT / QIF / 3D-PDF** — импорт JT (LODs + XT B-rep), экспорт QIF для метрологии, 3D-PDF (PRC) для отчётов; матрица возможностей в docs.
432. **three.js/web NURBS viewing** — three.js NURBSSurface vs свой WASM-тесселятор + WebGL; замер FPS на 1k граней, рекомендация в ARCHITECTURE.md.
433. **Progressive meshes from NURBS** — LOD-иерархия (edge collapse с pinned trim-вершинами), LOD0..n, переключение по дистанции камеры.
434. **View-dependent tessellation** — экранная ошибка ε_px → 3D-допуск через bounding sphere; пересчёт при смене view с гистерезисом.
435. **Frame budgeting** — бюджет N мс/кадр: очередь задач по приоритету (видимость × экранная площадь × staleness), прерывание по бюджету.
436. **WebWorker tessellation pools** — пул воркеров, задачи = грани (surface, tolerance) → transferable Float32Array; дедупликация по hash грани.
437. **OffscreenCanvas rendering** — WebGL-контекст в worker; main thread только input; замер jank до/после.
438. **Per-face LRU cache** — ключи (face_hash, tolerance, lod), LRU по байтам VRAM/heap; hit-rate в HUD.
439. **Memory budgets for assemblies** — глобальный бюджет (2 ГБ) по компонентам пропорционально экранной значимости; даунгрейд LOD дальних экземпляров.
440. **Point-membership classification** — PMC для B-rep: луч в generic направлении, чётность пересечений + проверка близости к грани (on/in/out).
441. **Ray-parity robustness** — попадание в ребро/вершину: чётность по знаку нормаль·луч; fallback — повторный луч в случайном направлении.
442. **B-rep diff/merge** — diff по face hash + topological naming (matched/modified/added/deleted); merge с конфликт-детекцией по изменённым подграфам.
443. **Semantic feature-tree diff** — сравнение feature DAG параметрически; человекочитаемый diff «fillet R3→R5 на edge#12».
444. **CRDT collaborative editing** — параметры как LWW-регистры, feature DAG как RGA-список; синхронизируется исходник, не тесселяция.
445. **ISO 10303 conformance audit** — валидация экспорта (обязательные атрибуты, ссылочная целостность, AP203/AP242); audit log round-trip ошибок в CI.
446. **Kernel testing taxonomy** — слои: unit / integration (B-rep) / golden models / property-based (инварианты Эйлера, замкнутость) / fuzz; каталог и SLA каждому.
447. **Coverage-guided fuzzing** — cargo-fuzz таргеты на парсеры STEP/IGES/STL и булевы со случайными поливалидными входами; корпус в git, краши по seed.
448. **Sanitizer CI** — ASan/TSan/Miri на крейтах с unsafe; WASM с overflow-checks; запрет #[allow] без обоснования.
449. **Reproducible WASM builds** — фиксация toolchain, Cargo.lock, wasm-bindgen, SOURCE_DATE_EPOCH; CI: bit-идентичность двух сборок (sha256).
450. **Interactive playground** — редактор DSL → WASM в worker → прогрессивная тесселяция → WebGL; share через URL (модель в hash), без бэкенда.

## Часть VII. Продвинутая численность (451–533)

451. **Moving lines для имплицитизации кривых** — семейство движущихся линейных форм Седерберга, обращающихся в нуль на рациональной кривой; определитель матрицы moving lines даёт имплицитное уравнение без громоздкого вычисления результанта.
452. **μ-базис рациональной кривой** — минимальный базис модуля движущихся линий степеней μ₁+μ₂=n; имплицитизация сводится к определителю 2×2 из μ-базиса и автоматически отсекает лишние факторы.
453. **Moving surfaces для тензорных патчей** — обобщение на движущиеся плоскости и квадрики, обращающиеся в нуль на поверхности; матричный метод Седерберга–Чена даёт имплицитную форму патча как определитель.
454. **μ-базис поверхности по Доккену** — практический алгоритм вычисления минимального базиса движущихся плоскостей через последовательное понижение степени; работает для биквадратичных и бикубических параметризаций CAD-патчей.
455. **Сизигии и свободные резольвенты** — μ-базис вычисляется как базис модуля сизигий параметризации; нужен алгоритм над кольцом многочленов (нормальные формы Грёбнера или интерполяционные схемы Кокса).
456. **Base points и лишние факторы** — базисные точки параметризации порождают посторонние множители в результанте; μ-базис и moving surfaces с квадриками устраняют их, давая чистую имплицитную форму.
457. **Имплицитная форма в булевых операциях** — перевод пересечения «параметрическая поверхность × параметрическая поверхность» в систему f(u,v)=0, g(u,v)=0 снимает проблему поиска начальных точек трассировки.
458. **GJK для контрольных полигонов** — расстояние между выпуклыми оболочками контрольных сеток за итерации по симплексам Минковского; мгновенный отсев заведомо непересекающихся патчей перед SSI.
459. **EPA для глубины проникновения** — расширение политопа после срабатывания GJK даёт направление и величину проникновения оболочек; нужно для контакт-анализа и сдвига тел перед булевыми.
460. **SAT по разделяющим осям** — тест разделяющей оси для OBB контрольных сеток дешевле полного GJK на регулярных конфигурациях; 15 осей для двух OBB, ранний выход при первом зазоре.
461. **Иерархия OBB-деревьев для B-rep** — двухуровневый обход деревьев ориентированных боксов патчей сокращает пары кандидатов пересечения с O(n·m) до почти линейной по выходу.
462. **Отсев по контрольной сетке до Ньютона** — проверка непересечения проекций контрольных полигонов и интервальных оценок производных отсекает ложные стартовые точки итераций point-to-curve/surface.
463. **Range enclosure интервалами** — интервальная оценка образа базисных функций и всей кривой на подотрезке; гарантированные границы значений вместо выборочного сэмплирования.
464. **Аффинная арифметика против dependency problem** — хранение интервала как аффинной формы с шумовыми символами отслеживает корреляции и резко сужает обёртку по сравнению с классическими интервалами на длинных цепочках операций.
465. **Интервальный Ньютон Мура** — оператор N(X)=m−f(m)/F′(X) либо доказывает единственность корня в боксе, либо доказывает его отсутствие; основа сертифицированной изоляции корней.
466. **Оператор Кравчика** — вариант интервального Ньютона с предобуславливанием матрицей; сертификат существования через теорему Брауэра без инверсии Якобиана в точности.
467. **Тейлор-модели** — представление функции как полином степени k плюс интервальный остаток; подавляют раздувание обёртки там, где интервалы и аффинные формы деградируют.
468. **Валидация остатка Тейлор-модели** — границы остатка считаются интервальным вычислением (k+1)-й производной (схемы Берца–Макино); даёт строгий enclosure для кривизны и нормалей на целом патче.
469. **Forward AD на дуальных числах** — значение плюс производная в одном проходе без символьных выражений; точные градиенты point inversion и фиттинга без ручного вывода формул.
470. **Гипердуальные числа для Гессианов** — расширение дуальных чисел до ε₁ε₂=0 даёт точные вторые производные; нужно для кривизны, Ньютона второго порядка и α-теории.
471. **Reverse AD для фиттинга** — обратный проход вычисляет градиент по тысячам контрольных точек за время, сопоставимое с одной оценкой функции; без него least-squares фиттинг с градиентным спуском не масштабируется.
472. **Кросс-валидация AD против символьных производных** — property-тест: производные по A4.2/A4.4 обязаны совпадать с дуальными числами до ULP-уровня; ловит ошибки в ручных формулах рациональных производных.
473. **Адаптивная точность Шевчука** — предикаты orient2d/orient3d/incircle с ранней фильтрацией и расширением точности только при неопределённом знаке; золотой стандарт робастных геометрических решений.
474. **Арифметика экспансий** — число как сумма неперекрывающихся double (Shewchuk, Priest); grow-expansion и expansion-sum дают точные знаки детерминантов без произвольной точности.
475. **Фильтрация предикатов** — быстрый путь на double с априорной оценкой ошибки; при входе в полосу неопределённости — fallback на экспансии; 99.9% вызовов остаются на скорости FPU.
476. **Статические vs динамические фильтры** — статическая граница ошибки считается при компиляции из структуры выражения, динамическая — на лету; выбор влияет на порог переключения в точный путь.
477. **Simulation of Simplicity** — символьное возмущение Эдельсбруннера–Мюкке разрешает вырождения (касания, тройные точки) без особых веток кода; предикаты остаются консистентными при совпадающих входах.
478. **Предикаты в однородных координатах** — тесты стороны и ориентации для рациональных точек (wx,wy,wz,w) без проективного деления; деление вносит ошибку именно там, где нужен точный знак.
479. **Изоляция корней Штурмом** — цепочка Штурма даёт точное число вещественных корней полинома на интервале; сертифицированный старт для всех ветвей пересечения.
480. **Алгоритм VAS** — правило знаков Винсента–Акритаса–Стржебонского с преобразованиями Мёбиуса изолирует корни быстрее Штурма на практике; стандарт в CAS для univariate-изоляции.
481. **Бисекция с сертификатом единственности** — субдивизия бокса до тех пор, пока интервальный Ньютон не подтвердит единственный корень; гарантированно полный список решений, никаких «пропущенных ветвей».
482. **Сертифицированный экстремум кривизны** — enclosure второй производной на сегменте доказывает, что найденный стационарный максимум глобален; критично для допусков тесселяции и офсетов.
483. **Гомотопическая континуация для SSI** — деформация простой системы с известными корнями в целевую с трекингом путей; находит все изолированные решения без начальных приближений.
484. **Полиэдральные гомотопии** — число путей равно смешанному объёму Бернштейна, часто на порядки меньше полного произведения степеней Безу; делает континуацию практичной для бикубических систем.
485. **Предиктор-корректор с адаптивным шагом** — трекинг гомотопических путей: предиктор Эйлера/Рунге–Кутты, корректор Ньютоном, шаг по оценке кривизны пути; иначе пути скачком теряются.
486. **Трассировка ветвей через гомотопию к касанию** — обнаружение критических точек ветви продолжением к вырожденному положению; надёжнее поиска поворотов по сетке параметров.
487. **Липшиц-константы из enclosure градиента** — L = sup|∇f| на боксе из интервальной оценки производных; превращает «кажется далеко» в доказанный отсев в субдивизионных алгоритмах.
488. **Липшиц-отсев в рекурсивной субдивизии** — если нижняя грань расстояния до цели превышает текущий рекорд плюс L·радиус бокса — вся ветвь отбрасывается; даёт исчерпывающий поиск без полного перебора.
489. **α-теория Смейла** — величина α(f,x)=β·γ сертифицирует квадратичную сходимость Ньютона до запуска итераций; заменяет эвристику «сошлось, наверное» доказательством.
490. **γ-теорема и безопасный старт** — γ(x)=sup‖f⁽ᵏ⁾/k!‖^{1/(k−1)} определяет радиус гарантированной сходимости; выбор стартовых точек субдивизией до γ-порога исключает расходимость.
491. **Обусловленность оценки точки кривой** — чувствительность C(u) к возмущению контрольных точек и весов; объясняет, почему большие веса ухудшают точность даже при стабильном де Буре.
492. **Обусловленность пересечения** — точность пересечения двух поверхностей ограничена сверху ~1/sin(угол между нормалями); при касательном контакте никакая арифметика не даст лучше √ε.
493. **Backward error, компонентная норма** — результат верен как точное решение возмущённой задачи с малым компонентным возмущением входа; правильный критерий качества вместо «ошибки результата».
494. **Forward error = condition × backward** — разделение: backward error отвечает за алгоритм, condition number — за задачу; отчёт об ошибке в ядре должен показывать оба числа.
495. **Error budget ledger** — учёт вклада каждой операции конвейера (оценка → проекция → булевы → тесселяция) в итоговый допуск; предотвращает ситуацию «допуск съеден на втором шаге».
496. **Диаграмма Вилкинсона выражения** — граф вычисления с разметкой границ ошибки каждого узла; автоматически находит катастрофическое сокращение (cancellation) в формулах ядра.
497. **Имплицитизация с допуском** — символьно-численная схема: точные степени и структура, численные коэффициенты; контроль ранга через SVD вместо точного определителя на float-входах.
498. **Symbolic preprocessing + numeric solving** — гомогенизация, выбор базиса и упрощение системы символьно, решение численно; гибрид устойчивее чисто символьных и чисто численных подходов.
499. **Рациональная реконструкция весов** — восстановление точных дробей из float-весов алгоритмом непрерывных дробей с границей знаменателя; возвращает «красивые» веса при импорте STEP/IGES.
500. **Слой EGC (Exact Geometric Computation)** — выражения с гарантированным знаком в стиле LEDA/CGAL: каждое сравнение либо точно, либо уточняется; страховка топологии B-rep от неверных решений предикатов.
501. **Граница степени выражения** — для EGC-предиката заранее известна степень полинома и битовая длина, достаточная для знака (границы Кэушика–Яп); позволяет выбирать точность до вычисления.
502. **Ленивая точная оценка** — трёхуровневый fallback: интервалы → экспансии → рациональная арифметика; точный путь оплачивается только в вырожденных случаях, средняя производительность не падает.
503. **Субдивизионная изоляция решений (quadtree)** — рекурсивное деление параметрической области с тестами исключения/включения; выдаёт сертифицированный список боксов со всеми решениями системы.
504. **Сертифицированная топология ветви** — изоляция всех особых точек (касания, самопересечения) кривой пересечения до трассировки; гарантирует правильную связность сегментов SSI.
505. **Enclosure нормалей патча** — интервальная оценка ∂S/∂u × ∂S/∂v даёт гарантированный конус нормалей всего патча; основа отсева по освещению, видимости и draft-анализа.
506. **Отсев силуэтов по конусу нормалей** — если конус нормалей не содержит направления, ортогонального взгляду, силуэта на патче нет; отбрасывает большинство патчей силуэтного рендера без вычислений.
507. **Гарантированные боксы через degree elevation** — выпуклая оболочка после повышения степени сходится к кривой; конечное число elevations даёт AABB с сертификатом точности ε.
508. **Минимальное расстояние с сертификатом** — субдивизионный поиск с Липшиц-отсевом доказывает, что найденная пара ближайшая глобально, а не локальный минимум Ньютона.
509. **Верифицированное расстояние Хаусдорфа** — двусторонние enclosure расстояний точка↔кривая дают сертифицированный H(A,B); единственно корректная метрика для сравнения ядра с референсами.
510. **Хаусдорф контрольных полигонов** — расстояние между контрольными полигонами до и после упрощения ограничивает отклонение кривых через базисное неравенство; дешёвый сертификат качества knot removal.
511. **Интервальная кривизна** — enclosure K(u,v) и H(u,v) по целому патчу из интервальных первой и второй фундаментальных форм; доказанные границы кривизны для офсетов и тесселяции.
512. **Сертификат отсутствия самопересечений офсета** — если enclosure доказывает d·κ_max < 1 по всей кривой, офсет радиуса d глобально гладок; заменяет дорогой пост-фактум тримминг.
513. **Уточнение кратных корней** — кратный корень обусловлен как m-я степень: ошибка ~ε^{1/m}; вычисление кратности через последовательные производные и соответствующее снижение заявленной точности.
514. **Дефляция кратных решений** — добавление уравнений производных (deflation) превращает кратный корень в простой для расширенной системы; восстанавливает квадратичную сходимость Ньютона.
515. **Бернштейн vs мономиальный базис** — обусловленность Бернштейна на [0,1] в десятки раз лучше степенного базиса при той же степени; запрет мономиальных представлений в ядре — численное решение, не стилистика.
516. **Обусловленность корней полинома** — пример Вилкинсона: возмущение коэффициента на ε сдвигает корни на ε^{1/n}; хранение пересечений как корней требует анализа чувствительности коэффициентов.
517. **Масштабирование параметра** — рескейл u∈[a,b] в [0,1] и центрирование контрольных точек снижает динамический диапазон коэффициентов и обусловленность всех последующих полиномиальных операций.
518. **Trust region для point inversion** — метод доверительной области ограничивает шаг Ньютона там, где кривая сильно изогнута; сходится там, где чистый Гаусс–Ньютон улетает с поверхности.
519. **Левенберг–Марквардт для фиттинга** — демпфированный Гаусс–Ньютон устойчив при почти сингулярном якобиане (параллельные сечения лофта, вырожденные веса); стандарт нелинейного МНК.
520. **Dogleg Пауэлла как fallback** — комбинация шага Коши и Гаусса–Ньютона без факторизации на каждой итерации; дешёвая альтернатива LM при больших системах.
521. **Критерий остановки по backward step** — останавливаться, когда шаг меньше обусловленности-умноженного-на-машинный-эпсилон порога, а не по |f(x)|<tol; иначе итерации крутятся без улучшения результата.
522. **Rank-revealing QR для сингулярных систем** — факторизация с перестановкой столбцов обнажает численный ранг; честная диагностика недоопределённых фиттингов вместо мусорного псевдорешения.
523. **SVD-диагностика ранга ограничений** — сингулярные числа якобиана скетч-солвера показывают недо- и переопределённость; малые σ указывают точные конфликтующие ограничения пользователю.
524. **Сертификат deflection тесселяции** — верхняя грань отклонения хорды от кривой через enclosure второй производной (‖C″‖·h²/8); доказанный допуск сетки вместо эвристического сэмплирования.
525. **A posteriori ошибка МНК** — оценка фактической максимальной девиации аппроксимации сертифицированным point-to-curve расстоянием на контрольной выборке; допуск фиттинга подтверждается, а не предполагается.
526. **Смешанная точность в предикатах** — double-double только в узких местах (знаки детерминантов, произведения весов), обычный f64 в остальном; точность экспансий без их полной стоимости.
527. **Компенсированное скалярное произведение** — алгоритмы Dot2/DotK Огиты–Румпа–Оиси дают точность двойной длины за счёт EFT без библиотек длинной арифметики; критично для нормалей и объёмов.
528. **Компенсированный Горнер** — CompHorner (Graillat–Langlois–Louvet) оценивает полином с точностью u² вместо n·u и отдаёт running error bound бесплатно; апгрейд всех Безье-оценок ядра.
529. **Running error bound** — динамическая граница ошибки, накапливаемая вместе со значением; раннее предупреждение, что результат уже не в допуске, до конца вычисления.
530. **Тестирование под возмущением** — каждый численный тест прогоняется с входом, возмущённым на ±k ULP; устойчивый код обязан давать топологически тот же ответ, флагируются пороговые решения.
531. **Рандомизированная ротация как метаморфный тест** — случайные вращения/перестановки осей не должны менять число пересечений и знаки предикатов; ловит скрытую анизотропную хрупкость.
532. **Herbie-стиль переписывания выражений** — автоматический поиск эквивалентных формул с меньшей ULP-ошибкой на типовых диапазонах входа; систематическая борьба с cancellation в горячих формулах.
533. **Контракт численных гарантий API** — каждая операция ядра документирует backward error, допустимые condition numbers и поведение на вырождениях; пользователь ядра видит, что именно обещано, а что нет.

## Часть VIII. CAD-операции и домены (534–617)

534. **Эвольвента зубчатого колеса** — эвольвента окружности задаётся параметрически (x = r_b(cos t + t sin t), y = r_b(sin t − t cos t)) и кусочно-точно аппроксимируется кубическими NURBS с контролем отклонения по нормали; в ядре нужна для точного профиля зуба, а не полилинии.
535. **Параметры зацепления по ISO 53 / DIN 867** — модуль m, число зубьев z, угол профиля α=20°, делительный диаметр d=mz и диаметр основной окружности d_b=d·cos α должны быть явными полями фичи Gear, чтобы ядро строило профиль из стандартных параметров, а не из сырых координат.
536. **Коррекция профиля зуба (смещение исходного контура)** — коэффициент смещения x сдвигает реечный инструмент на x·m, меняя толщину зуба и диаметр вершин; ядро должно поддерживать x≠0 для устранения подрезания при z < z_min = 2/sin²α.
537. **Подрезание и граница переходной кривой** — область у ножки зуба, обрезанная вершиной рейки, описывается переходной кривой (трохоидой углубления); её нужно генерировать обводкой угла рейки, иначе симуляция прочности зуба некорректна.
538. **Косозубые колёса как sweep со скруткой** — эвольвентный профиль экструдируется вдоль оси с углом наклона зуба β (lead L = πd/tan β); это скрученный sweep поверх RMF-компенсации, где точность начала/конца витка критична для торцевых фасок.
539. **Конические колёса и октоидное зацепление** — зубья строятся на дополнительном конусе с углом δ, профиль — сферическая эвольвента, аппроксимируемая по методике Тредгольда (эквивалентное цилиндрическое колесо z_v = z/cos δ); ядру нужен конусный лофт с переменным профилем.
540. **Циклоидальные профили (часовые и редукторные передачи)** — эпициклоида и гипоциклоида задаются радиусами катящихся окружностей и собираются в профиль зуба часовых колёс по BS 978; требуется кусочная аналитическая сборка с G1-стыками дуг и прямых.
541. **Обкатка как булева симуляция профиля** — профиль зуба получается огибающей семейства положений инструмента (метод огибающих); реализуется как многократный boolean-вычитание или envelope-вычисление — прямая проверка булевых операций ядра на массовых тонких сечениях.
542. **Кулачки: закон движения толкателя** — профиль кулачка строится из диаграммы s(φ): участки покоя, подъёма по циклоидальному или полиномиальному закону 3-4-5, обеспечивающему C² по скорости/ускорению; ядро должно интерполировать s(φ) сплайном с заданной гладкостью.
543. **Профиль кулачка через инверсию движения** — огибающая положений роликового толкателя в обращённом движении даёт кривую профиля с радиусом-вектором r(φ) = r₀ + s(φ); для роликового толкателя это офсет на радиус ролика — прямое применение офсета кривой с контролем самопересечений.
544. **Проверка подрезания и минимального радиуса кривизны кулачка** — условие ρ_min > r_roller + margin и ограничение угла давления φ ≤ 30–45° вычисляются по кривизне профиля; ядро должно давать поле кривизны вдоль профиля как сервис.
545. **Резьба ISO metric: профиль по ISO 68** — треугольный профиль с углом 60°, шаг P, высота профиля H = (√3/2)P, срезы вершин H/8 и впадин H/4; ядро должно строить точное сечение-профиль как замкнутый полигон с аналитическими углами, а не треугольник «на глаз».
546. **Резьба как скрученный sweep профиля** — сечение резьбы движется по винтовой линии r(θ) с шагом P; для f64-ядра важна развертка винтовой линии с большим числом витков без накопления ошибки угла (θ = 2π·n витков).
547. **Трапецеидальная резьба DIN 103 и ACME** — профиль 30° (метрическая) / 29° (ACME) с зазорами по вершинам и впадинам; отдельная фича, поскольку сечение — трапеция с фасками, а не треугольник, и допуски заданы по DIN 103-3.
548. **Фаски и сбеги резьбы** — начало резьбы (зафрезеровка по ISO 4753) и сход витка на выходе — полувиток с убывающей глубиной профиля; моделируется масштабируемым профилем в sweep, что проверяет поддержку morphing-профилей в ядре.
549. **Различение наружной/внутренней резьбы и болт-гайка допуски** — классы допусков 6g/6H (ISO 965) смещают средний диаметр; ядро должно строить номинальный профиль и давать API для смещения профиля на допуск, чтобы модели болта и гайки не интерферировали в сборке.
550. **Пружины: цилиндрическая винтовая линия с коррекцией торцов** — рабочие витки с шагом t и прижатые опорные витки с шагом, убывающим до 0.25d; требуется винтовая кривая с переменным шагом (геликоид с нелинейным законом z(θ)).
551. **Проволочный профиль пружины и овализация сечения** — при навивах сечение проволоки оваливается (эффект Уолла); для точной массы и КМП ядро должно поддерживать sweep эллиптического сечения вдоль винтовой линии.
552. **Конические и бочкообразные пружины** — радиус витка r(θ) линейно или по квадратичному закону меняется по высоте; это sweep по обобщённой спирали, проверяющий параметрическое семейство r(θ), z(θ) в ядре.
553. **Шпонки по DIN 6885 / ISO 773** — призматическая шпонка с размерами b×h от диаметра вала, пазы по глубине t₁ (вал) и t₂ (втулка); фича должна автоматически выбирать сечение по d вала и строить паз как boolean с заданными глубинами.
554. **Шлицевые соединения: эвольвентные по DIN 5480 и прямобочные по ISO 14** — вал и втулка с z шлицами; эвольвентный шлиц — то же зацепление, что у шестерни, с углом 30°; переиспользование gear-профиля в другой фиче — тест модульности ядра.
555. **Посадки ISO 286: система отверстия/вала** — поля допусков H7/g6 и т.п. задаются IT-градациями (IT = 10^{0.2·(ITG−1)}·i, i = 0.45∛D + 0.001D); ядро должно иметь таблицу отклонений ES/EI/es/ei и применять их к цилиндрическим граням как сдвиг диаметра.
556. **Геометрия под посадку с натягом** — для посадок с натягом (H7/p6) моделируемая геометрия должна строиться по максимуму материала (внутренний цилиндр больше наружного), чтобы CAD честно показывал интерференцию в сборке, а не «скрывал» её номиналом.
557. **Bend allowance и bend deduction** — длина развёртки гиба BA = (π/180)·θ·(R + k·T); ядро должно уметь вычислять BA по углу, радиусу и толщине и строить развёртку с учётом нейтральной линии, смещённой на k·T.
558. **K-фактор и его зависимость от R/T** — k = 0.5 только при больших радиусах; для R/T < 1 k ≈ 0.33 (таблицы DIN 6935 / эмпирика); фича sheet metal должна принимать таблицу k(R/T, материал), а не константу.
559. **Модель гиба: граница гиба и tangent lines** — гиб в 3D — область между двумя касательными линиями с внутренним радиусом R; ядро строит тороидальную/цилиндрическую грань гиба и сшивает её с плоскими фланцами с G1-стыками.
560. **Развёртка листовой детали с деформацией** — unroll плоских фланцев тривиален, но зона гиба разворачивается с учётом удлинения/сжатия; нужен anisotropic unroll, где метрика в зоне гиба масштабируется по k-фактору — расширение общего unrolling-алгоритма.
561. **Рельефы гиба (bend relief) и разрывы** — прямоугольные или круглые reliefs на краях гиба предотвращают разрыв материала; фича вычитает relief из развёртки и из сложенной модели, требуя согласованности 3D↔flat состояний.
562. **Штамповочные элементы: лоуvers, ланцы, вытяжка** — вытяжка (deep drawing) меняет толщину стенки по закону утонения; для CAD-ядра достаточно параметрических формообразующих фич с заданной глубиной и радиусами, но они должны оставаться редактируемыми в дереве.
563. **Пресс-формы: уклоны (draft) с линией разъёма** — draft-фича наклоняет стенки на 0.5–3° относительно нейтральной плоскости/кромки с сохранением или уменьшением размера (parting-line draft); ядро должно поворачивать грани вокруг линии разъёма, а не просто taper-трансформировать тело.
564. **Линия разъёма и разделение формы** — автоматический поиск silhouette-кривых в направлении вытягивания и построение parting surface (часто — ruled/lofted поверхность через силуэт); прямое применение силуэтных кривых из ядра.
565. **Shrinkage-компенсация** — модель масштабируется на (1 + s) по осям (изотропно или анизотропно для усадки материала, например ABS 0.4–0.7%); фича должна быть неразрушающей — масштаб применяется как обёртка над телом, сохраняя исходную параметрию.
566. **Поднутрения и выдвижные сегменты (lifters/sliders)** — поднутрение мешает извлечению по направлению разъёма; ядро должно находить поднутрения относительно пары направлений и помечать зоны для слайдеров — расширение undercut-detection на мульти-осевой случай.
567. **Система охлаждения формы: каналы как sweep-тела** — conformal cooling channels повторяют форму полости на расстоянии 8–15 мм; это офсетная поверхность + sweep трубы вдоль неё — хороший стресс-тест офсетов и sweeps.
568. **GD&T: датумы и reference frames** — датум A/B/C строит базовую систему координат (плоскость + ось + точка) по правилу 3-2-1; ядро должно уметь создавать именованные датумы на гранях и вычислять DRF (datum reference frame) с вырожденными случаями.
569. **Позиционный допуск и зона допуска** — допуск позиции Ø0.1 задаёт цилиндрическую зону вокруг истинной позиции; проверка отверстия = расстояние оси от теоретического центра ×2 ≤ Ø0.1; ядро должно извлекать ось цилиндрической грани и считать отклонение.
570. **MMC/LMC-модификаторы** — при MMC допуск позиции растёт на бонус = |фактический размер − MMC|; ядро должно считать фактический mating size (наибольший вписанный цилиндр для отверстия) — задача fitting-а цилиндра к тесселированной/аналитической грани.
571. **Допуски формы: плоскостность, цилиндричность, профиль** — плоскостность = расстояние между двумя параллельными плоскостями, охватывающими грань (min-zone по Chebyshev, не least squares); требуется min-zone fitting — отдельный численный алгоритм поверх геометрии ядра.
572. **Профиль поверхности с/без датумов** — profile of a surface задаёт равномерную зону ±t/2 вокруг теоретической поверхности; проверка = max |signed distance| точек грани до номинальной NURBS-поверхности — массовый point-inversion, тест производительности ядра.
573. **Робототехника: рабочее пространство манипулятора** — reachable workspace строится дискретизацией сочленений и volumetric-аппроксимацией (DEX-метрика); ядро предоставляет boolean-union тысяч сфер/цилиндров или alpha-shape поверхность для визуализации границы.
574. **Ориентация инструмента и поверхностные ограничения** — допустимая ориентация TCP задаётся конусом вокруг нормали поверхности (например ±30° при полировке); ядро должно выдавать поле нормалей вдоль траектории и проверять угол к ней.
575. **Траектория по поверхности: изолинии и constant scallop** — траектории покрытия (покраска, шлифовка) строятся как офсеты на поверхности с шагом, зависящим от ширины пятна инструмента; геодезический офсет с контролем scallop height h ≈ s²/(8R).
576. **Конфигурационные особенности в декартовом пространстве** — сингулярности (вырожденный якобиан) проецируются в зоны, где скорость сочленений →∞; для CAD-ядра важно визуализировать эти зоны как поверхности в рабочем пространстве.
577. **3D-печать: генерация supports для overhang** — области с углом нормали к вертикали > 45° (или заданным) требуют поддержки; ядро находит down-facing области по полю нормалей и строит tree/block supports до ближайшей поверхности — ray-casting сервис ядра.
578. **Анализ толщины стенки для печати** — min wall thickness (0.8–2 мм для FDM) проверяется медиальной осью или ray-зондами в обоих направлениях нормали; тонкие зоны должны подсвечиваться на модели до экспорта в слайсер.
579. **Lattice-заполнение: TPMS и струты** — gyroid-домены задаются неявным полем sin(x)cos(y)+... > t и превращаются в оболочку marching-cubes/lattice-балками вдоль ячеек; ядро должно резать lattice по B-rep границе тела (boolean с неявным телом).
580. **Проверка самопересечений перед слайсингом** — модель для печати обязана быть watertight и 2-manifold; сервис ядра — отчёт о self-intersections, open edges, flipped normals с привязкой к граням для ремонта.
581. **Ориентация детали на столе: оптимизация по поддержкам/времени** — перебор углов ориентации с оценкой overhang-площади, высоты Z и площади контакта со столом; ядро предоставляет проекции и mass-properties для скоринга.
582. **Оптика: freeform-поверхности линз** — свободная форма задаётся Zernike-полиномами или XY-полиномами поверх базовой коники (sag = cr²/(1+√(1−(1+k)c²r²)) + ΣAᵢZᵢ); ядро должно строить NURBS-аппроксимацию sag-поверхности с точностью < λ/10.
583. **Константа коничности и асферика** — conic constant k (k=−1 парабола, k<−1 гипербола) полностью определяет сечение зеркала; рациональная квадратичная кривая с весом из k — прямое применение конических сечений ядра.
584. **Оптические допуски: sag error и slope error** — качество поверхности задаётся не только отклонением по высоте (PV, RMS), но и по углу нормали; ядро должно выдавать оба поля ошибок между изготовленной и номинальной поверхностью.
585. **Дороги: клотоидные переходные кривые** — между прямой и круговой кривой вставляется клотоида с параметром A² = R·L (A — параметр клотоиды); ядро должно строить клотоиду через ряды Френеля и аппроксимировать её NURBS с допуском 1 мм на 100 м.
586. **Сборка трассы: прямая–клотоида–дуга–клотоида–прямая** — пикетаж и таблица элементов (PI, R, A) собираются в единую G1/G2-цепочку с проверкой стыков по кривизне; это constraint-driven сборка кривых, а не ручной spline.
587. **Вираж и продольный профиль** — поперечный уклон меняется линейно вдоль переходной кривой (отклонение от оси пути как функция пикетажа); поверхность дороги = sweep поперечного профиля с переменным креном вдоль 3D-направляющей.
588. **Развязки и ветвления трасс** — съезды требуют ветвления коридора: blend между двумя осями с G2; ядро должно поддерживать curve-network fill поверхностей покрытия на узлах развязки.
589. **Ship hull: теоретический чертёж (lines plan)** — корпус задаётся шпациями, ватерлиниями и батоксами; ядро должно строить поверхность скиннингом по шпангоутным сечениям с сохранением fairing-условий (кривизна монотонна между перегибами).
590. **Fairing корпуса: дискриминация плохих точек** — судовой фэйринг требует отсутствия лишних перегибов в линиях кривизны; инструмент — гребёнка кривизны по изолиниям и интерактивное исправление контрольных точек (прямое применение fairing-алгоритмов ядра).
591. **Дифферентка и окончания корпуса** — транец, бульб и ахтерштерн — локальные фичи поверх базовой поверхности корпуса; требуются trimmed blend и локальное переопределение сетки контрольных точек без разрушения глобальной гладкости.
592. **Гидростатика: объём и центр плавучести по осадке** — displacement, центр buoyancy, метацентрическая высота вычисляются интегрированием сечений до ватерлинии; ядро должно сечь корпус плоскостями и считать площади/моменты сечений (mass-properties как сервис).
593. **HVAC: переходы круг–прямоугольник** — transition-фитинг строится лофтом между кругом и прямоугольником с равномерным распределением точек по периметру; классическая задача loft с согласованием параметризации сечений.
594. **Развёртка фитингов HVAC для раскроя** — все фитинги должны разворачиваться в плоскость (по DIN 18379 обрешётка); transition круг–прямоугольник разворачивается триангуляцией (triangulation development); ядро должно давать развёртку с той же сеткой, что и 3D-патч.
595. **Отводы (elbows) из секторов** — многосекторный отвод (lobster-back) строится из усечённых цилиндров под углом; каждый сегмент — trimmed cylinder, развёртка — синусоида; тест точных цилиндрических триммингов и unroll.
596. **Сопряжения тройников: линия проникновения** — пересечение двух цилиндров (branch–main) даёт кривую врезки; это частный случай SSI цилиндр–цилиндр, для HVAC нужен точный аналитический ответ (а не марширующий SSI) и развёртка выреза под сварку.
597. **Шестерни: боковой зазор и проверка зацепления** — backlash задаётся утонением профиля по дуге делительной окружности; ядро должно моделировать пару колёс в зацеплении и проверять интерференцию при вращении — boolean-коллизии в цикле по углам.
598. **Червячная передача: глобоидный червяк** — профиль червяка ZI/ZA по DIN 3975 строится sweep-ом трапецеидального профиля по винтовой линии с углом подъёма γ; высокий lead angle (до 45°) — стресс-тест скрученных sweep-ов.
599. **Кулачковые пары 3D: цилиндрические и глобоидные кулачки** — профиль канавки на цилиндре = развёртка закона движения на цилиндрическую поверхность; требуется wrapping плоской кривой на цилиндр и вырез канавки sweep-ом сечения ролика.
600. **Пружины кручения и растяжения с крюками** — концевые элементы (крюки, петли) — отдельные кривые, сшитые с винтовой частью с G1; фича пружины должна быть составной кривой (composite) с разными законами по участкам.
601. **Шпоночные пазы с выходом фрезы** — паз на валу имеет радиус выхода дисковой фрезы на конце; геометрия паза — не просто призма, а sweep с профилем фрезы; ядро должно моделировать manufacturing-aware фичи.
602. **Посадки: предельные калибры** — гладкие калибры-пробки/скобы по ISO 1938 строятся от предельных размеров посадки; фича генерирует калибр из грани + поля допуска — тест связки допусков ISO 286 с геометрией.
603. **Sheet metal: flange на криволинейной кромке** — отбортовка по кривой кромке требует sweep стенки вдоль кривой с нормалью к плоскости листа; на вогнутых кромках материал «собирается» — развёртка должна отражать удлинение кромки.
604. **Joggle (ступенчатый изгиб) в листовом металле** — двойной гиб малого радиуса для нахлёста листов; параметрическая фича из двух связанных bend-ов с общим k-фактором и проверкой минимального расстояния между гибами (≥ 4T + R).
605. **Пресс-формы: гейт и литниковая система** — литниковые каналы (sprue, runner) моделируются sweep-телами с уклоном 2–5° и сопряжениями радиусами; должны вычитаться из формы и учитываться в shrinkage-обёртке.
606. **Штампы: радиусы вытяжной кромки** — радиус пуансона r_p = (4–6)T и матрицы r_m = (6–10)T определяют возможность вытяжки; CAD-фича deep-draw должна валидировать радиусы против толщины и коэффициента вытяжки β = d/D ≤ 0.55.
607. **GD&T: допуск направления (перпендикулярность, параллельность)** — перпендикулярность оси к датуму = цилиндрическая зона Øt, ось фактического элемента должна лежать внутри; вычисление угла между осями граней — базовый сервис ядра для проверок.
608. **GD&T: биение (runout) и суммарное биение** — circular runout проверяется по разности радиусов в сечении при вращении вокруг датума; ядро должно сечь поверхность плоскостями ⊥ датум-оси и считать radial deviation в каждом сечении.
609. **Робототехника: tool-path для 5-осевой обработки** — движение инструмента по NURBS-поверхности: позиция из point inversion, ось — из нормали + lead/tilt углов; ядро должно выдавать (point, normal, curvature) пакетно вдоль кривой контакта.
610. **Робототехника: sweep-объём инструмента для проверки коллизий** — swept volume фрезы/робота за цикл — boolean-union тысяч поз; ядро должно предоставлять быстрый approximated sweep (конвекс-холлы сечений) для collision checking.
611. **3D-печать: compensation усадки и деформаций** — SLA/SLS дают анизотропную усадку по осям; пре-деформация модели (inverse distortion) применяется как поле смещений к вершинам/контрольным точкам — free-form deformation поверх ядра.
612. **Оптика: TIR-линзы и коллиматоры** — freeform-рефлекторы строятся методом supporting ellipsoids или SMS (Simultaneous Multiple Surfaces); ядро должно аппроксимировать кусочно-гладкие рефлекторные поверхности NURBS-сеткой с заданным slope error.
613. **Оптика: экспорт в Zemax/Code V** — обмен через sag-таблицы (grid sag, DAT-файл) или STEP; ядро должно экспортировать поверхность как регулярную сетку sag с производными, согласованными по краям.
614. **Дороги: 3D-коридор как sweep с супере** — покрытие дороги = sweep поперечного профиля (включая вираж) вдоль пространственной оси (план + продольный профиль); требуется frame вдоль 3D-кривой, не сворачивающийся на крутых кривых (RMF).
615. **Ship hull: разбивка на секции и стыки блоков** — корпус строится блоками (блок-секция), стыки — сварные швы с зазорами; ядро должно резать поверхность корпуса плоскостями швов и сохранять G1 на стыках блоков для гидродинамики.
616. **HVAC: изоляция и кожухи поверх фитингов** — слой изоляции = офсет тела фитинга на 25–100 мм с развёрткой для раскроя; офсет должен корректно работать на составных телах с острыми кромками (mitered offset).
617. **Кросс-домен: единый сервис «производимость» (DFM)** — все домены сводятся к запросам вида «минимальный радиус», «уклон», «толщина», «интерференция»; ядро должно предоставлять единый analysis-API (curvature field, draft map, thickness map, clearance query), на котором строятся все DFM-проверки выше.

## Часть IX. IGA, рендер и приложения (618–700)

618. **Bézier extraction operators** — для каждого элемента сплайна строится матрица C^e, переводящая глобальные контрольные точки в локальные Безье-коэффициенты; вся КЭ-сборка далее работает только с Безье-базисом Бернштейна, что унифицирует IGA с классическим FEM-кодом.
619. **Составной оператор экстракции** — глобальный оператор экстракции как произведение поэлементных C^e для вставки узлов и повышения степени; храните его в разреженном виде, чтобы перестройка дискретизации не трогала геометрию.
620. **Смешанные степени p/q** — экстракция поддерживает разные степени по u и v и локальную вставку узлов; проверяйте тождество M = Σ_e (C^e)ᵀ C^e = I как property-тест сборки.
621. **Интегрирование по Безье-элементам** — квадратура Гаусса на каждом Безье-патче через вытащенные локальные базисы: матрица жёсткости K^e = ∫ BᵀDB dΩ без явной оценки NURBS-базиса внутри цикла квадратуры.
622. **Глобальная сборка КЭ-матриц** — scatter локальных K^e в глобальную разреженную матрицу по карте «элемент → глобальные степени свободы»; на Rust — CSR (sprs) с предварительным построением sparsity pattern по индексным множествам элементов.
623. **Воспроизводимость полиномов (patch test)** — IGA-дизкретизация с NURBS-базисом точно воспроизводит линейные и квадратичные поля при C^p-гладкости; сделайте patch test обязательным regression-тестом сборки.
624. **Слабые граничные условия Нитше** — Dirichlet-условия на криволинейных границах без конформных сеток: добавление членов потока и штрафа −∫(∂u/∂n·v + u·∂v/∂n) + β∫u·v; параметр β оценивайте из обратного неравенства по локальной кривизне границы.
625. **Нитше-склейка неоднородных патчей** — многопатчевые модели с несовпадающими узловыми векторами стыкуются слабо через штрафные члены на интерфейсе; устраняет необходимость глобального merge knot vectors перед анализом.
626. **Оценка штрафного параметра Нитше** — β = C·p²/h_e с константой из локального eigenvalue-задачи на элементе; недооценка даёт неустойчивость, переоценка — плохую обусловленность, оба случая покройте тестами.
627. **Модальный анализ на NURBS** — собственные частоты и формы из обобщённой задачи Kφ = ω²Mφ на том же базисе, что и геометрия; ноль перепараметризации исключает ошибку геометрической аппроксимации в спектре.
628. **Согласованная матрица масс** — M^e = ∫ρ NᵀN dΩ с полной квадратурой (p+1 точек Гаусса); lumping только как опция, поскольку ломает высокую точность спектра C^p-базиса.
629. **Спектральная точность IGA** — при степени p ошибка частот падает как O(h^{2p}); сравнивайте с FEM-серией в бенчмарке на эталонной балке/пластине как демонстрацию преимущества k-refinement.
630. **k-refinement vs h/p-refinement** — повышение степени со вставкой узлов сохраняет максимальную гладкость и даёт меньше степеней свободы на ту же точность; реализуйте как отдельную стратегию измельчения наряду с h и p.
631. **Линейный баклинг (eigenvalue buckling)** — геометрическая жёсткость K_g от начального напряжённого состояния: (K + λK_g)φ = 0; критическая нагрузка λ₁ и форма потери устойчивости без нелинейного итерационного решателя.
632. **Геометрическая матрица жёсткости** — K_g собирается из градиентов базиса и тензора напряжений преднагружённого состояния; требует предварительного статического решения, порядок вызовов закрепите в API анализа.
633. **Пост-критические формы как начальные несовершенства** — масштабированная первая buckling-форма (амплитуда ~ t/100) подмешивается в геометрию для нелинейного посткритического анализа; типовой сценарий тонкостенных оболочек.
634. **IGA-оболочки Кирхгофа–Лява** — C¹-гладкость NURBS устраняет необходимость в степенях свободы вращения: формулировка только по перемещениям, без shear locking и без drilling DOF.
635. **Мембранно-изгибное разложение** — энергия оболочки разделяется на мембранную (первая форма) и изгибную (вторая форма); обе считаются напрямую из фундаментальных форм NURBS-поверхности — геометрия и анализ делят один код производных.
636. **Изгибная жёсткость через кривизну** — изгибная составляющая K^e использует Δκ = κ_deformed − κ_undeformed из второй фундаментальной формы; численно стабильно только при C¹-базисе, что бесплатно даёт IGA.
637. **Контактная формулировка node-to-surface** — проекция slave-узла на master-NURBS-поверхность тем же Ньютоном инверсии точки, что в геометрическом ядре; зазор g = (x_s − x_m)·n и его вариации дают контактную матрицу.
638. **Штрафной контакт vs Лагранж** — penalty-регуляризация проста, но жёсткость контакта зависит от штрафа; множители Лагранжа точны, но расширяют систему — поддерживайте оба с общим интерфейсом ContactConstraint.
639. **Mortar-интегрирование контакта** — проекция контактных невязок на mortar-сегменты устраняет зависимость от выбора slave/master; квадратура по пересечённым подэлементам в параметрической области master-патча.
640. **Поиск контактных пар** — широкая фаза по BVH контрольных сеток (выпуклая оболочка как bound), узкая — инверсия точки на аналитической поверхности; переиспользуйте picking-инфраструктуру вьюера.
641. **Самоконтакт оболочек** — пары ищутся внутри одной поверхности по расстоянию между не смежными областями контрольной сетки; без этого баклинг тонких стенок недооценивает краш-сценарии.
642. **Trim-aware IGA: классификация элементов** — тримминг-кривые разбивают Безье-элементы на cut/uncut/outside; классификация чётностью пересечений луча в (u,v)-домене с робастными предикатами на трим-полигоне.
643. **Квадратура на вырезанных элементах** — cut-элемент триангулируется CDT в параметрической области, квадратурные точки поднимаются на поверхность; глубина подразделения адаптируется под долю вырезанной площади.
644. **Проблема малых вырезанных долей** — элемент с долей площади < 1% даёт почти вырожденные строки матрицы; лечится расширенной обрезкой (extended B-spline) или штрафной стабилизацией граничных базисов.
645. **Stabilized cut elements** — ghost-penalty: штраф на скачок градиента через грани cut-элементов восстанавливает обусловленность независимо от положения трим-кривой; параметр штрафа масштабируется от h и p.
646. **Immersed boundary (Fiction domain)** — геометрия погружена в регулярный B-сплайн-фон: нагрузки и условия Нитше на погружённой границе, интегрирование по реальному материалу через маркер принадлежности на квадратурных точках.
647. **Reconstruction of trimmed basis** — базисные функции, обрезанные трим-кривой, заменяются расширенными функциями соседних стабильных элементов (aggregated/extended B-splines), сохраняя разбиение единицы на вырезанной области.
648. **GPU-оценка поверхности в compute-шейдере** — узловые векторы, контрольные точки и веса в storage buffers; один workgroup на Безье-патч, каждый поток — своя (u,v)-точка; вывод — позиции и аналитические нормали в vertex buffer без обратного чтения на CPU.
649. **Предвычисленные матрицы экстракции на GPU** — для равномерной тесселяции точки и нормали патча = (C^e)ᵀ · (M_bernstein(u) ⊗ M_bernstein(v)) · C^e · P; матричная форма устраняет FindSpan и ветвления в шейдере полностью.
650. **WGSL Bernstein evaluation** — оценка по схеме де Кастельжо над vec4<f32> в однородных координатах с делением на w в конце; фиксированная степень через loop unroll против дивергенции warp'ов.
651. **Адаптивная GPU-тесселяция** — двухпроходная схема: compute-проход оценивает кривизну и экранную ошибку каждого патча, пишет требуемый LOD; второй проход инстанцирует заранее тесселированные патч-шаблоны этого LOD — ноль CPU-участия на кадр.
652. **Патч-шаблоны (pre-tessellated stencils)** — набор индексных буферов N×M для типовых разрешений (2,4,8,16...); рендер выбирает шаблон по LOD, позиции считаются в вершинном/compute-шейдере — переиспользование одной геометрии на всех патчах.
653. **Crack-free LOD между соседями** — разные LOD соседних патчей дают трещины на общем ребре: тесселяция рёбер отдельным проходом с единым LOD на ребро (min двух соседей) или stitching-юбкой в geometry-этапе.
654. **Куллинг по контрольной сетке** — выпуклая оболочка контрольных точек патча как тайт-bound: frustum и occlusion-куллинг на compute-проходе до тесселяции, indirect draw только видимых патчей.
655. **Occlusion culling через HiZ** — иерархия глубины прошлого кадра; контрольные боксы патчей тестируются против HiZ-мипов, невидимые патчи исключаются из indirect buffer — ключевое для плотных сборок.
656. **GPU ray tracing подразделения** — для API с ray tracing (wgpu experimental, Metal, DXR через нативный бэкенд): луч пересекается с AABB-подразделением патча, уточняется итеративным подразделением контрольной сетки по выпуклым оболочкам — точное попадание без треугольников.
657. **Bézier clipping на GPU** — пересечение луч–Безье-патч итеративной обрезкой по «жировым линиям» в проекции на плоскость луча; квадратичная сходимость, фиксированный лимит итераций в compute-шейдере для пикинга и измерений.
658. **Pixel-free рендер: analytic silhouettes** — силуэтные кривые из условия n(u,v)·v = 0 трассируются маршингом в параметрической области с Ньютон-коррекцией; рисуются как 3D-кривые независимо от разрешения — линии чёткие при любом зуме.
659. **Силуэты как трим-операция** — силуэтная кривая разделяет патч на лицевую и обратную части; та же инфраструктура, что и тримминг: классификация точек знаком n·v, CDT домена — переиспользование кода.
660. **Exact edge rendering** — острые рёбра и изокривые рендерятся сэмплированием аналитической кривой с адаптацией по экранной кривизне (пиксельный допуск), а не фиксированным шагом: число сегментов не зависит от масштаба модели.
661. **Resolution-independent hatch/разрез** — штриховка сечений и размерные линии генерируются в экранном пространстве из аналитических кривых сечения; пиксельная точность при экспорте в векторный PDF/SVG тем же конвейером.
662. **Screen-space adaptive tessellation** — допуск тесселяции пересчитывается из пиксельной ошибки через проекцию bounding sphere патча на экран; гистерезис ±20% против мерцания LOD при плавном зуме.
663. **Derivative-based normal quality** — нормали из аналитических производных патча, а не из треугольников; блики без «полосатости» на малых LOD, что визуально скрывает грубую тесселяцию.
664. **Снаппинг-иерархия в скетче** — приоритеты: точка на кривой > конец/середина > касание > сетка; кандидаты из BVH по радиусу курсора, выбор по взвешенному скору «тип × расстояние», hysteresis против дрожания между кандидатами.
665. **Геометрический снаппинг на аналитике** — середины дуг, центры окружностей и точки касания вычисляются из рационального представления кривой, а не из тесселяции: точность снапа не деградирует с LOD.
666. **Реалтайм constraint solving** — инкрементальный Левенберг–Марквардт: при перетаскивании пересчитываются только ограничения, связанные с движимым примитивом (подграф зависимостей), тёплый старт от прошлого решения — цикл солвера < 2 мс.
667. **Dirty-регионы графа ограничений** — бипартитный граф «примитив–ограничение»; drag помечает затронутые узлы, якобиан собирается только по активному подграфу; полный резолв только при структурном изменении.
668. **Rubber-band preview** — предпросмотр кривой/дуги/прямоугольника от первой зафиксированной точки к курсору рендерится оверлейным слоем с предсказанием ограничений (горизонталь, касание) до клика — снижает число отмен на порядок.
669. **Constraint inference во время drag** — вертикальность/горизонтальность/равенство длин угадываются из текущего положения с визуальными глифами; принятие — по удержанию в зоне снапа, отказ — по выходу, без модальных диалогов.
670. **Размерные ограничения как интерактив** — параметрический размер редактируется двойным кликом, новое значение мгновенно резолвится солвером; переопределение подсвечивается красным до коммита, не после.
671. **Солвер под мышью (live drag)** — при перетаскивании свободной точки солвер итеративно удовлетворяет остальные ограничения на каждый mouse-move (бюджет 4 итерации), отдавая остаточную невязку в HUD — пользователь чувствует «жёсткость» модели.
672. **CRDT для совместного редактирования модели** — параметры фич как LWW-регистры с HLC-метками, дерево фич как RGA с tombstone-удалением; синхронизируется параметрический исходник (килобайты), не тесселяция — геометрия перестраивается локально из конвергированного состояния.
673. **Undo в CRDT-среде** — глобальный undo невозможен без координации; реализуйте локальный undo через инверсию собственных операций (compensating ops), не откатывая чужие правки — иначе race с репликами.
674. **Awareness/присутствие** — курсоры, выделения и viewport'ы участников — ephemeral-сообщения вне CRDT-лога (не персистятся); отдельный канал, чтобы не раздувать журнал синхронизации.
675. **Offline-first персистентность в IndexedDB** — снапшот CRDT-состояния + append-only журнал операций в IndexedDB (crate idb/rexie через wasm-bindgen); при открытии — загрузка снапшота, догон журналом, фоновая компактификация.
676. **Инкрементальные WASM-снапшоты** — B-rep и feature-дерево сериализуются дельтами по версиям узлов; полный снапшот раз в N операций, между ними — только изменённые подграфы, иначе запись в IndexedDB станет узким местом.
677. **Конфликт-free перестройка геометрии** — после применения удалённых операций пересчёт по DAG dirty-флагам затрагивает только изменённые ветки; удалённая правка дальнего узла не перетесселирует всю модель.
678. **Sync-протокол с дельта-сжатием** — обмен по WebSocket/WebRTC: векторные часы для anti-entropy, дельты операций в zstd; офлайн-периоды сливаются одним compaction-пакетом при переподключении.
679. **PWA-оболочка вьюера** — service worker кэширует WASM-ядро, шейдеры и шрифты (версионированные URL по хэшу сборки); приложение полностью работает офлайн, обновление — атомарной сменой cache group.
680. **Сохранение по FSA API** — File System Access API для «родного» Save/Save As .step/.scad в офлайне; fallback на download-блоб в браузерах без поддержки, единый интерфейс DocumentStore.
681. **Фоновая тесселяция в worker-пуле под PWA** — очередь тесселяции живёт в Web Worker'ах с SharedArrayBuffer (COOP/COEP-заголовки в service worker); main thread никогда не блокируется геометрией — критично для воспринимаемой отзывчивости.
682. **Semver для геометрического ядра** — численное поведение — часть API: minor-версия может менять результаты только в пределах задокументированных допусков, любая смена допусков/порядка операций — breaking; golden-модели фиксируют «численный контракт» версии.
683. **Численный контракт в тестах** — для каждого публичного алгоритма зафиксированы эталонные выходы с допусками; PR, меняющий выход за пределами допуска, требует явного bump'а и записи в CHANGELOG — автоматическая проверка в CI.
684. **Фазз-корпус как артефакт релиза** — минимизированный корпус (cargo fuzz cmin) коммитится в репозиторий, регрессия по корпусу — обязательный CI-шаг; новые краши пополняют корпус с seed-ссылкой на CI-ран.
685. **Structured fuzzing геометрии** — генерация поливалидных B-rep'ов и узловых векторов через arbitrary-генераторы с инвариантами (m = n+p+1, w>0), а не сырые байты: фаззер исследует глубокие состояния булевых и SSI, а не отшивается парсером.
686. **Differential testing против OCCT** — харнесс гоняет одинаковые сценарии (импорт STEP → булевы → массовые свойства) через своё ядро и OpenCASCADE (pythonOCC/нативный бинарь), сравнивая объём/площадь/Hausdorff с допуском; расхождения классифицируются: баг, известное отличие, флаки.
687. **Дифференциальная матрица референсов** — ротируемые референсы (OCCT, geomdl, curvo) с per-case допусками; никогда не фиксируйте своё ядро единственным эталоном — зацикливание ошибок на самих себя.
688. **Perf-регрессии в CI** — criterion-бенчи на фиксированном runner'е, результаты в исторический store (bencher/codspeed), PR блокируется при деградации >5% на горячих путях (evaluate, тесселяция, булевы) с автоматическим flamegraph-диффом.
689. **WASM-перф отдельно от натива** — тайминги wasm32 (headless chrome/firefox в CI) отличаются от натива в разы на SIMD/атомиках; отдельный perf-набор под браузер, порог регрессии свой.
690. **Канареечный численный стек** — ночной прогон полного тест-сьюита с -C target-feature и разными уровнями оптимизации ловит fast-math/UB-зависимые расхождения до релиза; расхождение между O0/O3 — автоматический blocker.
691. **Релизные ворота ядра** — gate-чеклист: зелёный фазз-корпус, дифф против OCCT без новых расхождений, perf-delta в пределах бюджета, golden-модели без смены допусков; релиз-тег создаётся только CI-ботом после всех ворот.
692. **SBOM и reproducible WASM в релизе** — артефакт релиза содержит Cargo.lock, sbom (cyclonedx) и sha256 WASM-модуля; CI пересобирает релизный коммит и сверяет бит-идентичность до публикации.
693. **Канонический golden-набор моделей** — курируемая библиотека .scad/.step-моделей (примитивы, филлеты, тримминг, сборки) в Git LFS с зафиксированными массовыми свойствами; любой PR ядра обязан пройти весь набор — это единое определение «ничего не сломал».
694. **Стадии rollout численных изменений** — изменение алгоритма (новый SSI, новый триммер) вводится за feature-флагом, golden-дифф собирается при выключенном и включённом флаге; удаление флага — отдельный PR после стабилизации.
695. **Телеметрия падений ядра в PWA** — opt-in сбор структурированных ошибок (код ошибки ядра, сигнатура модели по хэшу, без геометрии) в локальную очередь IndexedDB с отправкой при онлайне; приоритизация багов по реальной частоте, а не по жалобам.
696. **Политика MSRV и toolchain** — минимальная версия Rust фиксируется в rust-toolchain.toml и проверяется CI-матрицей (msrv/stable/beta); WASM-таргет пинится отдельно, поскольку simd128/threads-фичи меняют кодогенерацию.
697. **Классификация багов ядра по последствиям** — taxonomy: crash / wrong-topology / wrong-geometry-within-tol / perf; wrong-topology — максимальный приоритет и обязательный regression-тест до мержа фикса, так как тихая порча B-rep хуже падения.
698. **Bisect-автоматизация регрессий** — git bisect run с golden-скриптом (сборка + прогон упавшей модели) для численных регрессий; flaky-тесты помечаются quarantine-меткой и не блокируют main, но имеют SLA на расследование.
699. **Кросс-платформенная численная идентичность** — тест сравнения выходов ядра на x86_64/aarch64/wasm32 с допуском 0 (детерминированный порядок редукций) или задокументированным отклонением; недетерминизм между платформами ломает CRDT-конвергенцию тесселяционных кэшей и golden-тесты.
700. **Публичный changelog численного поведения** — CHANGELOG разделён на API-изменения и численные изменения (новые допуски, смена алгоритмов, исправленные расхождения с референсами); потребители ядра (вьюер, PWA, CLI) подписываются на численную секцию как на контракт.

## Часть X. Обратный инжиниринг и гибридные представления (701–770)

701. **PCA-оценка нормалей (Hoppe)** — ковариация k ближайших соседей, нормаль = собственный вектор наименьшего собственного значения; размер окрестности по локальной плотности, иначе сглаживаются рёбра ещё до сегментации.
702. **Консистентная ориентация нормалей** — распространение знака по графу касательных плоскостей (MST по весу 1−|nᵢ·nⱼ|, Хоппе); без неё регионы «инвертируются» и фиттинг получает вывернутые данные.
703. **MLS-проекция Левина** — локальная полиномиальная аппроксимация касательной плоскости с гауссовыми весами h(p) по плотности; выносит шум и выбросы до оценки кривизны, уменьшая ложные сегменты.
704. **Кривизна на мешах (Таубин / Русинкевич)** — тензорная оценка из перепада нормалей или per-triangle квадратичный фит с накоплением по вершинам; вход для region growing и детекции рёбер.
705. **Крест-линии (ridges/ravines, Отаке–Беляев)** — экстремумы главных кривизн вдоль главных направлений; надёжнее диэдрального угла на зашумлённых сканах и дают прямые границы для тримминга.
706. **Region growing с очередью по остатку** — посев в точке минимальной кривизны, рост по минимальной ошибке текущего прокси; порядок обработки меняет качество сегментации сильнее, чем порог.
707. **Вариационная сегментация (VSA, Коэн-Стейнер)** — итеративная кластеризация треугольников к L².¹-оптимальным плоским прокси; даёт патч-подобное разбиение, готовое под четырёхстороннюю структуру.
708. **Иерархическая сегментация по стоимости слияния** — bottom-up merge регионов с минимальным приростом ошибки фиттинга; позволяет пользователю выбрать гранулярность без перезапуска алгоритма.
709. **Алгебраическая дистанция Таубина** — фиттинг неявных поверхностей первым приближением истинного расстояния; стабильнее простого least squares на частичных данных.
710. **Фиттинг сферы Пратта** — алгебраический circle/sphere fit без смещения радиуса, в отличие от naive LSQ; база для распознавания сферических филлетов.
711. **Faithful-фиттинг квадрик (Лукач)** — цилиндр и конус по приближённой геометрической дистанции; точнее произвольного RANSAC-проголосованного примитива после его локализации.
712. **Efficient RANSAC (Шнабель)** — выборка минимальных наборов с локальным подтверждением для плоскостей, сфер, цилиндров, конусов и торов на облаках в миллионы точек; стандарт детекции примитивов.
713. **Распознавание тора** — оценка оси по моментам, затем нелинейное уточнение (R, r) Левенбергом–Марквардтом; тор часто ошибочно принимается за цилиндр при малых дугах покрытия.
714. **Классификация региона по (K, H)-сигнатуре** — плоскость (0,0), цилиндр (K=0), сфера (K=H²), тор/конус — по связи H²/K; быстрая предклассификация перед дорогим нелинейным фитом.
715. **Робастные оценки (Huber, Tukey)** — M-оценки вместо чистого МНК при фиттинге примитивов: выбросы сканера и зарегистрированные неудачно сканы не сдвигают параметры.
716. **Границы регионов: crust / alpha shapes (Амента)** — восстановление замкнутых петель на краях сегментов; из них строятся 3D кривые-швы будущего B-rep.
717. **Трассировка и сглаживание границ сегментов** — упорядоченный обход по мешу → B-сплайн-фиттинг в допуск с G¹-стыками на вершинах; «рваные» границы региона — главный источник зазоров в реконструкции.
718. **Конформная параметризация региона (LSCM/ABF++)** — развёртка неплоского региона в 2D-домен с минимальными угловыми искажениями; основа фиттинга поверхности к непрямоугольному сегменту.
719. **Крест-поля и квад-разметка (Bommes, mixed-integer)** — 4-направленное поле по главным кривизнам, целочисленная параметризация даёт четырёхсторонний layout; из него напрямую рождается патч-комплекс.
720. **Извлечение патч-структуры из quad-разметки** — каждая квад-ячейка верхнего уровня = один NURBS-патч; T-стыки layout либо согласуются узлами, либо закрываются Gregory-заплаткой.
721. **Реконструкция по сечениям (slices → skinning)** — облако режется на параллельные слои, контуры слоёв фитятся кривыми и собираются скиннингом; классический конвейер для сканов турбинных лопаток.
722. **Прогрессивная итеративная аппроксимация (PIA/LSPIA)** — фиттинг больших облаков без решения СЛАУ: коррекция контрольных точек по векторам отклонения сходится геометрически; масштабируется на миллионы точек.
723. **Размещение узлов по ошибке спана** — начальный вектор узлов из квантилей параметров, затем вставка узлов там, где отклонение выше допуска; лучше равномерного распределения в зонах высокой кривизны.
724. **Фиттинг «границы сначала»** — сначала фитятся четыре граничные кривые патча и фиксируются, затем внутренность — через поверхность Кунса с вариацией внутренних точек; гарантирует G⁰ на швах комплекса.
725. **Фиттинг с ограничениями формы** — линейные неравенства на контрольные точки (выпуклость, монотонность толщины, запрет перегибов) решаются QP поверх МНК; нужен для аэродинамических и судостроительных поверхностей.
726. **Минимизация числа узлов в допуске** — жадное удаление узлов с проверкой отклонения (A5.8) после достижения точности; компактные патчи дешевле хранить, тесселировать и передавать в STEP.
727. **Билатеральная фильтрация облака** — сдвиг точки вдоль нормали с весом по расстоянию и по разности нормалей; шум снимается без размытия острых рёбер, в отличие от гауссовой фильтрации.
728. **Point-to-plane ICP** — выравнивание скана на референс-модель минимизацией расстояния до касательной плоскости; сходится квадратично против линейной point-to-point и стабильнее при частичном перекрытии.
729. **Детекция плоскостей симметрии** — зеркальная копия облака выравнивается на исходное ICP-подобной минимализацией; найденная плоскость задаёт семантику модели и половинит объём фиттинга.
730. **Детекция осей вращения** — голосование по парам точек с согласованными нормалями либо фиттинг поверхности вращения к региону; найденная ось позволяет заменить свободный фит точным revolve.
731. **Детекция повторов (pattern/instance mining)** — кластеризация локальных дескрипторов геометрии + голосование за трансформации (geometric hashing); один экземпляр фитится один раз, остальные — инстансы с матрицами.
732. **Достройка по симметрии** — недосканированные области восстанавливаются зеркальным/вращательным переносом данных; веса таких точек в фиттинге снижаются, чтобы не маскировать реальные дефекты.
733. **T-сплайны: T-точки и правила вывода базиса** — базисная функция определяется локальным вектором узлов, собранным лучевым поиском вдоль рядов сетки; именно лучевой поиск, а не глобальный вектор узлов, — главное отличие реализации.
734. **Analysis-suitable T-splines (ASTS)** — ограничения: вложенность при уточнении и непересечение продолжений T-стыков противоположной направленности; только для ASTS доказаны линейная независимость базиса и конвертируемость.
735. **Безье-экстракция T-сплайнов** — локальные операторы C^e отображают T-сплайн-узлы на канонические Безье-элементы; единый механизм и для IGA, и для экспорта в тензорные патчи.
736. **Рациональные T-сплайны (weights)** — веса на контрольных точках T-сетки сохраняют способность точно представлять коники и цилиндры; при конвертации в NURBS веса растаскиваются по тем же вставкам узлов.
737. **Аудит конверсии T→NURBS** — после разбиения по T-расширениям измеряйте хаусдорфово отклонение и G¹-скачки на новых швах; конверсия геометрически точна, но параметрические рассогласования ломают downstream-операции.
738. **Экстраординарные точки внутри T-сплайнов** — вокруг вершин валентности ≠4 локально применяется подразделение; храните флаг экстраординарности, чтобы экспортер решал: точный вывод невозможен, нужна аппроксимация.
739. **Лимитная позиция и нормаль Catmull–Clark (Халстед)** — предельная точка и касательная плоскость вершины выражаются взвешенной комбинацией соседей; нужны для G¹-стыковки конвертированных NURBS-патчей с окружением.
740. **Точная оценка Стэма** — собственное разложение матрицы подразделения даёт S(u,v) в любой точке окрестности экстраординарной вершины без итераций; позволяет тесселировать и фитить лимитную поверхность с контролируемой точностью.
741. **Характеристическое отображение** — проверка инъективности и регулярности схемы подразделения через control mesh характеристического отображения; гарантия, что лимитная поверхность не самопересекается локально.
742. **Регулярные квады Catmull–Clark → бикубические патчи** — квад без экстраординарных вершин тождественен bicubic B-сплайну: конверсия точная, без сэмплирования; выделяйте такие области в первую очередь.
743. **Loop → треугольные патчи** — регулярная треугольная ячейка Loop-схемы есть треугольный полиномиальный патч степени 4; конвертируется в треугольный Безье, а далее в вырожденный четырёхсторонний NURBS.
744. **Doo-Sabin → биквадратические NURBS** — схема сглаживания даёт лимитные bi-2 патчи вокруг четырёхсторонних граней; дешёвая альтернатива Catmull–Clark, когда достаточна C¹.
745. **Допуск-ориентированная конверсия subdivision → NURBS** — адаптивное сэмплирование лимитной поверхности (Стэм) + глобальный фиттинг с сертификатом отклонения; применяется там, где точная конверсия невозможна из-за экстраординарных вершин.
746. **Грегори-патч: рациональные внутренние точки** — две внутренние контрольные точки на угол вычисляются как рациональные функции (u,v), что развязывает несовместимые твисты; реализация должна хранить «запёкшуюся» NURBS-форму для экспорта.
747. **Совместимость твистов в вершине** — у четырёх патчей в общей вершине смешанные производные должны согласовываться; вершинная несовместимость — главная причина отказа G¹-заполнения, диагностируйте её до выбора Gregory.
748. **S-патчи (Луп–ДеРоуз)** — обобщение Безье на n-сторонние домены через симплексные координаты; точное представление без рациональных трюков Грегори ценой высокой степени.
749. **Энергетическое заполнение n-сторонних дыр** — внутренние контрольные точки минимизируют тонкопластинную энергию при фиксированных G¹-условиях на границе; даёт «честную» заплатку без артефактов веера.
750. **Вырожденные четырёхсторонние патчи** — треугольная область как стянутая сторона NURBS-патча (ряд совпадающих контрольных точек); STEP это стандарт, но все оценщики должны переживать нулевую длину ряда.
751. **C¹-условия на полюсе (Прауч)** — гладкость в вырожденной точке требует компланарности первого ряда контрольных точек касательной плоскости; проверяйте и принудительно выравнивайте ряд при реконструкции полюсных патчей.
752. **Предельные нормали и кривизна на полюсе** — производные вырождены, но направленные пределы существуют; считайте нормаль по пределу из невырожденных колец, иначе освещение и офсеты разваливаются у полюса.
753. **Детекция сингулярностей при импорте** — сканер модели ищет свёрнутые края (|Sᵤ×Sᵥ| < ε на краю), стянутые ряды и кратности, дающие разрывы; сингулярные конфигурации маркируются и обходятся особыми путями кода.
754. **Репараметризация для удаления вырождения** — разрез патча по изокривой через сингулярную точку или перенос полюса изменением вектора узлов; часто дешевле, чем пожизненная поддержка вырожденного случая во всех алгоритмах.
755. **G¹-стыковка: условия на поперечные производные** — S₁(1,v) и S₂(0,v) связаны через α(v)·∂ᵤS₁ + β(v)·∂ᵤS₂ + γ(v)·∂ᵥS = 0 с полиномиальными α, β, γ; выбор степеней этих функций определяет, решаема ли стыковка.
756. **Мёбиус-репараметризация швов** — при несовпадении параметризаций соседних патчей общий шов репараметризуется рациональной линейной функцией; без этого G¹-условия формулируются в несопоставимых параметрах.
757. **Проблема вершинного окружения (vertex enclosure)** — вокруг вершины валентности n G¹-условия смежных швов образуют замкнутую систему; при чётной/нечётной валентности размерности решений различаются — планируйте заплатки с учётом валентности.
758. **Согласование узлов и степеней на шве** — перед G¹/G²-сшивкой оба патча приводятся к общему вектору узлов и степени вдоль шва (вставка узлов, повышение степени); иначе стыковка существует только точечно.
759. **G² через границу** — дополнительно согласуются вторые поперечные производные; условия накладываются на два ряда контрольных точек и конфликтуют с соседними швами — решайте глобально, а не по одному шву.
760. **Согласование главных кривизн на шве** — G¹ не гарантирует совпадения k₁, k₂; для класса А требуйте равенства кривизн и совпадения главных направлений, проверяемого гребёнками через границу.
761. **Линии кривизны через многопатчевый комплекс** — интегрирование поля главных направлений Рунге–Куттой с переключением патча на шве (сохранение дугового параметра); основа для патч-разметки и квад-ремешинга.
762. **Умбилики и их классификация** — точки k₁=k₂ (star/lemon/monstar по Портесу) — источники разрывов поля направлений; алгоритмы трассировки линий кривизны должны детектировать и обходить их.
763. **Геодезические через швы** — геодезическая кривизна сохраняется при пересечении границы патчей (аналог Снелла для касательных); нужно для раскроя, путей инструмента и измерения расстояний на комплексе.
764. **Метрики качества многопатчевой поверхности** — отражательные линии, зебра и изофоты через швы визуализируют G¹/G²-дефекты раньше любых чисел; встраивайте их в отладку стыковки.
765. **Консистентная ориентация комплекса** — обход графа патчей с пропагацией знака (u,v)-ориентации; несогласованная ориентация ломает нормали, булевы и экспорт в B-rep.
766. **Аудит зазоров и нахлёстов швов** — измерение максимального расстояния между образами общего ребра из двух соседних патчей; отчёт по допуску сшивки до попытки sewing в B-rep.
767. **Сшивка рёбер с разной степенью** — повышение степени и вставка узлов доводят обе стороны шва до идентичного B-сплайна, после чего контрольные точки усредняются или фиксируются с допуском; стандартный этап healing.
768. **Треугольные Безье-патчи** — барицентрические координаты и де Кастельжо на треугольном домене; естественное представление для трёхсторонних областей и результатов конверсии Loop.
769. **Треугольный патч → NURBS** — треугольный Безье степени n переводится в вырожденный четырёхсторонний патч со стянутой стороной; конверсия точная, но наследует все проблемы вырожденных конфигураций.
770. **Глобальная G¹-оптимизация комплекса** — после построения всех патчей контрольные точки варьируются совместно под минимизацию энергии изгиба с линейными G¹-ограничениями; убирает накопленные локальные несогласованности реконструкции.

## Часть XI. CAM и метрология (771–840)

771. **Z-level черновая обработка** — сечения заготовки и детали горизонтальными плоскостями с шагом Δz, из каждого сечения строится 2D-область резания (stock ∩ ¬part) с офсетом на радиус фрезы; ядро должно предоставлять робастные сечения B-rep плоскостью и 2D-булевы в плоскости сечения — это тот же код, что и для слоёв 3D-печати.
772. **Adaptive clearing (трохоидальная обработка)** — черновой проход с постоянным углом врезания φ_max: траектория — спирали/трохоиды внутри офсетной области, радиальное врезание a_e ограничено условием φ = 2·arccos(1 − a_e/R) ≤ φ_max; требуется 2D-офсет с самопересечениями и медиальная ось областей резания.
773. **Трохоидальная коррекция шага** — на криволинейных участках эффективный угол врезания растёт на внутренней стороне; коррекция шага по формуле s_corr = s·R_path/(R_path ± R_cutter) требует кривизны траектории в каждой точке — ядро выдаёт κ(t) вдоль CL-кривой аналитически.
774. **Rest machining (дорезка остатка)** — остаточный материал = stock_new − (stock_old ⊖ swept(фреза_big)); сравнение модели заготовки с аналитическим swept-объёмом крупной фрезы выделяет зоны под малый инструмент, экономя 30–50% машинного времени.
775. **Constant scallop чистовая обработка** — шаг между проходами вычисляется из условия равной высоты гребешка h на произвольной поверхности: соседняя траектория = офсет по поверхности, найденный решением уравнения scallop(S(u,v), S(u',v'), R) = h с учётом обеих главных кривизн; требуется surface-surface offset marching, а не фиксированный шаг в параметрах.
776. **Scallop высота с учётом кривизны поверхности** — для выпуклой поверхности (радиус ρ) с шаровой фрезой R: h ≈ s²(1/ρ + 1/R)/8, для вогнутой — h ≈ s²(1/ρ − 1/R)/8; ядро должно вычислять главные кривизны вдоль контактной кривой и адаптировать шаг построчно.
777. **Pencil milling (обводка карандашом)** — чистовой проход вдоль линий пересечения двух поверхностей (внутренние углы): контактная кривая = fillet-like след центра фрезы, найденный как SSI поверхностей с двойным офсетом на R; используется после z-level для зачистки внутренних галтелей.
778. **Steep/shallow разделение зон** — классификация поверхности по углу нормали к оси Z: крутые зоны (>θ) обрабатываются z-level, пологие — scallop-проходами; ядро строит поле угла нормали и границы изолиний n·k = cos θ — та же изокривойная инфраструктура, что и для уклонов форм.
779. **Выбор инструмента по кривизне (зарезание)** — условие отсутствия зарезания: R_фрезы ≤ 1/|κ_min| для вогнутых зон, где κ_min — минимальная главная кривизна по всей поверхности; ядро выдаёт карту кривизны по патчам, CAM дихотомией выбирает максимально жёсткую (короткую, толстую) фрезу без зарезания.
780. **Торовая фреза как swept-генератор** — эффективный радиус торовой фрезы зависит от направления подачи и угла наклона: R_eff = (R − r) + r/sin α для контакта на угле α; проверка зарезания для тора требует вычисления контактной точки между тором и NURBS-поверхностью — задача отталкивания двух поверхностей.
781. **Модель инструмента в ядре** — фреза = параметрическое тело вращения (плоская: цилиндр+плоскость; шаровая: цилиндр+сфера; торовая: цилиндр+тор+плоскость) с ISO 13399-атрибутами (D, R, L, число зубьев); единый enum CutterGeometry в ядре, чтобы collision и scallop-расчёты не дублировали геометрию.
782. **CL-файл (Cutter Location) как поток событий** — CL-запись = (x,y,z, i,j,k, feed, tool) с таймстампом; ядро валидирует CL потоково: каждая точка проверяется на gouging (расстояние поверхности до оси инструмента), что требует поточного point-to-surface distance без построения полной траектории.
783. **APT/CL-грамматика** — парсер классических APT-операторов (GOTO, CIRCLE, TLON/TLOFT, INTOL/OUTTOL) поверх существующего gcode-core; ядро трактует INTOL/OUTTOL как допуски хорды внутрь/наружу от поверхности и маппит их на параметры адаптивной дискретизации.
784. **Постпроцессор: компенсация радиуса G41/G42** — для 2.5D-контуров коррекция на радиус фрезы: углы обходятся дугой (roll-around) или удлинением (intersection); ядро вычисляет 2D-офсет контура с классификацией углов (острый/тупой) — та же математика, что для офсета штамповых кромок.
785. **Циклы сверления G81–G83 как фичи** — canned cycles маппятся на hole-фичи модели: постпроцессор распознаёт набор отверстий с одинаковыми параметрами (диаметр, глубина) и сворачивает их в один цикл; требуется кластеризация цилиндрических граней по радиусу и оси — переиспользование pattern-detection из фич.
786. **5-осевое позиционирование: lead и tilt** — угол lead (по направлению подачи) 3–15° уводит контакт с центра шаровой фрезы (нулевая скорость резания в полюсе), tilt страхует от зарезания боковой поверхностью; ядро выдаёт коврик (point, normal, tangent) вдоль траектории, CAM вычисляет углы из локального каркаса Френе.
787. **Singularity avoidance при RTCP** — вблизи вырожденных положений поворотных осей (C→∞ скорость при A≈0) требуется обход: сглаживание ориентации кватернионным SLERP с ограничением угловой скорости осей; ядро предоставляет непрерывную репараметризацию ориентационной кривой на сфере S³.
788. **Кинематика станка в ядре** — цепочка поворотных осей (table-table, head-head, head-table) как параметризованная SE(3)-композиция; постпроцессор решает обратную кинематику из CL в координаты осей, ядро валидирует прямой подстановкой — единый код direct/inverse kinematics.
789. **Огибающая угловых скоростей осей** — для каждого CL-сегмента считаются ω_A(t), ω_C(t) через Якобиан кинематики; подача ограничивается условием max(ω)/ω_max оси — требуется дифференцирование кинематической цепочки вдоль траектории.
790. **Chordal deviation для подачи** — линейная интерполяция G1 внутри криволинейного участка даёт отклонение хорды δ = R(1−cos(Δθ/2)); шаг дискретизации выбирается из δ ≤ tol и пересчитывается на время кадра интерполятора станка (1–4 мс).
791. **Jerk-limited планирование подачи** — скорость на криволинейном участке ограничена центростремительным ускорением v ≤ √(a_n·R) и рывком v ≤ ∛(j·R²); ядро выдаёт κ(t) и dκ/dt вдоль траектории, планировщик строит S-профиль скорости с оглядкой (look-ahead) на N кадров.
792. **Look-ahead по кривизне траектории** — окно предпросмотра сканирует CL вперёд, торможение планируется до точек локального максимума κ; требуется поточная оценка кривизны составной траектории с сшивкой G1-стыков сегментов.
793. **Анализ доступности инструмента (accessibility)** — точка поверхности доступна ориентацией (i,j,k), если отрезок от точки контакта до конца фрезы и державки не пересекает деталь/приспособление; ядро предоставляет batch ray-cast «отрезок vs B-rep» для тысяч направлений на точку.
794. **Visibility map по Гауссовой сфере** — для каждой поверхности строится карта видимости: направления нормалей, из которых поверхность видна без окклюзии; рендерится GPU z-buffer'ом с 6 кубических направлений с ортопроекцией — классический ambient occlusion конвейер, переиспользуемый для CAM.
795. **GPU z-buffer проверка державки** — силуэт державки (конус+цилиндры) рендерится в depth-buffer из точки контакта вдоль оси инструмента; коллизия = сравнение глубины фрагментов детали с дальней плоскостью державки — O(пиксели) вместо O(треугольники) на CPU.
796. **Минимальная длина вылета фрезы** — для каждой зоны ищется минимальный вылет L, при котором державка не коллидирует: бинарный поиск по L с ray-cast проверкой на каждом шаге; меньший вылет → меньше вибрации, допустимая подача растёт как (L₀/L)³.
797. **Базирование 3-2-1** — шесть точечных контактов: 3 на первичной плоскости (гасят Z, Rx, Ry), 2 на вторичной (X, Rz), 1 на третичной (Y); ядро выбирает датум-поверхности по площади и плоскостности и раскладывает контакты максимально разнесённо для устойчивости.
798. **Анализ устойчивости базирования** — при силах резания F схема проверяется на опрокидывание: моменты относительно каждого ребра треугольника контактов; ядро вычисляет выпуклую оболочку контактных точек и положение проекции равнодействующей.
799. **Проверка прижимов на коллизии** — траектория инструмента проверяется против тел прижимов и губок: swept-объём фрезы vs fixture boolean, красные зоны возвращаются CAM для смещения прижимов или перестановки — тот же collision-запрос, что и для державки.
800. **CMM: планирование точек по GD&T** — количество и раскладка точек измерения определяются типом допуска: плоскостность — сетка ≥ 4×4, позиционный допуск отверстия — 8 точек на окружности в 2 сечениях; ядро генерирует точки + нормали на грани из привязанного GD&T-фрейма (PMI).
801. **CMM: стратегия обхода препятствий** — путь щупа между точками измерения строится как shortest path с отступом 2–5 мм от модели: retract-move-approach; требуется быстрый signed-distance запрос для планирования траектории щупа.
802. **Компенсация радиуса щупа** — измеренная точка смещается от поверхности на радиус рубина вдоль направления подхода; коррекция требует точной нормали поверхности в точке контакта — point inversion + normal из ядра, а не аппроксимация по соседям.
803. **On-machine probing циклы** — измерительные циклы (Renishaw-style: касание, отскок, повтор) генерируются как G-код с переменными #500+; ядро планирует probing-точки на припуске и сравнивает измеренное с номиналом для коррекции привязки G54 до чистовой обработки.
804. **Обновление привязки по probing** — измеренное положение заготовки (3+ точек) транслируется в сдвиг/поворот рабочей системы координат: решение задачи Wahba/least-squares rigid fit по парам «номинал–измерение».
805. **Анализ размерных цепочек: worst case** — замыкающий размер T₀ = Σ|T_i| арифметически; ядро строит граф размерной цепочки от датумов модели (PMI-аннотации) и перебирает конфигурации знаков для максимума/минимума.
806. **RSS анализ допусков** — статистическая цепочка: T₀ = √(ΣT_i²) при нормальном распределении звеньев; даёт реалистичный бюджет допусков против пессимистичного worst case, оба режима — из одного графа цепочки.
807. **Монте-Карло размерных цепочек** — каждое звено сэмплируется по своему распределению (нормальное/равномерное/сдвинутое, Cp<1), 10⁵–10⁶ итераций дают гистограмму замыкающего размера и долю брака; в Rust — batch SIMD генерация, детерминированный seed для воспроизводимости.
808. **Чувствительность допусков (contribution)** — вклад звена i в дисперсию замыкающего: (∂T₀/∂T_i)²·σ_i²/σ₀²; ранжирование звеньев показывает, какие допуски ужесточать/ослаблять — вычисляется аналитически из Якобиана цепочки.
809. **SPC по измеренным точкам** — контрольные карты X̄-R по партиям измерений: UCL/LCL = X̄ ± 3σ/√n; ядро хранит историю измерений фичи и вычисляет Cp = (USL−LSL)/6σ, Cpk = min(CPU, CPL) с тренд-анализом.
810. **Статистическая оценка формы поверхности** — по облаку измеренных точек патча оценивается систематическая ошибка (среднее поле отклонений) и случайная (дисперсия); поле отклонений как scalar field поверх NURBS-патча — прямое использование surface evaluation для визуализации heatmap.
811. **ICP best-fit измеренного к CAD** — итеративное выравнивание облака точек на модель: проекция каждой точки на поверхность (point inversion), затем least-squares rigid transform по парам; сходимость ускоряется k-d деревом на контрольной сетке и тёплым стартом от датум-схемы.
812. **Best-fit с датумами (constrained alignment)** — выравнивание с фиксированными степенями свободы: датум A гасит 3 DOF, B — 2, C — 1; оптимизация только по оставшимся DOF (проекция градиента на допустимое подпространство SE(3)) — иначе best-fit «съезжает» с функциональных баз.
813. **Взвешенный ICP по приоритету датумов** — точкам на датум-поверхностях назначается больший вес w_A > w_B > w_C, свободные поверхности — минимальный; ядро передаёт карту весов из PMI-разметки в солвер выравнивания.
814. **Отчёт отклонений: цветовая карта** — после выравнивания каждой точке ставится signed distance до CAD-поверхности; вьюер рендерит поверхность, раскрашенную по полю отклонений (зелёный/красный за допуском) — тот же scalar-field шейдер, что и для кривизны.
815. **GD&T: оценка позиционного отклонения** — фактическая ось отверстия из измеренных точек (least-squares cylinder fit); позиционное отклонение = 2×расстояние от оси до идеальной позиции, сравнение с зоной Øt с учётом MMC-бонуса (Øt + (D_max − D_actual)).
816. **MMC/LMC бонус-расчёт** — бонус к допуску позиции растёт по мере отхода размера от MMC: bonus = |D_actual − D_MMC|; ядро связывает измеренный размер фичи с её позиционной зоной, что требует единой модели GD&T-данных (размер + позиция на одной фиче).
817. **Траектория фрезы как offset tube для верификации** — проверка программы = boolean stock − swept(фреза вдоль траектории) vs CAD-деталь: undercut (красный) / overcut (синий); swept трубки вдоль NURBS-траектории с переменной ориентацией оси — прямое применение swept volume из п. 610 с профилем инструмента.
818. **Верификация G-кода симуляцией удаления материала** — dexel/voxel-модель заготовки: каждый G1-проход вычитает dexel-пересечения инструмента; ядро экспортирует фрезу и траекторию в dexel-движок и сравнивает результат с B-rep деталей по Hausdorff-расстоянию.
819. **Обнаружение gouging в CL** — для каждой CL-точки: расстояние от сегмента инструмента до всех граней в окрестности (BVH-запрос) должно быть ≥ 0; отрицательное проникновение = gouge, точка и глубина возвращаются в отчёт с подсветкой во вьюере.
820. **Припуск на обработку (stock allowance) как офсет** — чистовые траектории строятся от поверхности, офсетной на припуск 0.1–0.5 мм; неравномерный припуск (больше на шлифуемых гранях) = переменный офсет по scalar-полю — та же инфраструктура variable offset.
821. **Trochoid corner loop для острых углов** — в острых внутренних углах контура скорость падает до нуля без петли; вставка trochoid-петли радиусом r = R_cutter + ε поддерживает подачу; ядро детектирует углы контура < 90° и вставляет петли с проверкой самопересечения.
822. **Helical ramp-in врезание** — заход в материал по винтовой траектории с углом ≤ 3°: радиус спирали ограничен внутренним радиусом фрезы (центр не режет для плоской фрезы); ядро строит винтовую кривую внутри офсетной зоны с проверкой доступности.
823. **Контроль толщины стружки (feed-per-tooth)** — fz = v_f/(n·z); на трохоиде эффективная fz растёт на прямых и падает на поворотах, коррекция подачи v_f(t) = fz_target·n·z·(1 ± κ·R_cutter) требует кривизны траектории в реальном времени из CL-потока.
824. **Стратегия climb vs conventional** — выбор попутного/встречного фрезерования по направлению обхода контура (CW/CCW) относительно вращения шпинделя; ядро классифицирует ориентацию каждого 2D-контура и маркирует проходы, чтобы CAM чередовал направление обхода для тонких стенок.
825. **Обработка тонких стенок: симметричные проходы** — стенка толщиной t обрабатывается попеременно с двух сторон с шагом по z, остаточная толщина ≥ 2t/3 на каждом проходе против изгиба; ядро выдаёт medial surface стенки и поле толщины для планирования z-шагов.
826. **Дефлекция инструмента (tool deflection)** — концевая фреза изгибается силой резания: δ = F·L³/(3EI); компенсация — увод траектории на δ в сторону, обратную отжатию; требуется оценка силы F из MRR (material removal rate) по swept-объёму за оборот.
827. **Стабильность резания: chatter lobes** — стабильная глубина a_p(ω) ограничена лепестками устойчивости: a_lim = −1/(2·Re[G(iω)]); CAM выбирает обороты шпинделя в стабильной зоне по FRF державки; ядро хранит FRF-таблицу инструмента как метаданные фичи резания.
828. **Термокомпенсация станка** — линейное расширение осей ΔL = α·L·ΔT (α = 11.7·10⁻⁶ для стали); для деталей с допуском IT5–IT6 постпроцессор масштабирует координаты по температуре из probing-цикла — correction layer между CL и G-кодом.
829. **Измерение формы: least-squares vs Chebyshev** — оценка цилиндра/плоскости из точек: LS-фит минимизирует Σd² (устойчив к шуму), Чебышёв min-max даёт зону допуска формы по ISO 1101 напрямую; ядро предоставляет оба солвера, так как GD&T-отчёт требует min-zone.
830. **Минимальная зона (min-zone) для плоскостности** — плоскостность = минимальное расстояние между двумя параллельными плоскостями, охватывающими точки; NP-трудная в общем, практичная — через convex hull облака и rotating calipers; ядро вычисляет min-zone для отчётов формы.
831. **Оценка профиля поверхности по ISO 1101** — отклонение профиля = max |d_i| после best-fit к номинальной поверхности без датумов (form-only) или с датумами (profile to datums); разделение «свободный fit / связанный fit» — два режима выравнивания из пп. 811–813.
832. **Ковариация измерений щупа** — погрешность CMM анизотропна (точность вдоль оси щупа лучше); ICP с Махаланобис-весами dᵀΣ⁻¹d вместо евклидовой метрики даёт корректную оценку неопределённости выравнивания — выводится через Якобиан трансформации.
833. **Отклонение направления щупа (approach vector)** — точки измерения должны браться с направлением подхода в пределах ±20° от нормали поверхности, иначе косинусная ошибка ~ (1−cos α); планировщик CMM фильтрует точки по полю нормалей из ядра.
834. **Сегментация облака сканов на фичи** — лазерный скан (10⁶+ точек) кластеризуется по кривизне/нормалям на примитивы (плоскость, цилиндр, конус) RANSAC-фиттингом; каждый сегмент связывается с гранью CAD-модели для сравнения — тот же primitive-fitting, что и для реверс-инжиниринга.
835. **Качество tessellation для CAM** — дискретизация траектории контролируется тремя допусками: chordal (хорда), scallop (гребешок), angular (изменение нормали); единый адаптивный сэмплер по max из трёх критериев — переиспользование адаптивной тесселяции вьюера с другими весами.
836. **Компенсация износа инструмента** — износ по VB (задняя поверхность) смещает эффективный радиус: R_eff = R − Δr(t); CAM корректирует радиусную компенсацию G41/G42 значением износа из on-machine измерения эталонной кромки — замкнутый цикл измерение→коррекция.
837. **Планирование установов (setup planning)** — разбиение фич на группы по направлению доступности: каждый установ = кластер фич с общим полусферой доступа; ядро строит visibility-карту (п. 794) и кластеризует нормали фич, минимизируя число переустановов.
838. **Датум-цели (datum targets) для castings** — точечные/линейные датум-цели на литых заготовках (ISO 5459): 6 контактных зон вместо плоскостей; ядро моделирует датум-цели как точечные контакты на шероховатых гранях для выравнивания измерений литья.
839. **Интеграция CAM ↔ CAD через единый B-rep** — CAM-операции хранят ссылки на face/edge ID ядра; при редактировании модели dirty-propagation инвалидирует только траектории, касающиеся изменённых граней — инкрементальная перегенерация tool-path из того же DAG, что и перестройка геометрии.
840. **Цифровой двойник обработки** — полный лог: CL → G-код → симуляция удаления → probing-измерения → SPC; замкнутый контур требует, чтобы ядро умело обратное отображение «измеренное отклонение → параметр фичи» через Якобиан feature-графа для адаптивной коррекции модели.

## Часть XII. Обмен, производительность и большие модели (841–900)

841. **STEP AP203 vs AP214 vs AP242: семантика** — AP203 — конфигурационно-управляемое проектирование (aerospace), AP214 — автомобильные процессы с цветами/слоями/кинематикой, AP242 — унификация обоих плюс семантическая PMI; один файл одного AP, поэтому детекция AP по `FILE_SCHEMA` до разбора сущностей.
842. **AP203 configuration_controlled_design** — `CONFIGURATION_ITEM` + effectivity связывают геометрию с версией изделия; игнорирование этой связки даёт «правильную геометрию чужой ревизии» — читайте и пробрасывайте effectivity в метаданные.
843. **AP214 presentation слои** — `styled_item`/`presentation_layer_assignment` несут цвет и слои автомобильной схемы; терять их нельзя — маппинг в цветовую модель вьюера с fallback на цвет продукта.
844. **AP242 managed model based 3d engineering** — единственный AP с `tessellated_*` (запечённой тесселяцией) рядом с точной геометрией: храните её как LOD-0, чтобы вьюер открывал модель мгновенно без перетесселяции.
845. **STEP XDE-атрибуты** — имена (`name` на product/shape), материалы, плотность, валидационные свойства (объём/площадь): переносите их в дерево сцены, а не в свалку строк — по ним сверяют round-trip.
846. **Семантическая PMI AP242** — `geometric_tolerance` + `datum_feature` + `datum_reference` привязаны к граням через `shape_aspect`; без shape_aspect рамка допуска «висит в воздухе» — стройте индекс shape_aspect → face id.
847. **PMI presentation vs semantic** — presentation (полилинии выносок) — картинка, semantic (tolerance + datums) — данные; при импорте требуйте соответствие обоих слоёв, при экспорте генерируйте presentation из semantic детерминированно.
848. **GD&T-зоны как геометрия** — цилиндрическая зона позиционного допуска строится из значения и датумов; ядро должно уметь `build_tolerance_zone()` для DFM-проверок, а не только для отображения.
849. **IGES-ловушка: единицы в header** — global section хранит unit flag (6=мм, 1=дюйм), но файлы «в миллиметрах с флагом дюйм» встречаются регулярно; сверяйте габариты с разумным диапазоном и логируйте аномалию.
850. **IGES-ловушка: DE-указатели и статусы** — каждая сущность имеет status (visible/blanked, dependent/independent); blanked-сущности импортировать нельзя, dependent-сущности без владельца — мусор: фильтрация до построения топологии.
851. **IGES-ловушка: entity 102 (composite curve)** — кромки часто идут составными кривыми с разрывами между сегментами; сшивайте сегменты с допуском файла (он в header) до построения wire.
852. **IGES-ловушка: surface of revolution (120)** — угловой диапазон и ось задаются отдельно, а половина экспортёров пишет угол в радианах, половина — «подразумевает»; валидируйте замыкание и знак угла golden-файлами.
853. **JT: XT B-rep внутри** — сегмент JT может нести точный Parasolid XT B-rep и параллельно LOD-мишки; читайте XT как первичную геометрию, меши — как LOD, а не наоборот.
854. **JT LOD-таблица** — LODs в JT выбираются по числу треугольников, но пороги проприетарны; стройте свою карту LOD→экранный размер и документируйте расхождение с оригинальными порогами.
855. **3MF: beam lattices и slice extension** — в отличие от STL, 3MF хранит lattice-решётки и слои слайсинга; при экспорте TPMS-заполнения пишите beam extension, при импорте — разворачивайте в B-rep или отдавайте как voxels.
856. **glTF-экспорт с Draco/meshopt** — тесселяция CAD жирная: компрессия meshopt + quantization attributes обязательна; сохраняйте точную геометрию в extras, чтобы обратный импорт не фиттил меш заново.
857. **USD composition arcs** — экспорт сборок через references/payloads: повторяющаяся деталь — один usd-файл + N инстансов; payloads дают ленивую загрузку «бесплатно» — проектируйте дерево сцены под них.
858. **IFC4: IfcAdvancedBrep vs IfcFacetedBrep** — приёмники (Revit, Tekla) понимают faceted надёжнее; экспортируйте advanced B-rep только при подтверждённой поддержке, иначе деградируйте в faceted с допуском.
859. **IFC: единицы, геопривязка и IfcMapConversion** — строительные модели живут в проектных координатах с map conversion в геодезику; храните двойную систему координат, иначе экспорт «уезжает» на километры.
860. **Round-trip fidelity scorecard** — автотест: STEP → ядро → STEP, сравнение объёма, площади, числа граней, Хаусдорфа на выборке точек; отчёт-таблица по каждой модели в CI, пороги per-metric.
861. **Healing: tolerance unification** — импортированный файл несёт зоопарк допусков (p-curves 1e-7, 3D-рёбра 1e-3); приведите всё к модельному допуску ядра с журналом «кто был расширен» — расширение допуска = потенциальная потеря точности, покажите её пользователю.
862. **Healing: edge fixing пайплайн** — стадии: удаление вырожденных рёбер → починка same-parameter (ребро vs p-curve) → пересборка wire; каждая стадия отдельной функцией с метрикой «исправлено/осталось».
863. **Healing: sewing с лимитом** — сшивка свободных рёбер по допуску, но не выше user-cap; сшитое ребро помечается `sewed=true`, чтобы последующие операции знали, где геометрия «натянута».
864. **Healing: surface extension для швов** — зазор между гранями часто лечится продлением поверхности в допуске вместо натяжки рёбер; приоритет: extend → project → stitch, каждый шаг с откатом при росте ошибки.
865. **Healing: canonical shape cast** — почти-плоские B-сплайн-грани конвертируются в plane/cylinder/cone (проверка нормой отклонения); аналитика ускоряет булевы и убирает численный шум.
866. **Healing-отчёт как артефакт** — JSON: зазоры до/после, сшитые рёбра, конвертации, неустранимые дефекты; вьюер показывает карту дефектов, CI фейлит сборку при превышении порога.
867. **SIMD SoA-батч оценки базисов** — раскладка узлов и параметров по 4/8 в регистр (`std::simd`), весь треугольный проход Кокса–де Бура векторно; кубики давать отдельным развёрнутым ядром, бенчмарк против скалярного пути в CI.
868. **AoSoA контрольных точек** — тайлы по 8 точек: внутри SoA (x,y,z,w), между тайлами AoS; одновременно векторизуется de Boor и не ломается cache locality при локальном доступе к p+1 точкам.
869. **Precomputed span table** — для равномерного сканирования параметра (тесселяция) таблица span-индексов считается один раз; убирает бинарный поиск из горячего цикла, кэш-линейный доступ к узлам.
870. **Arena для B-rep** — все вершины/рёбра/грани одной операции в bump-арене с итеративным drop; никаких индивидуальных Box — булевы перестают дёргать аллокатор тысячи раз.
871. **Pool-аллокатор по классам** — пулы фиксированного размера для Edge/Face/Coedge с intrusive freelist; стабильные индексы-поколения (generational index) одновременно дают топологические id.
872. **Компактный топологический граф** — half-edge хранить массивами u32-индексов (next/twin/face), а не указателями; 12–16 байт на coedge вместо 64+, проход инцидентности — предсказуемый stride.
873. **Cache-friendly обход: reordering** — перенумерация граней/патчей по пространственной близости (Morton-код центроидов) перед параллельной тесселяцией; соседние задачи делят кэш и не конфликтуют по памяти.
874. **Rayon в булевых: разбиение работы** — параллелизм по парам граней (n² независимых пересечений) → сборка рёбер пересечения последовательной фазой; shuffle-фаза через каналы, не общий mutex.
875. **Work-stealing тесселяция с приоритетами** — двухуровневая очередь: видимые грани в rayon-пул с большим чанком, фоновые LOD — отдельный пул с маленьким; видимая работа не ждёт фон.
876. **Ленивая оценка граней** — грань хранит (surface id, trim), точка оценивается по запросу; трим-проверка в (u,v) отсекает до 3D-оценки; кэш последней (u,v)→точка на грань.
877. **Мемоизация basis cache на спан** — внутри одного патча базисы зависят только от span: мини-кэш (span → базисы) на стеке; при сканировании с монотонным параметром попадание ~100%.
878. **FMA-стабильный de Boor** — α·P + (1−α)·Q переписать как Q + α·(P−Q) с `mul_add`; меньше ошибка округления и на одну операцию меньше — проверить оба эффекта бенчмарком и тестом точности.
879. **Иерархический LOD сборки** — LOD вычисляется на уровне узла дерева: дальняя подсборка рендерится одним merged-мешем, не суммой LOD деталей; пересборка узла только при смене LOD-порога его детей.
880. **Instancing с трансформ-индексом** — повторяющаяся деталь: одна тесселяция + массив матриц; идентификация инстанса через (geometry_hash, transform_index) — пикинг и выделение работают без развёртки.
881. **External references: ссылочная модель документа** — файл сборки хранит URI+хэш деталей, не геометрию; резолвер качает/читает по мере надобности, версия детали — по хэшу, конфликт ревизий — диагностика.
882. **Стриминг NURBS-first** — протокол: сначала AABB-дерево и NURBS-описания (компактные), тесселяции подкачиваются; вьюер рисует bounding boxes и переключает на геометрию по мере готовности.
883. **Occlusion-driven подгрузка** — запрос на тесселяцию детали ставится только после прохождения occlusion test её AABB на прошлом кадре (HiZ/conditional rendering); occluded детали остаются в LOD-N.
884. **Приоритетная очередь стриминга** — score = экранная площадь × (1/расстояние) × staleness × неготовность; бюджет кадра на десериализацию; preemption дешевле, чем отмена — задачи мелкие.
885. **Сборочный граф как единица кэша** — кэш тесселяций ключируется (node_hash, tolerance); node_hash подсборки = хэш хэшей детей — инвалидация каскадом без обхода всего дерева.
886. **Массивы/паттерны как инстансы** — детекция повторов (сравнение геометрии после выравнивания AABB) при импорте STEP: 200 одинаковых винтов → 1 геометрия + 200 трансформов до тесселяции.
887. **Сжатие узловых векторов** — дельта-кодирование узлов (для clamped-векторов края известны) + varint; для uniform-кривых хранить только (min, max, count); типично 5–10× экономия на полигональных профилях.
888. **Квантизация контрольных точек с сертификатом** — int16/int24 в локальном AABB + деквантизация; прикладывается оценка максимальной ошибки формы кривой через свойство выпуклой оболочки (ошибка кривой ≤ ошибке точек) — сертификат в заголовке блока.
889. **Shared knot vectors** — выделение одинаковых векторов узлов (кубики с одинаковой кратностью — 90% механических моделей) в таблицу с interning по хэшу; кривая хранит u16-ссылку.
890. **mmap-формат модели** — собственный контейнер: заголовок + выровненные секции (узлы, точки, топология, меши), mmap с zero-copy чтением; записывается как снапшот арены, открывается за миллисекунды.
891. **Copy-on-write страницы при редактировании** — mmap-регион read-only, мутации пишут в overlay-секцию с журналом; откат = сброс журнала, сохранение = compaction; большие сборки не дублируются в RAM.
892. **WASM SIMD128: численный паритет** — v128-путь обязан давать результаты в пределах заданного ULP от скалярного; CI-матрица scalar/simd × браузеры с побайтовым сравнением golden-выводов.
893. **WASM-потоки: планировщик без rayon** — wasm-bindgen-rayon сковывает топологией пула; собственный лёгкий планировщик (atomics + очередь задач) с настраиваемым числом потоков и graceful-degradation до 1.
894. **Бюджет памяти 4 ГБ (wasm32)** — разделяйте heap: геометрия в стабильных аренах, меши в отдельном регионе с LRU-выселением; трекер RSS внутри wasm (собственный аллокатор со счётчиком) и аварийный даунгрейд LOD при 80%.
895. **WASM64 readiness** — изолируйте все размерные типы за `type Idx = u32` и не привязывайтесь к `usize` в сериализации; переезд на memory64 потом — фича-флаг, а не рефакторинг.
896. **Geometry fuzzing с оракулами** — генератор валидных B-rep (грамматика операций), оракулы: Эйлер–Пуанкаре, неотрицательный объём, evaluate внутри AABB; каждый краш-кейс минифицируется (creduce-скрипт) в корпус.
897. **Mutation testing алгоритмов** — mutagen/cargo-mutants на ядре: мутация в find_span или де Буре обязана убиваться тестом; живые мутанты → новый property-тест, отчёт мутационного скора в релизных воротах.
898. **Дифференциальные оракулы на симметриях** — метаморфные отношения: булевы коммутативны (A∪B ≡ B∪A), реверс кривой сохраняет образ, поворот сцены поворачивает результат — прогон одних моделей через все симметрии ловит баги без эталонов.
899. **Cookbook-рецепты** — коллекция коротких задач уровня «выдавить профиль и снять фаску», «загрузить STEP и посчитать объём»: каждый рецепт — исполняемый файл, doctest в CI, сниппеты вставляются в документацию автоматически.
900. **Интерактивные примеры в браузере** — каждая страница API-доков содержит живой виджет (WASM-ядро + слайдеры параметров: степень, узлы, веса); код примера — тот же, что в репозитории examples, сборка примеров — часть релизного пайплайна.


## Часть XIII. Продвинутое моделирование и direct editing (901–950)

901. **Функционал энергии тонкой пластины** — минимизация E = ∫∫ (S_uu² + 2S_uv² + S_vv²) du dv по свободным контрольным точкам; дискретизация в конечные разности по контрольной сетке приводит к разреженной системе K·P = b, решаемой CG с предобусловливателем по диагонали узлов.
902. **Функционал вариации кривизны (Euler spiral fairness)** — E = ∫ κ_s² ds (квадрат производной кривизны) штрафует «волнистость» сильнее, чем ∫κ²; для B-сплайн-кривых собирается точным квадратурным интегрированием с Якобианом дуговой длины и даёт квази-линейную систему, решаемую итерациями Гаусса–Ньютона.
903. **Составной fairness-функционал** — E = α·E_membrane + β·E_plate + γ·E_curv_var с весами на виджете; градиент по всем слагаемым считается одной сборкой матрицы, поэтому смена весов не требует повторной факторизации при α,β,γ > 0 (общая разреженная структура).
904. **Вариационный филлинг n-сторонней дыры** — Coons-патч как начальное приближение, затем релаксация внутренних контрольных точек минимизацией пластинной энергии с закреплёнными граничными рядами (G1: свободен только второй ряд вдоль нормали, согласованный с соседями).
905. **Градиентная проверка вариационного солвера** — для каждого fairness-функционала аналитический градиент по контрольным точкам сверяется с центральными разностями на случайной поверхности (относительная ошибка < 1e-6); property-тест в CI, иначе оптимизация «сходит», но не туда.
906. **Мультисеточная релаксация больших сеток** — вариационная правка поверхности 100×100 контрольных точек решается V-циклами: coarse-сетка решает низкие частоты, fine — высокие; пролонгация/рестрикция — через утоньшение/удаление узлов того же B-сплайна.
907. **Нелинейная минимизация кривизны с граничными условиями G2** — связывание вторых рядов контрольных точек по формуле кривизны-продолжения как штрафы с адаптивным множителем Лагранжа; штраф растёт пока невязка G2 не упадёт ниже допуска, иначе жёсткая связка «замораживает» релаксацию.
908. **Fairness-индикаторы: поребрик кривизны (comb) на изопараметрах** — визуализация κ и κ' вдоль изолиний до/после релаксации; норма |Δκ'| как метрика улучшения, показываемая пользователю числом, а не только картинкой.
909. **Локальная вариационная правка с маской** — оптимизируются только контрольные точки в радиусе R от курсора с гармоническим затуханием влияния; матрица собирается из подблока глобальной матрицы энергии, поэтому правка 20 точек не трогает остальные 5000.
910. **FFD-lattice: построение решётки** — по AABB геометрии строится тензорная B-сплайн-решётка степени (l,m,n) с параметризацией точек модели в локальные (s,t,u) решётки через STP-координаты; кэширование (точка → параметры решётки) обязательно — пересчёт после каждого движения контрольной точки только по затронутому спану.
911. **FFD с B-сплайн-решёткой, не Безье** — локальная поддержка B-сплайна делает правку действительно локальной: сдвиг одной узловой точки меняет форму в окрестности (l+1)·(m+1)·(n+1) спанов; Безье-решётка тянет весь объём, поэтому для точечной правки подходит только B-сплайн.
912. **Деформация Барра: taper** — масштабирование x,y как функция z: x' = x·f(z), y' = y·f(z) с f заданной рациональной или B-сплайн-кривой профиля; якобиан деформации контролируется: где |∂f/∂z| велик, локальное растяжение нормалей корректируется транспонированным обратным якобианом.
913. **Деформация Барра: twist** — поворот вокруг оси z на угол θ(z) = θ₀ + z·(θ₁−θ₀)/h; применяется к контрольным точкам NURBS-поверхности (форма-образующая деформация на уровне контрольного полигона сохраняет класс геометрии), а не к вершинам меша.
914. **Деформация Барра: bend** — изгиб вокруг оси с радиусом r(y): точка (x,y,z) переходит в (r − (r−x)·cos θ, y₀ + (r−x)·sin θ, z), θ = (y−y₀)/r; область изгиба ограничена полосой y∈[y₀,y₁], за её пределами — чистый поворот, иначе геометрия «складывается» сама в себя.
915. **Wire-деформация (Singh–Fiume)** — деформация задана парой кривых: базовая W и целевая W'; точка модели проецируется на W (ближайшая точка), её смещение интерполируется разностью W'−W в точке проекции с радиальным затуханием e^(−d²/r²); подходит для «утолщения по линии» и правки по профилю.
916. **Wire-деформация с несколькими проволоками** — суммарное смещение = нормированная взвешенная сумма вкладов проволок (веса по расстоянию до каждой W_i), без перенасыщения: деление на сумму весов гарантирует, что две проволоки рядом не дают двойного смещения.
917. **FFD-деформация с сохранением объёма** — после сдвига контрольных точек решётки вычисляется новый объём замкнутого тела (дивергенцией по граням); остаточная коррекция — одномерный поиск масштаба вдоль средней нормали деформации до |ΔV/V| < 1e-4, чтобы bend не «выкачивал» объём из детали.
918. **Rolling-ball fillet** — филлет как огибающая шара радиуса r, катящегося по обеим опорным поверхностям: сначала offset-пересечения (две трассы центров шара), затем spine-кривая и сечения-дуги; точность трассы критична — marching с шагом по кривизне спайна и проекцией на оба офсета.
919. **Variable-radius fillet** — радиус r(t) задан законом вдоль спайна (линейный, B-сплайн через заданные точки, по длине дуги); сечение филлета — дуга с текущим r(t); контроль: r(t) не может упасть ниже 0 и не должен превышать локальную геометрическую досягаемость (медиальная ось даёт верхнюю границу).
920. **Setback blend (vertex blend)** — на вершине сходства k филлетов строится вершинная заплата: филлеты обрезаются на расстоянии setback от вершины, дыра заполняется n-сторонней поверхностью с G1/G2 к подрезанным филлетам; выбор setback per-edge, а не глобальный, иначе на узких гранях заплаты накладываются.
921. **Hold-line fillet** — филлет ограничен двумя произвольными кривыми на опорных гранях (не трассы rolling ball): сечение — кривая, касательная к обеим граням в точках холд-линий (коника через условия касания или G2-сплайн); холд-линии должны иметь одинаковую параметризацию по спайну — ресемплинг по длине дуги обязателен.
922. **Chordal fillet** — вместо радиуса задаётся хорда c: радиус сечения восстанавливается из хорды и угла между гранями r = c/(2 sin(φ/2)); удобен когда важна ширина валика (сварка); при переменном угле граней радиус «плывёт» — предупреждать пользователя о диапазоне r вдоль ребра.
923. **Curvature-continuous (G2) fillet** — сечение не дуга, а кривая с согласованной кривизной на концах (бленд по сплайну 5-й степени с G2-граничными условиями); маркировать в модели как отдельный тип, потому что downstream-операции (offset, шелл) должны знать, что кривизна непрерывна и не вводить аппроксимацию дугой.
924. **Fillet-overflow: пересечение филлетов до тела** — каскадные филлеты: сначала строятся поверхности филлетов по рёбрам независимо, затем их обрезка/пересечение между собой, и только потом булева подрезка тела; порядок рёбер сортировать по радиусу (больший первым), иначе малые филлеты съедаются чужими триммингами.
925. **Fillet-резолвер: graceful failure** — если филлет не строится (self-intersection сечения, радиус > допустимого), откатывать ребро с диагностикой (edge id, точка сходимости, предельный радиус), а не сносить всю операцию; пользователь получает «построено 9 из 12 рёбер, по 3 — пределы».
926. **AAG: построение графа** — узлы = грани, рёбра = рёбра B-rep с атрибутами (тип сопряжения: convex/concave/tangent/smooth по знаку двугранного угла в середине ребра, длина ребра); угол считается по нормалям в выборке точек ребра, не в одной — на кривых рёбрах знак угла может меняться.
927. **Атрибуты граней в AAG** — к узлу прикрепляются: тип поверхности (plane/cylinder/freeform), площадь, ориентация оси (для вращательных), радиус, признак «филлет-подобная» (малый радиус, два гладких соседа); классификатор поверхностей запускается один раз при построении графа и кэшируется.
928. **Распознавание отверстий** — шаблон: цилиндрическая грань, все рёбра concave, соседи — plane/torus(fillet); классификация: through/blind (есть ли дно), countersink/counterbore (коническая или цилиндрическая ступень у входа), резьба — по атрибутам/геометрической эвристике витка.
929. **Распознавание карманов** — подграф из plane-основания и боковых граней, у которого все рёбра на границе подграфа convex, а внутренние — concave; классификация по основанию (open/closed pocket), по боковым стенкам (straight/drafted — наклон оси стенки к нормали основания).
930. **Распознавание бобышек (boss) и рёбер жёсткости** — boss = инверсия кармана (convex внутри, concave на границе); rib = тонкая plane-пара граней с малым зазором, стоящая на двух несвязных границах; толщину рёбер измерять как среднее расстояние между парой противоположных граней (медиальная ось подграфа).
931. **Распознавание филлетов для подавления** — цепочки граней с тангенциальными рёбрами и малым радиусом кривизны маркируются как fillet-chain; подавление = замена цепочки пересечением продлений опорных граней (или offset-откат), с валидацией что результат замкнут.
932. **Feature suppression в AAG** — удаление фичи = вырезание её подграфа и «зашивка»: грани-соседи продлеваются (surface extension) до взаимного пересечения, новые рёбра — от пересечения продлений; откат при невозможности продления (расходящиеся поверхности) — честный failure с подсветкой виновной грани.
933. **Direct modeling: move face** — сдвиг грани вдоль вектора с пересборкой окрестности: соседние грани, которые «разошлись», продлеваются/обрезаются до новых пересечений; классификация соседей на «ведомые» (двигаются вместе, если coplanar/coaxial) и «поглощающие» (обрезают) по атрибутам AAG.
934. **Direct modeling: offset face** — то же, что move, но offset-ограничения: coaxial-цилиндры (пара concentric-граней) должны остаться concentric; радиальные offset'ы идут парой, иначе шелл-толщина ломается — детекция concentric-пар до мутации обязательна.
935. **Direct modeling: tweak (наклон грани)** — поворот грани вокруг оси на угол: если поворот превышает draft-анализ окрестности, рёбра-зависимости переводятся в fixed и правка блокируется; подсчёт допустимого угла до операции, не после.
936. **Direct modeling: replace face** — замена геометрии грани новой поверхностью (target surface): старые рёбра проецируются на новую поверхность (closest-point + итеративное уточнение), топология сохраняется; если проекция рёбер вылезает за естественные границы target — ошибка с указанием ребра.
937. **Direct modeling: delete face с зашивкой** — удаление грани тремя стратегиями по выбору: patch (построить новую поверхность через контур дыры — n-sided fill), extend (продлить соседей до пересечения), cap (сделать тело открытым/сшитым); стратегия по умолчанию выбирается эвристикой по типу соседей (plane → extend, freeform → patch).
938. **Replace face с выравниванием на аналитику** — частный случай: freeform-грань заменяется подогнанной plane/cylinder (least-squares фит по сетке точек грани) с допуском; «плоскость вместо кривой» убирает численный шум импортированных моделей — типичная healing-операция через тот же механизм replace face.
939. **Инкрементальность direct-edit: dirty-region** — move/offset/replace face пересобирает только грани, чьи рёбра пересекают сферу влияния (грань + соседи второго порядка); остальная топология и тесселяция переиспользуются, хэш поддерева не инвалидируется.
940. **Валидация после direct-edit** — после каждой операции: проверка замкнутости (каждое ребро ровно у 2 граней), Эйлер–Пуанкаре, самопересечения новых рёбер со старыми гранями в dirty-region; отчёт привязывается к undo-записи, чтобы откат возвращал проверенно валидное состояние.
941. **История построения: feature tree** — модель = последовательность фич (sketch→extrude→fillet→shell...) с параметрами; каждая фича хранит входные ссылки (persistent names), выходной B-rep снапшот опционально кэшируется; дерево сериализуется отдельно от геометрии (rebuild из дерева — must-work сценарий).
942. **Persistent naming** — ссылки «ребро №7» нестабильны при перестройке; именование через атрибуты порождения (ребро = пересечение грани фичи A и грани фичи B + индекс в группе) + поиск по близости как fallback; статистика «потерянных имён» после rebuild показывается пользователю по фичам.
943. **Rollback / rebuild** — откат к фиче k = перестройка с 0 (или с ближайшего кэшированного снапшота до k) и полная переоценка дерева; инкрементальный rebuild: пересчитываются только фичи, чьи входы изменились (топологическая сортировка графа зависимостей фич).
944. **Reorder операций** — перестановка фич в дереве допустима, если новый порядок не нарушает зависимости (фича не может идти раньше своих входов); проверка — топологическая сортировка + пробный rebuild; недопустимые перестановки блокируются с объяснением («fillet_3 зависит от грани, созданной extrude_2»).
945. **Подавление фич (suppress)** — suppressed-фича пропускается при rebuild, но остаётся в дереве со всеми параметрами; dependent-фичи, ссылающиеся на подавленную, помечаются dangling и тоже подавляются каскадом (с визуальной индикацией каскада в дереве).
946. **Parent/child визуализация зависимостей** — по выбору фичи показывать подграф: кто её родители (входы) и дети (кто сломается при удалении); «удалить фичу» = предпросмотр каскада до подтверждения, иначе пользователь удаляет sketch и теряет полмодели молча.
947. **Регенерация при смене параметра: минимальный dirty-set** — изменение параметра фичи помечает грязными только её потомков; кэшированные B-rep снапшоты чистых фич переиспользуются; измерять долю переиспользованных фич на типовых правках и держать её >80% в бенчмарке.
948. **Rollback-снапшоты и copy-on-write тел** — снапшот после каждой фичи хранит не копию B-rep, а delta (новые/изменённые грани) с CoW-ссылками на неизменённое; память истории из 50 фич — порядка одной модели, а не 50 копий.
949. **Режим «прямого» и «параметрического» редактирования одновременно** — direct-edit операции встраиваются в историю как фичи (move face с параметрами), а не разрушают дерево; конфликт (direct-edit ссылается на грань, исчезнувшую после правки выше по дереву) решается тем же persistent naming.
950. **Журнал операций как воспроизводимый скрипт** — вся история экспортируется в текстовый журнал (операция + параметры + версии имён); replay журнала на чистой сцене должен давать идентичный B-rep (сравнение хэшем объёма/топологии) — это одновременно формат макросов и регрессионный тест ядра.

## Часть XIV. Отраслевые домены II и платформа (951–1000)

951. **NACA 4-значные профили** — генератор по коду MPXX: толщина полиномом с замкнутой/открытой кромкой, линия кривизны кусочно-квадратичная; обе ветви объединяются в единую B-сплайн-кривую с контролируемым числом контрольных точек и кластеризацией узлов у носка (расстояния ∝ √(x/c)).
952. **NACA 5-значные профили** — линия кривизны с переходом кубика→прямая по ветвям, внутренний решатель для точки перехода через нелинейное уравнение на k₁; публичный API возвращает точный B-сплайн обеих ветвей, а не табличную аппроксимацию.
953. **CST-параметризация профиля** — класс-функция x^N1·(1−x)^N2 × форм-функция как B-сплайн по Bernstein-базису; обратная задача: подбор CST-коэффициентов под заданный профиль методом наименьших квадратов с регуляризацией Тихонова и невязкой по Hausdorff-расстоянию.
954. **Построение крыла по сечениям** — loft через массив профилей с выравниванием: приведение всех сечений к общему узловому вектору (merge + degree elevation), скин по хордовой параметризации направляющей; правило концевика — точка или куполообразная поверхность с G2-стыковкой.
955. **Крутка и стреловидность крыла** — сечения задаются в локальных осях (twist, dihedral, sweep, taper), loft строится в глобальных координатах с аналитической перенормировкой производных; проверка самопересечений при большой крутке через анализ знака якобиана поверхности.
956. **Интерполяция профиля через облако точек** — fitting B-сплайна к разметке аэродинамического профиля с ограничением G1 в носке (радиус кривизны ≥ заданного) и замыканием хвостовой кромки; итеративная параметризация Ли с весовой функцией по кривизне.
957. **Анализ кривизны профиля: качество обдува** — график кривизны и её производной как критерий гладкости: детекция «волнистости» через интеграл |dκ/ds| и пороговый счётчик перемен знака κ″; отчёт привязан к параметрам B-сплайна, а не к дискретным точкам.
958. **Стыковка крыло–фюзеляж (fairing)** — зализ как blend-поверхность с G2-граничными условиями по обеим сторонам; управляющие кривые — сечения-профили в плоскостях, ортогональных линии пересечения; автоподбор влияния (influence depth) по критерию минимума среднего отклонения кривизны.
959. **Highlight lines как числовая метрика** — линии бликов от виртуальной гирлянды параллельных источников: кривые на поверхности, где (n·r) = const, строятся марширующим методом на (u,v)-сетке; метрика качества — G-непрерывность самих бликовых линий, разрыв считается дефектом.
960. **Зебра-анализ с порогом квантования** — отражённая полосатая текстура рендерится на тесселяции, но валидация идёт аналитически: разрывы полос на шве поверхностей означают нарушение G1/G2; автоматический тест считает угол отражённых нормалей вдоль шва и сверяет с классом (A/B/C).
961. **Reflection lines через производные** — построение изопараметрических кривых отражения с последующим анализом порядка непрерывности: кривая рассматривается как функция параметра, и скачки её d²/ds² локализуют дефектные патчи с указанием (u,v)-координат.
962. **Пороговый класс-A валидатор** — конфигурируемые допуски: позиционный зазор, угол между нормалями на шве, относительный скачок кривизны; каждая грань получает класс (A/B/C), а отчёт — тепловую карту нарушений с сериализацией в JSON для CI-ворот.
963. **Isophote-анализ** — линии постоянного угла между нормалью и направлением света: n·L = cos θ; чувствительнее зебры к локальным вмятинам; метрика — отклонение расстояния между соседними изофотами от теоретического для идеальной формы.
964. **Детекция вмятин/выпуклостей поверхности** — сравнение карты гауссовой кривизны с её сглаженной версией (гауссов фильтр в (u,v)): остаток выше порога → подсветка зоны и выдача максимальной амплитуды дефекта в мм.
965. **Анатомические поверхности из DICOM** — конвейер: сегментация срезов → point cloud → обёртка B-rep: Poisson/marching cubes → ретопология в quad-сетку → B-сплайн-патчи по квадам с G1 на швах; допуск к облаку и число патчей — параметры задачи.
966. **Зубная коронка: параметрический шаблон** — базовая анатомия коронки как NURBS-шаблон с деформирующими контрольными точками (бугорки, фиссуры); адаптация под скан культи: FFD-деформация с ограничением минимальной толщины стенки (проверка через ray-cast к внутренней поверхности).
967. **Окклюзионный контакт как зазорный анализ** — сопряжение антагонистов: расчёт поля зазоров (signed distance между поверхностями) с классификацией: контакт (< 20 мкм), близкий, несоприкосновение; тепловая карта экспортируется вместе с моделью.
968. **Цементный зазор и кромка коронки** — оффсет внутренней поверхности на заданный зазор (25–50 мкм) с точным оффсетом NURBS и аппроксимацией в зонах поднутрения; детекция поднутрений — анализ видимости из направления установки (гистограмма n·d).
969. **Ортез по скану конечности** — облегающая поверхность: параметризация скана на цилиндрическую развёртку, оффсет на толщину материала, вырезы по анатомическим ориентирам; вентиляционные отверстия — булевы с паттерном, проверенным на минимальную перемычку.
970. **Имплант с пористой структурой** — твёрдое ядро B-rep + латтис-зона: трипли-периодические поверхности (gyroid) ограничиваются оболочкой импланта; пористая зона хранится как параметрическое описание (толщина стойки, размер ячейки), тесселяция — только на экспорте.
971. **Ювелирное паве: раскладка камней** — заполнение свободной поверхности сеткой камней: параметризация (u,v) → размещение по геодезической сетке с релаксацией (Lloyd-итерации на поверхности); ограничения: минимальный зазор между гранями камней, краевой припуск на крапаны.
972. **Огранка камня (brilliant cut)** — параметрический генератор: крона/павильон/рундист как наборы фацет-плоскостей по углам огранки; B-rep собирается пересечением полупространств; экспорт веса — объём × плотность с учётом усечений.
973. **Каст (оправа) под камень** — автовычитание: тело камня масштабируется на shrinkage-фактор, крапаны генерируются как призмы по нормалям к рундисту с фаской под обжим; проверка — минимальная толщина металла между камнем и внешней стенкой (ray-cast анализ).
974. **Кольцо: шинка по размеру** — параметрическая шинка как sweep эллиптического профиля по окружности с коррекцией эвольвенты посадки; таблица размеров (US/EU/RU) → диаметр; подгонка верхней площадки — обрезка sweep'а плоскостью с G1-blend к декоративной части.
975. **Подготовка к 3D-печати воском** — проверки ювелирной печатности: минимальная толщина (0.3 мм), self-support углы, drain-отверстия для полостей; отчёт с визуализацией нарушающих зон; автоориентация модели по минимуму площади поддержек.
976. **Панелизация фасада** — разбиение свободной поверхности на панели по (u,v)-сетке с ограничением максимального размера и типов панелей; каждая панель классифицируется: плоская / однократной кривизны / двоякой — по анализу гауссовой кривизны и отклонения от best-fit плоскости.
977. **Планаризация квад-панелей** — оптимизация сетки панелей под планарность: итеративная минимизация энергии Σ(отклонение вершин от best-fit плоскости)² с якорями на граничных кривых; метрика — максимальный и RMS-зазор, целевой допуск задаётся технологией (стекло ≤ 1–2 мм).
978. **Геодезические линии для раскроя** — раскрой двояких панелей: развёртка (flattening) с минимизацией энергии натяжения (as-rigid-as-possible в (u,v)); отчёт по деформации раскроя — поле растяжения/сжатия в % относительно исходной поверхности.
979. **Узлы и кромки панелей** — автоматическая генерация метаданных узла: тип стыка (открытый/закрытый), ширина шва как функция допусков соседних панелей, углы раскрытия кромки по нормалям; экспорт в таблицу спецификации с ID панели из имени грани.
980. **Нумерация и сериализация панелей** — детерминированная маркировка панелей (ряд×позиция от геодезической сортировки), экспорт каждой панели отдельным STEP/DXF с вложенным ID; повторный прогон при неизменной поверхности даёт идентичные ID — проверяется тестом.
981. **DSL ядра: синтаксис и грамматика** — скриптовый язык моделирования (pest/tree-sitter грамматика): примитивы, булевы, трансформации как выражения с именованными параметрами; типизация единиц (мм/м/град) на уровне парсера, ошибка единиц — на этапе компиляции, не в рантайме.
982. **DSL: переменные и параметризация** — именованные параметры с выражениями (`width = 40mm`, `hole_d = width/8`), зависимости строят DAG; изменение параметра пересчитывает только зависимый подграф — скриптовая модель параметрична «бесплатно».
983. **CLI движка** — бинарь `cad`: подкоманды `build script.cad -o model.step`, `info model.step` (объём, площадь, грани), `convert`, `validate`, `tessellate --tol`; все коды возврата и stderr-формат машиночитаемы (JSON с `--json`) для пайплайнов CI.
984. **Пакетная обработка** — режим `cad batch manifest.toml`: список заданий (скрипт + параметры + выход), параллельное исполнение с изоляцией (процесс на задание), дедупликация по хэшу (скрипт, параметры) — повторный прогон пропускает готовые артефакты.
985. **Детерминизм скриптовой сборки** — одни и те же входы обязаны давать побайтово идентичный STEP: фиксированный порядок обхода топологии, запрет HashMap-итерации в выходном потоке, seed генераторов — из манифеста; CI-тест собирает модель дважды и сравнивает хэши.
986. **Undo/redo: командный фреймворк** — каждая операция моделирования — объект Command с `execute/revert`; revert реализуется обратной дельтой топологии (список добавленных/удалённых сущностей), а не снапшотом — память растёт линейно по изменениям, а не по модели.
987. **Схлопывание и ветвление истории** — coalescing повторных мелких команд (перетаскивание точки = одна команда с начальным/конечным значением), лимит глубины с drop-политикой; redo-стек инвалидируется при новой команде, что фиксируется тестом инварианта.
988. **Транзакции и откат при ошибке** — группа команд под `transaction`: сбой любой операции откатывает всю группу по журналу; журнал записывается до мутации (write-ahead), падение процесса оставляет модель в согласованном состоянии при следующем открытии.
989. **Прогресс длинных операций** — контракт `Progress`: (stage, fraction, eta) с монотонностью fraction внутри стадии; тяжёлые алгоритмы (булевы, тесселяция, healing) обязаны отдавать прогресс не реже 10 Гц по счётчику итераций; CLI рендерит через indicatif, GUI — через канал.
990. **Отмена операций (cancellation)** — кооперативная отмена через `CancellationToken`: точки проверки в циклах пересечений, tessellation и fitting'а; отмена обязана завершаться < 100 мс и оставлять модель нетронутой (мутации применяются только в commit-фазе).
991. **Доступность (a11y) CLI и сообщений** — вывод CLI без ANSI-цвета при `NO_COLOR`/не-TTY, статусы дублируются текстом (не только цветом), прогресс-бары заменяются строковыми процентами для скринридеров; все exit-коды документированы и стабильны.
992. **Интернационализация диагностик** — сообщения об ошибках через fluent/icu-messageformat каталоги: код ошибки стабилен (E1001), текст — локализуем; плюрализация и порядок аргументов — по CLDR; английский — fallback, тесты проверяют покрытие всех кодов всеми локалями.
993. **Структурированные диагностики** — каждая ошибка: код, severity, span (файл/строка для DSL или entity id для геометрии), сообщение, подсказка; сериализация в JSON для IDE-интеграции (LSP diagnostic) — формат фиксируется JSON Schema и версионируется.
994. **Модель единиц измерения** — внутреннее представление всегда в SI-базе (метры), единица документа — метаданные; парсинг `5mm`, `2in`, `3'` в тип `Length` на границе API; арифметика смешанных единиц — корректна по построению, сырые f64 без единицы в публичном API запрещены (newtype).
995. **Конвертация и допуски при смене единиц** — смена единицы документа масштабирует геометрию с точным коэффициентом (inch = 25.4 мм — exact); абсолютные допуски пересчитываются, относительные сохраняются; STEP-импорт/экспорт читает/пишет `CONVERSION_BASED_UNIT` без потерь.
996. **Лицензионная чистота зависимостей** — `cargo-deny` в CI: whitelist лицензий (MIT/Apache-2.0/BSD/Zlib), запрет GPL/AGPL в дереве зависимостей, `cargo-about` генерирует NOTICE для релизов; каждое добавление зависимости — проверка лицензии и duplicate-версий.
997. **Патентная чистота алгоритмов** — реестр алгоритмов с известными патентными рисками (отдельные методы healing, фасетирования): предпочтение открытым публикациям и алгоритмам с истёкшими патентами; каждый спорный алгоритм документируется обоснованием и альтернативой.
998. **Плагинная архитектура: ABI и регистрация** — ядро экспортирует стабильный C-ABI слой (или WASM-интерфейс wit) для плагинов: регистрация операторов, импортёров, экспортёров через таблицу vtable с версией ABI; несовпадение версии — отказ загрузки с диагностикой, не UB.
999. **Песочница и лимиты плагинов** — плагин исполняется с бюджетом памяти/времени, паника плагина изолируется (catch_unwind / отдельный процесс), ошибка не роняет ядро; телеметрия отказов плагина — в общий канал диагностик с id плагина и версии.
1000. **Плагинный реестр команд DSL** — плагин может регистрировать новые команды DSL (`gear.module(2).teeth(24)`) с JSON Schema параметров; парсер DSL валидирует вызовы плагинов по схеме до исполнения, автодополнение LSP строится из того же реестра — язык расширяем без перекомпиляции ядра.
