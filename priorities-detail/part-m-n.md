#### 181. nalgebra vs glam [статус: TODO] [трудоёмкость: M]
- **Суть:** Развести линейную алгебру: nalgebra (генерики, LU/SVD) — в ядре, glam (f32, SIMD) — в рендере, с явной конвертацией на границе. Сейчас nalgebra фигурирует только в `mechanics-core`, а ядро (`nurbs-core`, `math-core`) использует собственные типы точек/векторов — нужно зафиксировать решение: либо собственные типы + маленький солвер, либо nalgebra внутри, glam наружу. Подводный камень — скрытая конвертация f64↔f32, размывающая допуски.
- **Где в коде:** `crates/math-core` (типы), `crates/nurbs-core/src/core`, рендер-граница в `geometry-bridge`/`gpu-compute`.
- **Зависимости:** 246 (Scalar f64), 184 (f64 для геометрии, f32 для GPU).
- **Критерии приёмки:** ADR-документ; один источник типов Point3/Vector3/Matrix для ядра; конвертация f64→f32 только в одном модуле; grep не находит glam внутри ядра и nalgebra в рендер-пути.

#### 244. Шкалы допусков [статус: TODO] [трудоёмкость: M]
- **Суть:** Эффективный допуск вычисляется от масштаба сцены: `tol_eff = bbox_diagonal × relative_tol`, без зашитых констант вида 1e-9. Ввести тип `ToleranceContext { scale, abs_tol, rel_tol }`, прокидываемый во все геометрические сравнения; константы допусков собрать в одном месте. Риск — перфорация API: сотни сигнатур придётся расширить контекстом, лучше сделать его частью конфигурации операции, а не параметром каждой функции.
- **Где в коде:** `crates/nurbs-core/src/foundation/` (новый `tolerances.rs` рядом с `guards.rs`), потребители — `offset/`, `intersection/`, `trim/`.
- **Зависимости:** 185 (иерархия допусков), 1064 (контракт допусков).
- **Критерии приёмки:** grep не находит числовых литералов-допусков вне `tolerances.rs`; тест: одна и та же операция на модели ×1000 масштаба даёт согласованный результат в относительных единицах.

#### 246. Scalar f64 в ядре [статус: TODO] [трудоёмкость: M]
- **Суть:** Зафиксировать `f64` как рабочий скаляр ядра: либо `pub type Scalar = f64`, либо генерик `T: Float` только там, где реально нужны два пути (тесты точности, embedded). Генерик «на всякий случай» удваивает время компиляции и размывает код — прагматичный вариант: type alias + тонкая абстракция над элементарными функциями. Конвертация в f32 только на рендер-границе.

#### 254. Детерминизм вычислений [статус: TODO] [трудоёмкость: L]

- **Где в коде:** `crates/nurbs-core/src/numerics/` (редукции), `crates/nurbs-core/src/tessellation/` (сборка меша), CI-матрица платформ.
- **Зависимости:** 1070, 919.
- **Критерии приёмки:** CI собирает эталонную модель на трёх платформах и сравнивает хэши; список «известных недетерминированных мест» пуст или документирован; отчёт о fast-math флагах в релизных заметках.

#### 915. DSL ядра: синтаксис и грамматика [статус: TODO] [трудоёмкость: L]

#### 921. Отмена операций (cancellation) [статус: TODO] [трудоёмкость: M]
- **Суть:** Кооперативная отмена через `CancellationToken`: точки проверки в циклах пересечений, тесселяции, fitting'а; отмена завершается < 100 мс и оставляет модель нетронутой — мутации применяются только в commit-фазе. В коде токена нет. Камень преткновения — SSI-marching и булевы, где «посередине» легко получить полусобранную топологию: отсюда требование commit-фазы.
- **Где в коде:** `crates/nurbs-core/src/foundation/` (новый `cancel.rs` рядом с `guards.rs`), проверки в `intersection/ss_intersection/continuation.rs`, `tessellation/`, булевых.
- **Зависимости:** 920 (общий `OperationContext`), 1065 (бюджеты итераций — уже частично в `guards.rs`).
- **Критерии приёмки:** тест: отмена булевой на тяжёлой паре завершается < 100 мс с `Err(Cancelled)`; модель после отмены бит-в-бит равна исходной; ни одна публичная операция не игнорирует токен (checklist аудит).

#### 925. Модель единиц измерения [статус: TODO] [трудоёмкость: M]
- **Суть:** Внутреннее представление — всегда SI-база (метры); единица документа — метаданные; парсинг `5mm`, `2in`, `3'` в newtype `Length` на границе API; сырые `f64` без единицы в публичном API запрещены. Смешанная арифметика корректна по построению. В OpenSCAD-домене сейчас неявные миллиметры — это надо сделать явным. Риск — неудобство API; смягчается литеральными хелперами (`mm(5.0)`).
- **Где в коде:** новый `crates/nurbs-core/src/foundation/units.rs`; границы — `openscad-core/src/value.rs`, `rush-frontend`, будущий CLI.
- **Зависимости:** 926, 244 (допуски масштабируются вместе с единицами).
- **Критерии приёмки:** `Length::mm(25.4) == Length::inch(1.0)` точно; компиляция падает при передаче голого f64 в публичную геометрическую функцию; документ несёт единицу в метаданных.

#### 926. Конвертация и допуски при смене единиц [статус: TODO] [трудоёмкость: S]
- **Суть:** Смена единицы документа масштабирует геометрию точным коэффициентом (inch = 25.4 мм — exact); абсолютные допуски пересчитываются, относительные сохраняются; STEP-импорт/экспорт читает/пишет `CONVERSION_BASED_UNIT` без потерь. Отдельный кейс — IGES unit flag (пункт 800), там коэффициенты те же. Камень — допуски, зашитые в уже построенные pcurve, — пересчитывать централизованно.
- **Где в коде:** `crates/nurbs-core/src/foundation/units.rs` (`rescale`), вызовы в STEP/IGES-конвейере (группа G).
- **Зависимости:** 925, 171, 800.
- **Критерии приёмки:** round-trip STEP мм→inch→мм возвращает исходные координаты в пределах 1e-15 относительной; тест пересчёта `ToleranceContext` при смене единицы.

#### 1083. C-API: opaque handles и бюджеты ошибок [статус: TODO] [трудоёмкость: L]
- **Суть:** Публичный `extern "C"` слой: все типы — opaque указатели (`CadBody*`, `CadSurface*`), память владеет ядро, освобождение парными `cad_*_free`; ошибки — коды enum + thread-local сообщение (`cad_last_error_message`); никаких паник через FFI-границу — `catch_unwind` на каждом entry point; ABI-версия в имени символа `cad_abi_v1_*`. Это контракт для всех будущих биндингов (Python, .NET). Существующий `photogrammetry-ffi` — локальный прецедент FFI, но без этих дисциплин.
- **Где в коде:** новый крейт `crates/cad-ffi`; поверх `nurbs-core`, `brep-core`, `geometry-ops`.
- **Зависимости:** 232 (панико-устойчивость), 256/1086 (стабильный API), 921 (отмена через хендл операции).
- **Критерии приёмки:** header-файл генерируется (cbindgen) и компилируется тестовым C-файлом; тест: вызов с битым входом → код ошибки + сообщение, не abort; valgrind/ASan-прогон без утечек на парных free.

#### 1084. Python-биндинги с GIL-освобождением [статус: TODO] [трудоёмкость: L]
- **Суть:** pyo3-обёртка: все операции > 1 мс (booleans, тесселяция, импорт) под `py.allow_threads`; возврат — владельческие объекты без копирования (Arc-тела за Py-классом); numpy-интероп zero-copy через buffer protocol для точек/треугольников; исключения маппятся из кодов ошибок C-API, не из паник. pyo3 в проекте сейчас нет — чисто новая работа поверх 1083.
- **Где в коде:** новый крейт `crates/cad-python` (maturin), поверх `cad-ffi`.
- **Зависимости:** 1083, 920/921 (прогресс/отмена пробрасываются колбэками).
- **Критерии приёмки:** булева из Python не блокирует GIL (параллельный тест с threading); точки приходят в numpy без копии (проверка `__array_interface__` адресов); исключение на битом STEP читаемо и содержит код.

#### 1085. Semver численного поведения [статус: TODO] [трудоёмкость: M]
- **Суть:** Совместимость определена явно: patch-релиз не меняет численный выход ни одной операции на золотом корпусе (побайтово в допуске); minor — может улучшать точность (документировано); major — может менять алгоритмы. - **Критерии приёмки:** CI сравнивает численный выход золотого корпуса с бейзлайном предыдущего релиза; CHANGELOG-линтер требует секцию numerics при расхождениях; документ политики опубликован.

## Группа N. Продвинутые операции (офсеты, SSI, филлеты, блендинг) — 17 пунктов

#### 158. Офсет поверхности [статус: реализовано] [трудоёмкость: XL]
- **Суть:** S + d·n в общем случае не NURBS: сетка офсетных точек строится по нормалям, затем фиттинг B-сплайном в заданный допуск с контролем самопересечений (офсетный радиус против минимального радиуса кривизны). Подводные камни — вырожденные нормали на полюсах (105), потеря точности на гребнях, разрастание узлового вектора при фиттинге.
- **Где в коде:** `crates/nurbs-core/src/offset/surface_offset.rs`, `offset/surface_offset/` (deviation.rs, validity.rs), фиттинг — `foundation/fitting/`.
- **Зависимости:** 133 (главные кривизны — реализовано), 124/125 (фиттинг — реализовано), 105.
- **Критерии приёмки:** max |deviation| от точного офсета аналитических поверхностей (плоскость, цилиндр, сфера) < допуска; отказ с диагностикой при d > 1/max|kᵢ|; NaN-защита через `guards.rs` (есть, см. deviation.rs).

#### 159. Офсет кривой [статус: реализовано] [трудоёмкость: L]
- **Суть:** Точный офсет нерационален: конвейер сэмплирование → фиттинг в допуск, контроль самопересечений (локальные петли при d > 1/κ_max и глобальные при сближении ветвей) с обрезкой/зашивкой joins на углах. Камни — острые углы (выбор join-стратегии: arc/miter/chamfer) и вырождение касательной.
- **Где в коде:** `crates/nurbs-core/src/offset/curve_offset.rs`, `curve_offset_join.rs`, `curve_offset_wire.rs`.
- **Зависимости:** 66 (кривизна — реализовано), 60 (fit-and-simplify).
- **Критерии приёмки:** Хаусдорф от точного офсета окружности/прямой < допуска; петли при d > 1/κ_max детектируются и удаляются; join на угле 90° даёт G0/G1 по выбранной стратегии.

#### 160. Пересечение поверхность–поверхность (SSI) [статус: реализовано] [трудоёмкость: XL]
- **Суть:** Marching: стартовые точки из подразбиения (семплирование AABB/BVH пар), шаг по касательной к кривой пересечения с коррекцией Ньютоном на обе поверхности; сборка ветвей, разрешение junctions (пересечение ветвей), репорт нерешённых зон. Камни — тангенциальные и почти-вырожденные случаи (пункты 1062/1063), выбор шага по кривизне, пропуск малых петель при грубом стартовом сэмплировании.
- **Где в коде:** `crates/nurbs-core/src/intersection/ss_intersection/` (branches.rs, continuation.rs, junctions.rs, samples.rs, unresolved.rs, report.rs).
- **Зависимости:** 103 (производные поверхности — реализовано), 137 (point inversion), 253 (робастный Ньютон — реализовано).
- **Критерии приёмки:** аналитические пары (плоскость×цилиндр, цилиндр×цилиндр) — кривые пересечения в допуске от точных; каждая ветвь замкнута или упирается в границу домена; unresolved-зоны явно репортятся (unresolved.rs), не проглатываются.

#### 161. Пересечение кривая–поверхность [статус: реализовано] [трудоёмкость: L]
- **Суть:** Решение S(u,v) = C(t): Ньютон 3×3 по (u,v,t) со стартовой сетки — сэмплы кривой × грубая сетка поверхности, предварительное отсечение по BVH/AABB. Камни — касательные попадания (вырожденный якобиан, квадратичная сходимость теряется), кратные корни, промах мимо трим-области (точка в домене, но вне trim).
- **Где в коде:** `crates/nurbs-core/src/intersection/curve_surface.rs`, старты через семплирование и BVH в `distance/`.
- **Зависимости:** 78–80 (ближайшая точка, Ньютон), 143 (тримминг).
- **Критерии приёмки:** все корни на тестовых парах с известным числом пересечений (прямая×сфера: 0/1/2); касательный случай репортится как tangency, а не теряется; точность корня < геометрического допуска.

#### 162. Филлеты «катящимся шаром» [статус: реализовано] [трудоёмкость: XL]
- **Суть:** Радиус шара ограничен минимальным радиусом кривизны опорных поверхностей: r_max = min 1/max(|k₁|,|k₂|). Трасса центров шара — пересечение двух офсетов (SSI офсетных поверхностей), затем spine-кривая, сечения-дуги между точками касания, pipe-поверхность, тримминг опорных граней. Камни — вырождение спайна (самопересечение при больших радиусах), переменная кривизна опор, стыковка соседних филлетов (см. 862).
- **Где в коде:** `crates/nurbs-core/src/offset/fillet_surfaces.rs`; офсеты — `offset/surface_offset.rs`; SSI — `intersection/ss_intersection/`.
- **Зависимости:** 158, 160, 133 (все реализованы), 863 (graceful failure — реализовано).
- **Критерии приёмки:** филлет на аналитических парах (плоскость-плоскость, плоскость-цилиндр) совпадает с точным тором/цилиндром в допуске; отказ при r > r_max с диагностикой предельного радиуса; сечения перпендикулярны спайну и касательны обеим граням (G1-проверка).

#### 844. Функционал энергии тонкой пластины [статус: реализовано] [трудоёмкость: L]
- **Суть:** Минимизация E = ∫∫(S_uu² + 2S_uv² + S_vv²) du dv по свободным контрольным точкам: дискретизация в конечные разности по контрольной сетке → разреженная система K·P = b, CG с диагональным предобусловливателем. Камни — обусловленность на больших сетках, фиксация граничных условий (G0/G1 с соседями), отсутствие естественного «масштаба» у функционала (нужны веса, см. 846).
- **Где в коде:** `crates/nurbs-core/src/editing/surface_fairing.rs`, `numerics/sparse_linalg.rs`.
- **Зависимости:** 126 (сглаживание — реализовано), 847 (градиентная проверка).
- **Критерии приёмки:** энергия после минимизации ≤ начальной; сходимость CG за разумное число итераций на сетке 50×50; гребёнка кривизны визуально/метрически ровнее до/после.

#### 846. Составной fairness-функционал [статус: реализовано] [трудоёмкость: M]
- **Суть:** E = α·E_membrane + β·E_plate + γ·E_curv_var с весами на виджете; градиент по всем слагаемым собирается одной сборкой матрицы — смена весов при α,β,γ > 0 не требует повторной факторизации (общая разреженная структура). Это ключ к интерактивному фэйрингу: ползунок весов работает без пересборки. Камень — curv_var нелинеен; линеаризация на текущей итерации.
- **Где в коде:** `crates/nurbs-core/src/editing/surface_fairing.rs`, `numerics/sparse_linalg.rs`.
- **Зависимости:** 844, 847.
- **Критерии приёмки:** смена весов не пересобирает sparsity pattern (инструментальный тест); предельные режимы (α=1, β=γ=0) воспроизводят чистую мембрану; UI-ползунок в примере обновляет поверхность интерактивно.

#### 847. Градиентная проверка вариационного солвера [статус: TODO] [трудоёмкость: S]
- **Суть:** Для каждого fairness-функционала аналитический градиент по контрольным точкам сверяется с центральными разностями на случайной поверхности (относительная ошибка < 1e-6); property-тест в CI — иначе оптимизация «сходится, но не туда». Дешёвый пункт с непропорционально большой ценностью: ловит ошибки знака/индексации в сборке матрицы.
- **Где в коде:** тесты рядом с `crates/nurbs-core/src/editing/surface_fairing.rs` (proptest в `tests/`).
- **Зависимости:** 844, 846, 224 (proptest-инфраструктура).
- **Критерии приёмки:** для E_membrane, E_plate, E_curv_var и составного E относительная ошибка градиента < 1e-6 на 100 случайных поверхностях; тест в CI, время прогона < 30 с.

#### 852. FFD-lattice: построение решётки [статус: реализовано] [трудоёмкость: L]
- **Суть:** По AABB геометрии строится тензорная B-сплайн-решётка степени (l,m,n); точки модели параметризуются в локальные (s,t,u) решётки (STP-координаты); кэширование (точка → параметры решётки) обязательно — после движения контрольной точки пересчитывается только затронутый спан. Камни — точки вне AABB (расширение решётки), стоимость начальной параметризации для больших мешей.
- **Где в коде:** `crates/nurbs-core/src/editing/deform.rs`.
- **Зависимости:** 853, 78 (ближайшая точка для параметризации — нетривиальных случаев).
- **Критерии приёмки:** деформация при сдвиге одной точки решётки локальна (вершины вне (l+1)³ спанов неподвижны бит-в-бит); кэш параметров инвалидируется только по затронутым спанам; интерактивный FPS на мешах 100k вершин.

#### 853. FFD с B-сплайн-решёткой, не Безье [статус: реализовано] [трудоёмкость: M]
- **Суть:** Локальная поддержка B-сплайна делает правку действительно локальной: сдвиг узловой точки меняет форму в окрестности (l+1)·(m+1)·(n+1) спанов; Безье-решётка тянет весь объём. Пункт — архитектурное ограничение на 852: выбранная структура данных обязана быть B-сплайн-решёткой с узловыми векторами, а не одним тензорным Безье.
- **Где в коде:** `crates/nurbs-core/src/editing/deform.rs`.
- **Зависимости:** 852.
- **Критерии приёмки:** тест локальности (см. 852) доказывает B-сплайн-природу; степени (l,m,n) конфигурируемы; увеличение разрешения решётки через knot insertion не меняет текущую форму.

#### 856. Деформация Барра: bend [статус: реализовано] [трудоёмкость: M]
- **Суть:** Изгиб вокруг оси с радиусом r(y): точка (x,y,z) → (r − (r−x)·cos θ, y₀ + (r−x)·sin θ, z), θ = (y−y₀)/r; область изгиба ограничена полосой y∈[y₀,y₁], за пределами — чистый поворот, иначе геометрия «складывается» сама в себя. Камни — самопересечение при больших углах, потеря объёма (см. 859), корректная обработка контрольных точек vs тесселированных вершин (деформировать надо контрольные точки, иначе теряется точность).
- **Где в коде:** `crates/nurbs-core/src/editing/deform.rs`.
- **Зависимости:** 852 (общая инфраструктура деформаций), 859.
- **Критерии приёмки:** bend балки на 90° совпадает с аналитической дугой в допуске; область вне [y₀,y₁] — чистый поворот (проверка длин); отказ/предупреждение при самопересечении (r < половина толщины сечения).

#### 857. Wire-деформация (Singh–Fiume) [статус: реализовано] [трудоёмкость: L]
- **Суть:** Деформация задана парой кривых: базовая W и целевая W'; точка модели проецируется на W (ближайшая точка), смещение интерполируется разностью W'−W в точке проекции с радиальным затуханием e^(−d²/r²). Подходит для «утолщения по линии» и правки по профилю. Камни — неоднозначность проекции (точка равноудалена от двух участков W), выбор радиуса затухания, скорость: проекция каждой вершины — point inversion, нужен кэш/BVH.
- **Где в коде:** `crates/nurbs-core/src/editing/deform.rs`; ближайшая точка — `distance/`, `foundation/curve_projection/`.
- **Зависимости:** 78 (point inversion), 852.
- **Критерии приёмки:** деформация вдоль W непрерывна (нет скачков между соседними вершинами); точки дальше радиуса r неподвижны в допуске; W = W' → тождественное отображение бит-в-бит.

#### 859. FFD-деформация с сохранением объёма [статус: TODO] [трудоёмкость: M]
- **Суть:** После сдвига контрольных точек решётки вычисляется новый объём замкнутого тела (дивергенцией по граням); остаточная коррекция — одномерный поиск масштаба вдоль средней нормали деформации до |ΔV/V| < 1e-4, чтобы bend не «выкачивал» объём. Камни — коррекция по одной нормали груба при сложных деформациях (может понадобиться поле масштабов); объём по граням требует замкнутого тела — для открытых shell'ов режим неприменим, репортить.
- **Где в коде:** `crates/nurbs-core/src/editing/deform.rs` (пост-проход после bend/FFD); объём — `brep-core`/`geometry-ops` (интегрирование по граням, см. 1031).
- **Зависимости:** 852, 856, 1031 (объём с допуском).
- **Критерии приёмки:** bend балки: |ΔV/V| < 1e-4 после коррекции; на открытом теле — явная диагностика, не молчаливый пропуск; сходимость 1D-поиска < 20 итераций.

#### 860. Hold-line fillet [статус: реализовано] [трудоёмкость: XL]
- **Суть:** Филлет, ограниченный двумя произвольными кривыми на опорных гранях (не трассами rolling ball): сечение — кривая, касательная обеим граням в точках холд-линий (коника через условия касания или G2-сплайн); холд-линии ресемплируются по длине дуги для согласованной параметризации вдоль спайна. Камни — рассинхрон параметризаций (винтообразное сечение), кривые уходят с граней в допуске, вырождение сечения при сближении линий.
- **Где в коде:** `crates/nurbs-core/src/offset/fillet_surfaces.rs` (`hold_line_fillet`, guards на точках линий).
- **Зависимости:** 162, 64 (репараметризация по длине дуги — реализовано), 861.
- **Критерии приёмки:** сечения касательны обеим граням в точках холд-линий (G1-проверка по нормалям); ресемплинг линий синхронизирован (тест на винтовую конфигурацию); NaN-защита входных кривых через `foundation/guards.rs` (есть).

#### 861. Curvature-continuous (G2) fillet [статус: реализовано] [трудоёмкость: L]
- **Суть:** Сечение не дуга, а кривая с согласованной кривизной на концах (сплайн 5-й степени с G2-граничными условиями по кривизнам опорных поверхностей); в модели маркируется отдельным типом, чтобы downstream-операции (offset, shell) знали о непрерывности кривизны и не аппроксимировали дугой. Камни — G2-условия требуют главных кривизн опор в точках касания (133), гребёнка кривизны сечения без перегибов.
- **Где в коде:** `crates/nurbs-core/src/offset/fillet_surfaces.rs`; кривизны — `analysis/surface_shape_operator.rs`.
- **Зависимости:** 162, 133 (реализовано), 860.
- **Критерии приёмки:** кривизна сечения на стыках совпадает с нормальной кривизной опор в направлении стыка (G2-метрика < допуска); атрибут типа филлета сохраняется в B-rep и сериализации; offset G2-филлета не вводит дуговую аппроксимацию.

#### 862. Fillet-overflow: пересечение филлетов до тела [статус: TODO] [трудоёмкость: XL]
- **Суть:** Каскадные филлеты: сначала поверхности филлетов по рёбрам строятся независимо, затем их взаимная обрезка/пересечение (SSI филлет-на-филлет и филлет-на-грань), и только потом булева подрезка тела. Порядок рёбер — по убыванию радиуса, иначе малые филлеты съедаются чужими триммингами. Это самый тяжёлый пункт группы: в вершине сходятся 3+ филлета, нужен overlap-resolution (как в OCCT/Chamfer-makers). Камни — вырожденные тримминги в углах, нестабильность при близких радиусах, зависимость результата от порядка.
- **Где в коде:** `crates/nurbs-core/src/offset/fillet_surfaces.rs` (расширение), SSI — `intersection/ss_intersection/`, булева подрезка — `brep-core`/`geometry-ops`, вершинная сборка — новый модуль `offset/fillet_overlap.rs`.
- **Зависимости:** 162, 860, 861, 160, булевы (группы D–E), 863.
- **Критерии приёмки:** три сходящихся в вершине филлета (куб с r на трёх рёбрах) — замкнутое тело, Эйлер–Пуанкаре выполняется; порядок радиусов не меняет результат в допуске; отказ одного ребра не сносит остальные (863).

#### 863. Fillet-резолвер: graceful failure [статус: реализовано] [трудоёмкость: M]
- **Суть:** Если филлет не строится (self-intersection сечения, радиус > допустимого), ребро откатывается с диагностикой (edge id, точка сходимости, предельный радиус), а не сносит всю операцию: пользователь получает «построено 9 из 12 рёбер, по 3 — пределы». Камни — определение предельного радиуса само по себе итеративная задача (бисекция по r), диагностика должна быть машиночитаемой для UI-подсветки рёбер.
