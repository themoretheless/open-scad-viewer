#### 167. IGES 126/128 — рациональная B-сплайн-кривая и поверхность [статус: TODO] [трудоёмкость: M]
- **Суть:** Импорт/экспорт базовых NURBS-сущностей IGES: entity 126 (Rational B-Spline Curve) и 128 (Rational B-Spline Surface). Парсинг parameter data с учётом IGES-специфики: флаг рациональности, периодичности, нормировка узловых векторов, обработка PROP3 (planar) для кривых. Подводные камни: холостые пробелы/нулевые веса у весов на границах PD-записей, степени > допустимых, нестрогая неубываемость узлов из-за ошибок округления экспортёров.

- **Зависимости:** 16 (сравнение узлов с epsilon), 35 (валидация вектора узлов).
- **Критерии приёмки:** round-trip набора 126/128-сущностей (экспорт → импорт → совпадение контрольных точек/узлов/весов в допуске); корректный импорт 5+ файлов из публичных IGES-корпусов (NIST); отказ с типизированной ошибкой на битом PD.

#### 1073. Auto-repair с audit trail [статус: TODO] [трудоёмкость: M]
- **Суть:** Каждое исправление (snap вершины, re-trim кромки, flip нормали, удаление вырожденной грани, повторный sewing) записывается: {операция, id сущностей, дельта геометрии, обоснование}. #### 1074. Политика отказов импорта [статус: TODO] [трудоёмкость: S]

#### 1075. Импорт как двухпроходный конвейер [статус: TODO] [трудоёмкость: L]

Камни: рефакторинг существующих однопроходных парсеров — объёмная работа; согласованность ошибок проходов.

## Группа H. Скетчер и солвер ограничений (8 пунктов)

#### 1001. DR-планирование графа ограничений [статус: TODO] [трудоёмкость: XL]
- **Суть:** Декомпозиция графа скетча в дерево жёстких кластеров до численного солвера: pebble game по (2,3)-жёсткости Ламана или frontier-метод; солвер сшивает кластеры тремя ограничениями на пару, остаток — ньютоновский fallback. Это фундамент масштабируемости: системы на 10³ примитивов без одного гигантского якобиана. Камни: корректность классификации кластеров, обработка under-constrained подграфов, инкрементальное обновление плана при добавлении ограничения.
- **Где в коде:** `crates/sketch-core/src/` (сейчас — один глобальный солвер в `lib.rs`); новый модуль `dr_plan.rs`.
- **Зависимости:** 1002 (диагностика), 1003 (конвейер).
- **Критерии приёмки:** скетч 1000 примитивов решается < 100 мс; DR-план на известных тестовых графах совпадает с эталонной декомпозицией; добавление одного ограничения не перестраивает весь план (инкрементальность).

#### 1002. Диагностика over/under-constrained [статус: TODO] [трудоёмкость: M]
- **Суть:** DOF-счётчик покластерно (не только суммарно 2N − Σ): переопределённый кластер указывает минимальное множество конфликтующих ограничений (исключаемое множество в pebble game), недоопределённый — список свободных примитивов с остаточными степенями свободы. UX: подсветка конфликта в скетче.
- **Где в коде:** `sketch-core/src/dr_plan.rs` + `Diagnostics` в `lib.rs` (уже есть задел).
- **Зависимости:** 1001.
- **Критерии приёмки:** на скетче с заведомым конфликтом возвращается точное минимальное множество ограничений (тест на 10 конфликтных конфигурациях); under-constrained отчёт перечисляет свободные примитивы; нет ложных срабатываний на well-constrained корпусе.

#### 1003. Стратегии солвера как конвейер [статус: TODO] [трудоёмкость: L]
- **Суть:** Каскад: (1) редукция по DR-плану, (2) локальные аналитические замыкания (треугольники, линия-окружность касания), (3) демпфированный LM на остатке с тёплым стартом. Переход на следующую ступень — только при неудаче предыдущей; логирование (ступень, итерации, невязка). Камни: критерии «неудачи» ступени, тёплый старт LM от текущей геометрии, зацикливание LM — бюджет итераций (п. 1065).
- **Где в коде:** `sketch-core/src/lib.rs` (расширение `solve_with_diagnostics_options`).
- **Зависимости:** 1001, 1008 (нормировка), 1065.
- **Критерии приёмки:** ≥80% типовых скетчей решаются ступенями 1–2 без LM; невязка результата < допуска на всём корпусе; лог ступеней доступен через Diagnostics.

#### 1004. Автоограничения при рисовании [статус: TODO] [трудоёмкость: L]
- **Суть:** Инференс-движок во время drag: кандидаты из BVH радиуса курсора → предложения coincident/horizontal/vertical/tangent/equal/perpendicular; принятое ограничение — полноценное (участвует в DOF). Порог инференса и whitelist типов — настройки, отключение хоткеем. Камни: приоритизация кандидатов (расстояние vs тип), ложные срабатывания в плотных скетчах, хореография UI (это boundary ядро/UI).
- **Где в коде:** `sketch-core/src/inference.rs` (новый) + интеграция с вьюером (`src/`); BVH — переиспользовать `mesh-query`/2D-вариант.
- **Зависимости:** 1001–1003.
- **Критерии приёмки:** типовой сценарий рисования прямоугольника со скруглением: автоограничения предлагаются корректно на каждом шаге; ложных принятий < 5% в UX-тесте; отключение хоткеем работает мгновенно.

#### 1005. Ограничения симметрии и паттернов [статус: TODO] [трудоёмкость: M]
- **Суть:** symmetry(p1, p2, axis) — одно ограничение (4 уравнения, DOF-вклад 2 с учётом оси); линейный/круговой паттерн — ограничение-связка с общими параметрами шага, изменение прототипа пересчитывает копии через солвер; растворение паттерна обратимо. Камни: корректный DOF-вклад (оси тоже имеют степени свободы), паттерны поверх паттернов, производительность на больших паттернах.
- **Где в коде:** `sketch-core/src/lib.rs` (enum Constraint — расширение).
- **Зависимости:** 1001–1003.
- **Критерии приёмки:** symmetry держит DOF-счёт корректным (тест на счётчике 1002); изменение параметра паттерна пересчитывает все копии за один solve; растворение → N независимых примитивов с сохранением геометрии.

#### 1006. Валидация профиля перед экструзией [статус: TODO] [трудоёмкость: M]
- **Суть:** Скетч → профиль после проверок: контур замкнут в топологическом допуске, нет самопересечений (sweep-line по сегментам), вырожденные сегменты удалены, вложенные контуры классифицированы по чётности (острова/дырки), ориентация внешнего — CCW. Диагностика указывает конкретные сегменты-нарушители. Камни: почти-касающиеся сегменты (точные предикаты из группы D), граничный допуск замыкания.
- **Где в коде:** `sketch-core/src/profile_validate.rs` (новый); sweep-line — `planar-geometry` (curve_boolean/pathfinder) или `cad-predicates`.
- **Зависимости:** 153 (точные предикаты), 185 (допуски).
- **Критерии приёмки:** корпус из 100 валидных и 100 дефектных профилей классифицирован без ошибок; диагностика содержит id сегмента-нарушителя; CCW-нормализация проверена знаком площади.

#### 1007. Топологическая устойчивость скетча к rebuild [статус: TODO] [трудоёмкость: L]
- **Суть:** Примитивы скетча имеют persistent id; перестроение сопоставляет грани результата старому набору по (id контура, цепочка примитивов); исчезнувший контур → tombstone, ссылки (филлеты, PMI) получают «dangling reference»-диагностику вместо молчаливого перепривязывания. Камни: разбиение/слияние контуров при rebuild (один контур → два), стабильность id при undo/redo.
- **Где в коде:** `sketch-core/src/lib.rs` (id примитивов) + `brep-topology/src/persistent_naming.rs` (уже есть инфраструктура).
- **Зависимости:** 1006; потребители — 797 (PMI), 883.
- **Критерии приёмки:** сценарий «дырка исчезла при смене размера»: ссылка на её грань — диагностика, не crash; undo/redo сохраняет id; property-тест: rebuild без изменений → тождественное отображение id.

#### 1008. Численный масштаб скетч-солвера [статус: TODO] [трудоёмкость: S]
- **Суть:** Уравнения ограничений нормируются характерным размером (диагональ AABB скетча): иначе квадратичные члены при размерах ~10³ мм душат точность f64. Невязка и критерий сходимости — в нормированных единицах, денормировка на выходе. Камни: нормировка должна обновляться при сильном изменении масштаба в процессе solve.
- **Где в коде:** `sketch-core/src/lib.rs` (обёртка нормировки вокруг солвера).
- **Зависимости:** 1003.
- **Критерии приёмки:** property-тест: один и тот же скетч в шкалах 10⁻⁶…10⁶ сходится за одинаковое (±20%) число итераций с одинаковой нормированной невязкой.

## Группа I. Измерения и массовые свойства (9 пунктов)

#### 1028. Расстояние точка–тело [статус: TODO] [трудоёмкость: M]
- **Суть:** Сервис ядра: closest-point через BVH (broad-phase по AABB граней, узкая фаза — point inversion на поверхности), классификация in/out (ray-parity) для signed distance. Контракт: (расстояние, точка, face id, (u,v)) — все компоненты валидны одновременно. Камни: точки на швах/рёбрах (неоднозначность face id — выбирать детерминированно), вырожденные нормали.
- **Где в коде:** `brep-core/src/distance.rs` (новый); BVH — `mesh-query/src/bvh.rs` (адаптация под B-rep-грани), point inversion — `nurbs-core/src/distance` (п. 78–80, 137).
- **Зависимости:** 78–80, 137, 154 (замкнутость для signed distance).
- **Критерии приёмки:** точность vs аналитические тела (сфера, куб) ≤ 1e-9; signed distance корректен на замкнутых телах (ray-parity тест); детерминизм на швах: два прогона — одинаковый face id.

#### 1029. Минимальное расстояние тело–тело [статус: TODO] [трудоёмкость: L]
- **Суть:** Broad-phase: пара BVH с приоритетной очередью по нижней оценке (branch-and-bound на узлах); narrow-phase: Гаусс–Ньютон по (u₁,v₁,u₂,v₂) от лучшего узла, замкнутые решения для аналитических пар (плоскость-цилиндр). Результат: пара face id + статус (face-face / face-edge / edge-edge). Камни: сходимость GN на почти-параллельных поверхностях, пересекающиеся тела (расстояние 0 — отдельная ветка).
- **Где в коде:** `brep-core/src/distance.rs`; аналитические пары — `brep-core/src/analytic.rs`/`intersections`.
- **Зависимости:** 1028, 133 (главные кривизны для GN).
- **Критерии приёмки:** эталонные пары (два куба, сфера-плоскость) — точность ≤ 1e-9; статус контакта корректен на ребро-ребро кейсе; перформанс: пара тел по 10⁴ граней < 100 мс.

#### 1030. Угол между гранями [статус: TODO] [трудоёмкость: S]
- **Суть:** Диhedral angle вдоль общего ребра: сэмплирование нормалей по длине ребра, отчёт = (min, max, среднее) с положением экстремума. Для свободных поверхностей угол — не скаляр. Камни: знак угла (convex/concave — из группы J/AAG), вырожденные нормали на полюсах.
- **Где в коде:** `brep-core/src/measure.rs` (новый) поверх оценки нормалей `nurbs-core` (п. 104).
- **Зависимости:** 104–105.
- **Критерии приёмки:** аналитические кейсы (две плоскости под 45°, цилиндр-плоскость) — точность ≤ 1e-6 рад; min/max на переменном угле (конус-плоскость) совпадают с аналитикой; отчёт содержит параметр t экстремума.

#### 1031. Длина/площадь/объём с допуском результата [статус: TODO] [трудоёмкость: M]
- **Суть:** Каждая интегральная мера возвращает (значение, оценка погрешности): объём — сходимость гауссовых квадратур при удвоении сетки (Ричардсон), длина — Гаусс–Кронрод. API требует явный относительный допуск. В `brep-core/src/analysis.rs` уже есть `certified_mass_properties`/`MassProperties` — доработать контракт «значение + погрешность» для всех мер и обязательный параметр допуска.
- **Где в коде:** `brep-core/src/analysis.rs`, `nurbs-core/src/analysis` (площадь поверхности — п. 136), `math-core/src/moments.rs`.
- **Зависимости:** 65 (длина дуги), 136 (площадь), 1036.
- **Критерии приёмки:** погрешность по Ричардсону консервативна (истинная ошибка ≤ оценки) на аналитических телах; API без указания допуска не компилируется/ошибка; сходимость квадратур демонстрирует уменьшение оценки при удвоении сетки.

#### 1032. Pick-запрос через BVH с семантическим результатом [статус: TODO] [трудоёмкость: M]
