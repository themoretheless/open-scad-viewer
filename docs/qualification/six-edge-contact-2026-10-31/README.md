# Контактные ветви и замкнутый шестирёберный узел — 2026-10-31

Реализовано в Rust: проверка искривлённых многопролётных контактных ветвей и первое полное замкнутое тело для настоящей шестирёберной вершины с тремя разными радиусами у пар противоположных рёбер. Это ограниченное конструктивное семейство, а не завершение произвольного B-rep fillet.

## Результат

| Контроль | Топология F/E/V | G2-швы | Проверка кривизны граней | STEP / пересечения |
|---|---|---|---|---|
| Исходные профили `[0, 0.25, 0.5]` | 26 / 60 / 36 | 30, точное C2 | Общий интервальный проверяющий код: 26/26 `Within`, верхняя оценка 9.999797797680 мм⁻¹ | OCCT: валидное тело; 0 интерференций |
| Заданные срединные радиусы `[2.6, 2.8, 0.9]` мм | 26 / 60 / 36 | 30, точное C2 | Полная коэффициентная оценка ≤5.526568700397 мм⁻¹ | OCCT: валидное тело; 0 интерференций |

Предел 10 мм⁻¹ сохранён. Во втором контроле общий адаптивный проверяющий код кривизны не запускался повторно: вместо него применяется точная оценка для всей фактической геометрии этого семейства, описанная ниже. `genericCurvatureSkipped:true` сохранён в протоколе. Гладкость относится к 30 швам крыши; сопряжения с исходными вертикальными стенками и основанием остаются острыми.

Заданные радиусы — ненулевые главные радиусы на средней линии перехода вдали от центрального узла. Они не обозначают постоянную круговую кривизну поперёк G2-профиля до плоской грани. Каждое значение назначается двум противоположным рёбрам. Независимое задание всех шести радиусов пока не реализовано.

Для заданных радиусов выполнены:

- свежая интервальная проверка радиуса по коэффициентам, погрешность ≤10⁻⁷ мм;
- независимые проверки тензоров кривизны фактических NURBS-поверхностей в Rust;
- шесть независимых измерений главных радиусов после чтения STEP в OCCT;
- независимое точное интегрирование профилей через Python `Fraction`;
- сравнение объёма с OCCT: ошибка 2.274×10⁻¹³ мм³.

Объём исходного тела: 1532.374489954691 мм³. Объём тела с заданными радиусами: 1515.9954009645191 мм³. Удалено 16.379088990171848 мм³.

## API и сохранность исходников

Основной файл: `crates/brep-core/src/region_replacement/six_edge_corner.rs`.

- `six_edge_corner_stock()` создаёт каноническое исходное тело с шестью настоящими рёбрами в вершине.
- `propose_six_edge_corner_radii(source, [rx, ry, rdiag])` строит кандидат; слово `propose` не означает допуска.
- `inspect_six_edge_graph(source, candidate)` заново проверяет фактические данные тела и его коэффициенты.
- `build_six_edge_corner_radii(source, radii)` возвращает `QualifiedSixEdgeBody` только после полного допуска семейства и свежей общей проверки 3D-рёбер/подъёмов/замкнутости.
- `QualifiedSixEdgeBody` предоставляет геометрию только для чтения. `into_model()` потребляет квалификацию, чтобы изменённая модель не сохраняла старый допуск.

Источник не изменяется. Сохранены определения всех 13 исходных опорных поверхностей; для обрезанных потомков записывается распознаваемая `persist`-связь. Новое тело содержит 19 участков крыши, шесть исходных плоскостей стенок и основание. Корни общего разбиения принадлежат точной двумерной решётке; сварка по близости не используется.

Физический масштаб `138600/262144` мм фиксирован в исходном контрольном теле до операции. Построитель не изменяет масштаб или форму входа для прохождения проверки. Неканоническое исходное тело отклоняется. Параметры профилей используют сетку 2⁻²⁴; преобразование точных рациональных полюсов в binary64 принимается только при буквальном совпадении рационального значения.

## Почему полный допуск проверяет именно сохранённое тело

Крыша задаётся функцией

`z = S · [40 − φx(x) − φy(y) − φd(x+y)]`, `X=Sx`, `Y=Sy`.

Исходное тело использует `|x|`, `|y|`, `|x+y|`. В полосе `[-3,3]` функция φ имеет степень 6 и полюса `[3,2,1,h,1,2,3]`; вне полосы она совпадает с модулем. Каждый переход имеет одинаковые первые две производные с исходной плоскостью на концах полосы. Перекрывающиеся переходы и центральная поверхность строятся совместно одной функцией, а не независимо подгоняются.

Перед выдачей допуска весь фактический `Model` сравнивается с заново построенными точными определениями: поверхности, рёбра, pcurve, контуры, ориентации и роли материала. Старые булевы флаги не используются.

1. Точные целочисленные полуплоскости дают 19 выпуклых ячеек, покрывающих исходный шестиугольник. Для каждой ячейки повторно проверены принадлежность её полиномиальному пролёту, выпуклость и площадь. Внутренности разных состояний полос не пересекаются.
2. На каждом из 30 общих рёбер сравниваются точные рациональные ограничения высоты, двух первых и трёх вторых производных. Проверено 180 тождеств функций на всей длине, а не значений в нескольких точках. Общая регулярная XY-проекция переводит это в C2, следовательно G2 фактических поверхностей.
3. Крыша — однозначный граф над этим разбиением. Стенки стоят над границами выпуклого шестиугольника, основание имеет `z=0`, а высота крыши ≥4S>0. Отображение вертикальных столбцов задаёт вложенное замкнутое тело; все 325 пар граней покрыты этим конструктивным доказательством. Это отдельный класс-специфичный сертификат, а не заявление, что общий поиск самопересечений B-rep теперь решён.
4. Коэффициенты `φ−L` и `φ+L` неотрицательны, поэтому φ≥|L| и материал нового тела вложен в исходный. Объём вычислен точным интегрированием по ячейкам.
5. На полосе `φ''` имеет коэффициенты `(5/6)·[0,h,2−2h,h,0]`. Пусть их максимумы равны μx, μy, μd. Норма гессиана ограничена `max(μx,μy)+2μd`. Метрика графа `I+∇z∇zᵀ≥I`, поэтому абсолютные главные кривизны ограничены этим числом, делённым на S. Для стенок и основания кривизна нулевая. Оценка относится ко всем сохранённым участкам граней; расширения поверхностей вне trim-регионов не подменяют материал.

Общая проверка замкнутости дала `WithinTolerance`. OCCT дополнительно подтвердил 1 solid / 1 shell и ту же топологию. Численный OCCT-поиск уровня 5 не нашёл интерференций. Его собственные поля `nativeExactAbsenceProven:false` и `globalEmbeddingQualified:false` не переписываются: точное нативное доказательство принадлежит описанному выше проверяющему коду, а не OCCT.

## Контактные ветви

`nurbs_core::curve_coordinate_clock::inspect` доказывает строгую монотонность координаты по каждому исходному NURBS-пролёту интервальными производными. Исходные узлы, веса и полюса не заменяются аппроксимацией. Стационарные или неразрешённые интервалы не проходят.

`fillet_contact::branch::inspect` расширен на непараллельные рациональные контакты с переменной шириной полосы и несколькими пролётами на прямоугольных UV-гранях.

`fillet_contact::convex_branch::inspect` добавляет:

- оригинальные выпуклые многоугольные UV-контуры, включая треугольники;
- косые исходные рёбра с линейной UV-pcurve;
- искривлённые контакты и частичные интервалы исходного ребра;
- точные рациональные сертификаты полуплоскостей и доминирования выбранной граничной прямой над остальными;
- свежие проверки обоих реальных подъёмов на исходные поверхности и skin;
- отдельные состояния `BoundPartial` / `BoundFull` / `Unresolved` и общую область исходного параметра.

`topology::propose_bound_edge` подключает этот проверяющий код как ограниченный резервный путь. Геометрический бюджет учитывает предыдущие попытки. Частичная принадлежность не превращается в полную операцию над ребром.

Проверка принадлежности UV-полосы не доказывает единственность продолжения rolling-ball ветви, радиус, G2 или замкнутость тела. Эти свойства допускаются отдельными проверками.

## Воспроизведение

Использован закреплённый Rust nightly, `--offline --manifest-path crates/Cargo.toml`, отдельный `CARGO_TARGET_DIR=output/qualification/central-graph-dev-target`.

Финальные 36 тестов B-rep:

```sh
cargo test --offline --manifest-path crates/Cargo.toml \
  --config 'profile.dev.package.brep-core.opt-level=2' \
  --config 'profile.dev.package.brep-core.debug=0' -p brep-core \
  --test convex_contact_branch --test six_edge_corner --test contact_branch \
  --test contact_topology --test four_edge_corner --test trim_contact_replacement --test central_graph
```

Дополнительно: 3 теста `-p nurbs-core --test curve_coordinate_clock` и 5 тестов `-p nurbs-core --lib graph_trace::tests`. Всего **44**, без сбоев. Это целевые регрессии, не полный тест всего приложения.

Пример `six_edge_corner_diagnostics` принимает каталог вывода. Без дополнительных аргументов выполняет общую проверку кривизны всех граней. Аргументы `radii coefficient` выбирают заданные радиусы и полный коэффициентный сертификат. STEP сохраняется после нативного допуска.

Независимые проверяющие скрипты: `verify-central-graft-step-occt.py`, `verify-step-self-intersections-occt.py`, `verify-six-edge-radii-occt.py`, `verify-six-edge-volume.py`. Для OCCT использовалось локальное окружение OCP 7.7.2; последний скрипт требует только стандартную библиотеку Python.

`body.json` — снимок кандидата до квалификации с `accepted:false`. Авторитетные результаты находятся в `report.json`, `summary.json` и отдельных проверочных протоколах. SHA STEP сверены между всеми независимыми протоколами.
