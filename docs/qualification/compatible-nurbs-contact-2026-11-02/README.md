# Замкнутый G2-контроль на изогнутом NURBS-ребре

Нативный `sew_contact_g2_patch_set` впервые полностью допустил этот новый контактный контроль: **8 граней, 6 новых G2-швов, верхняя граница |κ| 9.867331764661289/mm**, все 28 межгранных пар классифицированы, неопределённых пар нет. Подтверждены фактические exact lifts/joins, корректные trim-регионы и инъективность граней. Это ограниченный конструктивный контроль, а не завершение общего fillet solver.

## Изменение геометрии

Исходное ребро — парабола r(x)=(x,0,7x²/64), представленная полиномиальным NURBS степени 8. Соседние неплоские опоры задают кровлю z=q(x)−h(x)|y|, где q=7x²/64 и h=(280/2¹⁸)x⁴(2−x)⁴. Область источника x∈[−1,3], y∈[−1,1], нижняя грань z=−4.

На x∈[0,2], |y|≤w=1/4 построен патч степени 8×4: z=q(x)−h(x)g(y), где g=w(3/8+3s²/4−s⁴/8), s=y/w. На y=±w функция g совпадает с |y| по двум производным; на x=0,2 нулевые 2-jets h согласуют концы перехода. Коэффициенты заданы точно представимыми двоичными числами. Сохраняемые исходные опоры не перестраиваются.

Контроль действительно меняет форму: высота при (x,y)=(1,0) уменьшается на 0.00010013580322265625 mm. На этом конкретном входе аналитически g≥|y|, h≥0, а новый верх остаётся выше основания; изменение остаётся внутри исходного материала. Общего material/nesting certificate это не заменяет.

`EdgeRadius.radius_mm=1` здесь является топологическим входом fixture; **постоянный геометрический радиус 1 mm не доказан и не заявляется**. Проверяется замкнутая G2-сшивка фактических кривых, не rolling-ball radius law.

## Закрытые неопределённости глобального контроля

До изменения классификатора тот же кандидат проходил замкнутость, G2 и κ≤10/mm, но оставлял пары [0,1], [0,7], [1,7] неопределёнными. Их контакт состоит из нескольких общих рёбер, включая невыпуклый контур. Добавлен `ProjectedTrimNetwork`:

- точная affine-проекция каждого полного исходного носителя с ненулевым детерминантом;
- точная проверка простоты исходных полигонов, пересечений сегментов, частичных совпадений и T-junctions;
- подтверждение общих Edge/Vertex ролей, противоположных сторон внутренности по каждому совпавшему ребру;
- точное winding-классифицирование середины каждого несовпавшего сегмента; без пересечений границ это классифицирует весь открытый сегмент и исключает вложение, в том числе вписанный полигон со всеми вершинами на другой границе.

Предусловия — свежие joint exact-boundary, valid-trim и face-injectivity proofs. Отчёт или Boolean caller-а не разрешает пропустить их. Все арифметические predicates рациональны; округление и близость координат не создают общую топологию. Бюджет **1000 ячеек на пару сохранён**. В новом теле три сетевых сертификата закрыли все оставшиеся пары без изменения его геометрии. Новый kind добавлен в нативный bridge и строгий TypeScript-валидатор.

## Независимый STEP

STEP экспортирован именно из допущенного `ContactPatchBody`. Пример дополнительно требует полного равенства геометрии локально проверенного и глобально допущенного моделей; metadata keys могут различаться.

OpenCascade через cadquery-ocp 8.0.1.0.0 прочитал оба файла как валидные одиночные Solid, с 7/8 гранями. Независимый ray при (1,0) и объём совпали с аналитическими значениями:

| | Источник | Изменённое тело |
|---|---:|---:|
| Объём, mm³ | 34.01287163628472 | 34.012860785590284 |
| Верхняя высота при (1,0), mm | 0.109375 | 0.10927486419677734 |

Объём уменьшился на расчётные 1/92160 mm³. Максимальное наблюдённое расхождение объёма с точной формулой 7.11e−15 mm³ относится только к этому контролю и не является общей точностью движка. BRepCheck не подменяет нативное полное доказательство отсутствия самопересечений.

Сжатые STEP имеют mtime=0 в gzip; SHA исходных файлов и архива записаны в result.json. independent-step.json связан с файлами и хешем независимого измерителя.

## Проверки и воспроизведение

- **29 Rust-тестов**: compatible_contact_body 1, convex_contact_branch 15, embedded_patch_body 4, g2_end_runout 4, polygon_contact_network 3, same_support_partition 2.
- **3 TypeScript protocol tests**, включая отказ при неподтверждённой exact scope, чужих/повторных рёбрах и вершинах, неверных осях и бюджете.
- Нативный `cargo check -p geometry-bridge`, `vue-tsc --noEmit` и MCP `tsc --noEmit` завершились с exit 0.
- Отрицательные геометрические тесты исключают пересечение, вложение/вписанные полигоны, одинаковые области с обратным обходом, неавторизованные контакты, T-junctions, самопересечения и недостаток бюджета. Они включают production-source примитива через тестовый host, без копирования алгоритма.

```sh
CARGO_TARGET_DIR=/tmp/open-scad-trim-g2-20261101 cargo test --offline --manifest-path crates/Cargo.toml --config profile.dev.package.brep-core.opt-level=2 --config profile.dev.package.brep-core.debug=0 -p brep-core --test polygon_contact_network --test compatible_contact_body --test same_support_partition --test embedded_patch_body --test convex_contact_branch --test g2_end_runout -- --nocapture
CONTACT_BODY_STEP=/tmp/body.step CONTACT_SOURCE_STEP=/tmp/source.step CARGO_TARGET_DIR=/tmp/open-scad-trim-g2-20261101 cargo run --offline --manifest-path crates/Cargo.toml --config profile.dev.package.brep-core.opt-level=2 --config profile.dev.package.brep-core.debug=0 -p brep-core --example compatible_contact_body
.venv-cad-step/bin/python docs/qualification/compatible-nurbs-contact-2026-11-02/verify-step.py /tmp/source.step /tmp/body.step --report /tmp/independent-step.json
```

Во время сборки параллельно добавлялись файлы intersection_graph; после их появления устранён один compiler visibility defect: join доступен родительскому модулю через pub(in super::super). Его математическое тело не менялось. Хеши затронутых исходников записаны после финальных проверок; стабильность всего параллельно редактируемого дерева не заявляется.

## Открытая область

Подтверждён один полиномиальный graph-класс с совместимыми концами, прямыми UV-сегментами, простыми контурами без отверстий и точной Cartesian affine-проекцией носителей степени ≤8. Острый предыдущий контроль по-прежнему выдаёт ExpandEndRegion; автоматическая перестройка его концевого региона не выполнена.

Остаются общие рациональные NURBS/произвольные ветви, доказанный закон заданного радиуса, концевые области и сложные узлы с разными радиусами, общая толщина/материальное вложение, обязательные детали/история и P0. Bridge/protocol подготовлены; WASM → worker → новый UI этой проверкой не доставлены. Полный список P0–P3 остаётся активным; fullGoalComplete=false.
