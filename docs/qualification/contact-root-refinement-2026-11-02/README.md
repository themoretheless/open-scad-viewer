# Разбиение общего ребра по корням контактных часов

Добавлен `edge_partition::contact_interval::between_contacts`. Новый путь заново проверяет принадлежность контактной ветви исходному ребру по буквальным исходным опорам и геометрии контактов. Готовые публичные отчёты или flags caller-а не принимаются как разрешение на изменение.

Затем обе корневые полосы общего контактного диапазона переводятся в пространственные интервальные оболочки исходной 3D-кривой. Представители внутри полос служат лишь предложением для авторинга; `feature_ops::edge_partition::split_with_uv_tolerance` заново квалифицирует исходную мировую кривую, все сохранённые дочерние участки и pcurve обеих опор. Сохранённые вершины проверяются относительно всего пространственного образа корневой полосы с локальным допуском исходного ребра, ограниченным общим допуском модели. При любой неполной проверке кандидат не выдаётся.

Результат `ContactInterval` хранит данные приватно, возвращает read-only модель, среднее ребро, общие вершины и их идентичности, корневые полосы/оболочки, границы ошибки и свежий branch-report. `reverify()` заново изолирует контактные часы и строит разделение из сохранённых исходников; сравнивает модель, роли вершин и корневые данные. Исходная модель неизменна.

Это уточнение топологии с сохранением материала, а не удаление секторов грани или построение скругления. Корни определяют станции контакта в исходных часах ребра; это не заявление о прямом пересечении контактной кривой внутри грани с самим исходным ребром.

## Проверки

24 теста прошли: convex_contact_branch 9, root_owned_interval 4, shared_edge_partition 7, embedded_patch_body 4. Новый положительный сценарий проверен для нелинейного полиномиального и рационального хода с неравными весами. Среднее ребро используется обеими исходными гранями и имеет ровно две общие новые вершины с разными устойчивыми идентичностями. Повторное построение воспроизводит модель. Проверены отказ при нулевом UV-бюджете, неподходящий изменённый skin и поддельный устаревший `positions.proven=true`; источник остаётся неизменным.

Границы ошибки сохранённых вершин относительно исходных корней, мм:

- полиномиальный случай: 6.091635000687126e-14 и 1.0859820044856771e-13;
- рациональный случай: 5.221401429160394e-14 и 1.938287884158694e-13.

Это верхние границы на данных контрольных входах, не заявленная общая точность всех операций. Учтено 7765/7779 ячеек соответственно. Branch cells, пространственные корневые оболочки и разбиение используют общий cell ledger; отдельные исходные лимиты UV/exact и квалификации сохраняются. Никакие допуски и бюджеты для зелёного результата не повышены.

Прежние проверки корневых интервалов, авторских trim-отношений, общих разбиений и подготовленного G2-тела/STEP остаются зелёными. Они не доказывают, что новая контактная ветвь уже вставлена в G2-тело.

## Воспроизведение

```sh
CARGO_TARGET_DIR=/tmp/open-scad-trim-g2-20261101 cargo test --offline --manifest-path crates/Cargo.toml --config profile.dev.package.brep-core.opt-level=2 --config profile.dev.package.brep-core.debug=0 -p brep-core --test convex_contact_branch --test root_owned_interval --test shared_edge_partition --test embedded_patch_body -- --nocapture
```

Хеши затронутых файлов записаны после итогового прогона. Лог сжат без времени в gzip-заголовке. Стабильность всех параллельно редактируемых исходников репозитория не заявляется.

## Следующая работа и границы

Путь требует двух раздельных внутренних корней. Полные и касающиеся исходных концов интервалы требуют отдельной транзакции endpoint roles. Применяются прежние ограничения branch ownership: прямые UV-границы выпуклого полигона, строгие исходные часы, подтверждённая инъективность опор и свежие фактические lift-проверки. Произвольные криволинейные UV-границы, частичные CoedgeTrim с независимыми корневыми концами и периодические подъёмы остаются открытыми.

Далее нужно передать эти общие вершины в material-retention сети, обрезать исходные грани, построить концевые/угловые переходы и заново допустить весь результат по G2, кривизне <=10/mm и глобальной геометрии. Здесь не квалифицированы радиус, толщина, объём как математическое доказательство, полное скругление произвольного B-rep, WASM/UI или история. Полная дорожная карта остаётся активной.
