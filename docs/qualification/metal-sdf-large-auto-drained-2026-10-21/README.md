**Проверка корректности завершена; квалификация ускорения заблокирована конкурирующей нагрузкой. A/B не запускался. Production-код не изменён.** Ранее подтверждённое пакетирование небольших SDF-входов сохранено; новых ускорений или изменений порога Auto нет.

## Почему нет вывода об ускорении

Первая серия находится в соседнем `metal-sdf-large-auto-2026-10-21`. На Auto/GPU 49³ два A/A-контроля оказались нестабильными: относительная ширина CI 22,2% и 13,6%; третий — 3,6%. Ни одного A/B после этого не запущено. Медианное время одинакового пути менялось примерно 18 → 12 → 4,7 мс. Вне измерений наблюдалась загрузка GPU 93–98%.

SIGSTOP не отменяет ранее отправленные GPU-команды. В повторный протокол добавлены 15 секунд отсутствия новых конкурентов и не менее пяти секунд фактической загрузки GPU ≤10%, с телеметрией AGX. После этого сфера/GPU 64³ прошла три A/A-контроля: отношения 0,9981 / 1,0016 / 1,0102, ширина CI 1,74% / 1,50% / 2,30%. Это подтверждает стабильность только этих контролей, **не ускорение**.

Следующее окно было прервано внешним SIGTERM: параллельная задача завершила контроллер пауз и исправила общие runners на наблюдение без сигналов конкурирующим процессам. Её изменения сохранены. Все журналы прежних пауз закрыты, восстановление выполнено. См. `output/qualification/test-suspension-20261021/controllers-stopped.json` и `benchmark-runner-fix.json` в рабочем дереве. Исторические hash runners в environment-файлах относятся к версии до этой внешней правки; бинарник и SDF-исходники не менялись.

Текущий runner только наблюдает за чужой работой. Для полноценной квалификации нужно свободное окно CPU/GPU. `observe-controls-sphere-auto-64` сохраняет последнюю попытку дождаться такого окна без остановки процессов. `summary.csv` сохраняет все полученные контрольные оценки; `status.json` явно запрещает считать работу подтверждённым ускорением.

## Повторение

Из корня репозитория после завершения конкурирующих сборок, тестов и GPU-бенчмарков:

```sh
python3 docs/qualification/metal-sdf-large-auto-drained-2026-10-21/run.py /absolute/path/to/sdf_core-test-binary
```

Бинарник должен содержать `gpu::small_batch_tests::paired_large_polygonize`. Сначала выполняются три AA-контроля каждого из семи случаев; только после прохождения всех gates запускаются AB+AA. Повторения создают новые каталоги и сохраняют предыдущие попытки. SHA-256 бинарника/исходников фиксируются до и после; повторная сборка во время измерений запрещена. Protocol: `protocol.md`; текущий режим конкуренции — observation-only, исторические описания STOP относятся к уже завершённым попыткам. Полученные AB-интервалы нужно проверить отдельно: только стабильные контроли и нижняя граница 95% CI >1 во всех трёх окнах подтверждают новый выигрыш. CPU и >4 КиБ — контроли неизменённого пути.

Последняя observation-only попытка завершилась по 120-секундному пределу: свободного окна не было. Наблюдалось 62 различных PID конкурирующей работы; максимальная загрузка GPU 99%. Ни одного измерительного вызова в этой попытке не запущено. Все журналы закрыты, оставшихся остановленных процессов с совпадающей исходной идентичностью нет. Тест `scripts/tests/test_benchmark_noninterference.py` прошёл.
