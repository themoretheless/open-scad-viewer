# Исправление отказа корпуса после Boolean и независимые STEP-измерения

Свежий прогон кронштейна, фланца и корпуса обнаружил регрессию: корпус после Boolean difference получал `BREP_LAYERED_FILLET_REFUSED / Source has no proven common prism frame`. Боковые геометрически прямоугольные грани имели 5–6 топологических рёбер из-за разбиения общих границ. Распознавание требовало ровно четыре.

`prism::side_is_proven` теперь проверяет покрытие четырёх сторон прямоугольной trim-области цепочками: постоянная граничная координата, одинаковое направление, точные стыки без щелей/перекрытий и независимое совпадение каждого исходного ребра с соответствующим ограничением изокривой. Прежние допуски совпадения/ограниченная нормализация системы координат не расширены. Явное метаограничение полного натурального диапазона не меняет результат; частичные диапазоны и периодические подъёмы не получают допуска без отдельного доказательства.

Слоистое распознавание также принимает полный нижний профиль из нескольких уже проверенных рёбер, сохраняя их направленные исходные кривые. Кривые не заменяются bounding box или display mesh. Небольшая щель и авторское искажение сверх допустимого округления по-прежнему вызывают отказ.

## Проверки

- **11 нативных тестов прошли**: новые проверки разбиения сторон/нижнего профиля, полного метаограничения, щели при увеличенном model tolerance и реального корпуса Boolean → R1; прежние повёрнутые/отражённые призмы, отверстия и искажения.
- **6 Python-тестов прошли** в обычном и оптимизированном (`-O`) режимах. Исправлена возможность ложного успеха пустого STEP-манифеста. Теперь обязательны все три детали в обоих объявленных состояниях, разные файлы, SHA-256, согласованные роль/скругление/положение; CLI с пустой матрицей не создаёт успешный отчёт до загрузки OpenCascade. Критические проверки не зависят от assert.
- Независимый OpenCascade через cadquery-ocp 8.0.1.0.0 прочитал **6 свежих STEP-файлов**: исходное и перемещённое/скруглённое R1 состояние каждой детали. Все тела валидны, содержат по одному Solid, bounding box и объёмы в объявленных допусках. Прошли **24 измерительных сечения** стенок, отверстия, дна, высоты и радиусных участков.
- Максимальная наблюдённая ошибка этих сечений — **7,105427357601002e-15 мм**; максимальное расхождение объёма — **1,6495405361638404e-6 мм³**. Это результаты данных измерений, не общая гарантия точности и не проверка всей толщины стенки.

## Как получена текущая матрица

Исходные B-rep и их размещение импортированы из зафиксированного WASM `cccc05ce27e15ded848ce27131a6b9d016617115ca7e574870c32742359192e5`. Скругления и STEP-экспорт выполнены **текущим нативным Rust-мостом**, а не этим старым WASM. `scripts/check-cad-parts-native-bridge.py` проверяет допуск native feature, неизменность входов и хеш исполняемого файла, затем пишет полную матрицу. `scripts/verify-cad-fresh-part-dimensions.py` и `scripts/verify-cad-step-occt.py --no-preview` независимо измеряют её. Манифест измерений связан SHA-256 с манифестом файлов и версией измерителя.

Это импорт объявленного B-rep JSON → нативная правка → нативный STEP → независимый просмотр/измерение. Это не полный цикл STEP-import в нашем приложении, не 20 смешанных правок, не Undo/Redo/перезагрузка браузера и не UI-построение исходных профилей. Идентичности STEP-представлений отдельно не квалифицированы. Producer оставляет browser/history-qualified флаги false; внешний результат измерений хранится отдельно.

## Доставка остаётся открытой

Опубликованный WASM по-прежнему отказывает этому корпусу; это повторно проверено в published-wasm-enclosure.json. Сборку/доставку WASM и полный сценарий в новом интерфейсе ещё нужно завершить. Общие NURBS-скругления/G2-узлы с независимыми радиусами не закрыты: использованные здесь R1-фичи относятся к прежним ограниченным призматическим/кольцевым классам и не объявляются общими G2-переходами.

## Артефакты и воспроизведение

В step/ находятся неизменённый входной манифест, два независимых отчёта и шесть сжатых STEP. step-archives.json связывает сжатые и исходные SHA-256. native-inputs.json.gz содержит зафиксированные исходные B-rep, без дублирования нативного исполняемого файла. Перед чтением STEP измерителями распакуйте `.step.gz` в новую папку и скопируйте туда manifest.json.

Соберите `cargo build --offline --manifest-path crates/Cargo.toml --config profile.dev.package.brep-core.opt-level=2 --config profile.dev.package.brep-core.debug=0 -p geometry-bridge --example inspect-request` с отдельным CARGO_TARGET_DIR. Затем `python3 scripts/check-cad-parts-native-bridge.py INPUTS.json PATH_TO_INSPECT_REQUEST NEW_OUTPUT`. Измерители запускаются Python из `.venv-cad-step`; матрица должна быть полной.

Хеши шести изменённых файлов не изменились между снимком итогового прогона и окончанием проверок/экспорта. Стабильность всего параллельно редактируемого репозитория не заявляется. Текущий опубликованный WASM-путь не подменён нативной проверкой; полная дорожная карта остаётся активной.
