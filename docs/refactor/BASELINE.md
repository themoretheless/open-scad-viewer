На ветке `main` не было ни одного зелёного прогона `CI` среди последних 60. Причины на коммите `6980c75c7`:

## Профиль и первая оптимизация горячего пути (O4, замер 2026-11-10)

Профиль `bench_validation` (`sample` из macOS, release с `debug = line-tables-only`): верх стека — невстроенный `Vec<f64>::index` (13 % выборок), `SurfaceSampler::evaluate`, `malloc`/`free`, `basis`, `validate_basis`. Причина первого пункта — профиль: `nurbs-core` собирался с `opt-level = "z"`, при котором компилятор почти не встраивает функции.

Сравнение в одном сеансе, попеременно, по два прогона на вариант, медианы 30 наблюдений (мс):

| Случай | `nurbs-core` `"z"` | `nurbs-core` `3` | `nurbs-core` и `brep-core` `3` |
|---|---:|---:|---:|
| validate 12 / 32 / 60 зубьев | 32,8 / 87,6 / 116,5 | 17,0 / 44,9 / 61,1 | 16,3 / 43,1 / 57,4 |
| decode 12 / 32 / 60 зубьев | 16,0 / 42,7 / 55,4 | 15,9 / 42,8 / 55,6 | 15,2 / 40,7 / 52,8 |

Принято: `nurbs-core` с `opt-level = 3` для нативной сборки (`validate` вдвое быстрее). Для `brep-core` выигрыш 1–3 %, профиль не меняется. Браузерное ядро закрепляет `"z"` в `scripts/build-geometry-kernels.mjs`; WASM с новым профилем побайтно совпадает с прежним (sha256 `df42b8af…`). Release-тесты `nurbs-core` и `brep-core` дают прежний результат (2384 из 2384; 1956 и 4 давних падения), прогон release-тестов `nurbs-core` сократился с ~55 до 18 с.

Медианы `validate` в этот день ниже записанных утром (32,8 против 70,8 мс на 12 зубьях при том же профиле): между сеансами разброс большой, сравнивать можно только внутри одного сеанса.
