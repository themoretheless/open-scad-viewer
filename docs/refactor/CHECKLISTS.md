# Чеклисты «метод» и «класс» (строка L8)

По этим пунктам разбираются модули `P1` из `inventory/*.md`. Пороги проверяются линтами clippy, остальные пункты проверяются при чтении.

## Как мерить

```bash
# clippy.toml в отдельном каталоге:
#   cognitive-complexity-threshold = 25
#   too-many-lines-threshold = 100
CLIPPY_CONF_DIR=<каталог> cargo clippy -p <crate> --lib --no-deps -- \
  -A clippy::all -W clippy::cognitive_complexity -W clippy::too_many_lines
```

`--no-deps` нужен, чтобы предупреждения соседних крейтов не мешали. Ратчет `npm run audit:architecture` отдельно держит лимит в 150 строк на функцию и 800 строк на файл `.rs`.

## Метод (функция)

1. Не больше 100 строк, когнитивная сложность не выше 25.
2. Один уровень абстракции: функция либо перечисляет шаги, либо выполняет один шаг. Если шаги делят много состояния, заведите контекстную структуру и сделайте каждый шаг её методом (`Census::collect`, `PairCheck::events`). Если состояния нет, используйте свободные стадии над простыми данными.
3. Не больше 7 параметров. Если их больше, сгруппируйте их в объект параметров (строка L2).
4. Никаких `unwrap`, `expect` и паникующей индексации в продакшен-коде: нарушенный инвариант возвращает ошибку (`?`, `ok_or_else`, `get`). Исключения записаны в `unwraps.md`.
5. У числовых лимитов и допусков есть имена (`const MAX_...`), без голых литералов в логике.
6. При разбиении тексты ошибок и их порядок не меняются, а общий счётчик работы остаётся одним.
7. Если тот же шаг уже есть в соседнем файле, вынесите общее ядро и оставьте тексты отказов вызывающим. Образцы: `overlap_components/atomic_cuts.rs`, `event_nodes/filled_selection.rs`, `event_nodes/filled_containment.rs`.

## Класс (тип и его модуль)

1. Одна ответственность. Если для описания типа нужно «и», это два типа.
2. Поля закрыты (`pub(crate)` или приватные), если тип держит инвариант. Инвариант проверяется в конструкторе, а не у каждого читателя. Отчёты с более чем 15 публичными полями разбиваются на вложенные типы по смыслу (строка L7).
3. Не больше 30 методов на тип. Если их больше, выделите роли в отдельные типы или модули.
4. Модуль зависит только от своего слоя и нижних (`ARCHITECTURE.md`, `scripts/moduleLayers.mjs`). Новые взаимные зависимости модулей одного слоя не появляются.
5. Повторяющийся `match` по одному перечислению в пяти и более файлах переносится в метод перечисления или в trait.
6. Дубликатов нет: `tools/refactor-audit/dupes.py` не находит в модуле клонов длиннее 30 строк.

## Проверка правки

1. `cargo clippy --no-deps` по крейту не даёт новых предупреждений в затронутых файлах. rustfmt запускается только на своих участках.
2. Тесты модуля проходят в изолированной выгрузке HEAD: `cargo test --release -p <crate> --lib <module>` и интеграционные тесты, где упоминается модуль.
3. `node scripts/check-head-builds.mjs` после коммита.
