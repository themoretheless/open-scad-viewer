# Pattern matching в ModelGraph Text

`match` выбирает результат по форме и содержимому значения. Это выражение:
его можно присвоить переменной, вернуть из функции, передать в `show`,
использовать внутри `foreach` и LINQ. Вычисление выполняет Rust.

Готовые исходники: [несколько видов геометрии](../../examples/modelgraph-text/pattern-matching.mg)
и [коробка SKADIS](../../examples/modelgraph-text/skadis-box-linq.mg).

```text
show match part
  2 => print_hook
  1 => body
  _ => [body, assembly_hooks]
```

Ветви проверяются сверху вниз. Сначала сопоставляется шаблон, затем условие
`where`, если оно есть. Вычисляется только результат первой подходящей ветви.
После `=>` можно переносить выражение и писать вложенный `match`.
Отступ тела — два пробела.

Когда ветви нужны промежуточные вычисления, после `=>` можно написать
локальные присваивания и завершить блок `ret`:

```text
radius = match {width:6, height:8}
  {width, height} =>
    area = width * height
    ret area / 2
  _ => 1
```

Переменная `area` существует только внутри этой ветви. Последним выражением
после `ret` может быть вложенный `match`, список или геометрия.

## Шаблоны

| Запись | Что сопоставляется |
| --- | --- |
| `2`, `-3.5`, `"hook"`, `10mm` | Конкретное значение |
| `_` | Любое значение, без нового имени |
| `n` | Любое значение, доступное в ветви под именем `n` |
| `n @ 1..10` | Совпадение вложенного шаблона с сохранением всего значения |
| `1 \| 2 \| 3` | Один из шаблонов |
| `1..5`, `1..<5` | Числовой диапазон; правая граница включена / исключена |
| `[x, y, z]` | Список ровно из трёх элементов |
| `[first, ..middle, last]` | Первый и последний элементы, список оставшихся между ними |
| `[first, ..]` | Первый элемент; остальные пропускаются |
| `{x, y: height}` | Запись с полями `x` и `y`; дополнительные поля допустимы |
| `{x, ..}` | То же разрешение дополнительных полей, записанное явно |
| `{x, !}` | Запись только с полем `x` |
| `int(n)`, `str(s)`, `length(n)` | Тип и вложенный шаблон значения |

Шаблоны можно вкладывать друг в друга:

```text
size = match {kind:"box", dimensions:[20mm,30mm,40mm]}
  {kind: "box", dimensions: [w, d, h]} where h > 0mm => w*d*h
  _ => 0mm*0mm*0mm
```

Здесь строка `"box"` — метка обычной записи. Это не объявление отдельного
DU-типа: текущий язык использует структурное сопоставление записей.

## Привязки, условия и альтернативы

```text
radius = match [0,7]
  [0, n] | [n, 0] where n > 0 => n
  _ => 1
```

Каждая альтернатива одной ветви обязана объявлять одинаковый набор имён.
`[0, n] | [n, 0]` допустимо, `[x] | [y]` — ошибка. Внутри одного шаблона
имя объявляется только один раз; `[x, x]` не означает проверку равенства.
Для неё используйте `[x, y] where x == y`.

Первая совпавшая альтернатива задаёт привязки. Если условие `where` затем
ложно, проверяется следующая ветвь целиком. Другие альтернативы уже
совпавшей ветви повторно не перебираются.

Условие может использовать новые имена и внешние переменные. `&&` и `||`
вычисляются с коротким замыканием:

```text
ratio = match [0,8]
  [x, y] where x != 0 && y/x > 1 => y/x
  _ => 0
```

Привязки существуют только в условии и результате своей ветви. Они могут
затенять внешнее имя, но не меняют его. Голое имя в шаблоне всегда создаёт
привязку; для сравнения с внешней переменной пишите новое имя и `where`:

```text
wanted = 2
result = match 2
  n where n == wanted => 10
  _ => 0
```

## Списки и записи

Списочный шаблон без `..` требует точной длины. С `..` он требует не менее
стольких элементов, сколько явно указано до и после остатка. Остаток может
оказаться пустым. В одном списочном шаблоне допускается один `..`.

```text
total = match [2,3,4,5]
  all @ [first, ..middle, last] => first + middle.sum() + last
  [] => 0
  [single] => single
```

`[]` сопоставляет только пустой список; `[..items]` — любой список.
Имя после `..` получает список, даже если в нём один элемент.

У записи по умолчанию проверяются только перечисленные поля. `{x, !}`
требует точного набора полей, `{!}` — пустую запись. Обычные `{}` и `{..}`
сопоставляют любую запись. Порядок полей значения не влияет на результат.
Для сохранения всех полей используйте `whole @ {x}`, затем `whole.y`.

## Типы и единицы

| Типовой шаблон | Значения |
| --- | --- |
| `int(n)` | Безразмерное целое число |
| `f64(n)`, `f32(n)` | Безразмерное число; целые тоже подходят |
| `str(s)` | Строка |
| `length(n)` | Длина с единицами |
| `angle(n)` | Угол с единицами |
| `list(xs)` | Список |
| `record(r)` | Запись |

Это проверка значения, не преобразование типа. Например, `int(n)` не
округляет дробь, а `length(n)` не приписывает миллиметры обычному числу.
`f32` и `f64` здесь не различают исходную разрядность литерала.
Внутрь можно поставить другой шаблон: `list([first, ..tail])`,
`record({kind:"box", size})`, `int(n @ 1..10)`.

Результаты `match` можно передавать в функции с типами `str`, `Vec<T>` и
структурами. Проверка аннотации сохраняется, даже если функция не использует
аргумент. Списки координат можно передать целиком в `box`, `rectangle`,
`translate`, `rotate` и `scale`: длина списка и единицы проверяются при
вычислении.

Суффиксы учитываются: `10mm` совпадает с `1cm`, но не с `10deg` и не с
безразмерным `10`. Диапазоны требуют совместимых размерностей границ:
`5mm..2cm` допустим, `5mm..20deg` — ошибка. Несовместимая размерность
самого проверяемого значения означает отсутствие совпадения.
Числа сравниваются без дополнительного допуска на погрешность; для допуска
используйте условие `where` с подходящими границами.

## Геометрия, foreach и LINQ

```text
// @modelgraph-text/1
items = [{kind:"box",size:[2,3,4],x:0},{kind:"sphere",radius:2,x:10}]

parts = foreach item in items
  yield match item
    {kind: "box", size: [w, d, h], x} => box([w,d,h]).translate([x,0,0])
    {kind: "sphere", radius: r, x} where r > 0 => sphere(r).translate([x,0,0])
    _ => []

show parts
```

Здесь `[]` возвращает пустую геометрическую коллекцию и пропускает элемент.

Та же конструкция работает в проекции:

```text
radii = [0,1,2,3].select(value => match value
  0 => 1
  n @ 1..3 => n*2
  _ => 1)

show radii.select((r,i) => sphere(r).translate([i*15,0,0]))
```

## Ошибки и границы реализации

Последняя ветвь `_` удобна, но не обязательна. Если ни один шаблон с условием
не подходит, вычисление завершается ошибкой, а не возвращает `null` или ноль.
Совпадение конкретного значения проверяется при вычислении; статического
доказательства полноты всех возможных вариантов пока нет.

Неактивные результаты и условия не вычисляются, но весь исходный текст
должен оставаться синтаксически корректным. Бюджеты списков, глубины и числа
шагов ModelGraph сохраняются. `match` не добавляет мутацию, IO, исключения,
асинхронность, регулярные выражения, пользовательские extractors или
отдельную систему объявлений DU.
