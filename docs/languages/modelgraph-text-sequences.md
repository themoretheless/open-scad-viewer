# foreach и LINQ в ModelGraph Text

Вычисления выполняет Rust. Списки могут содержать числа с единицами, строки,
вложенные списки и записи. Геометрию создавайте последним шагом `.select()`
или через `yield`. Параметры пересчитываются при изменении модели.

```text
// @modelgraph-text/1
param hook_count: 3 range 2..5

positions = (0..<hook_count)
  .select(i => {x: i * 40, radius: 2 + i})
  .orderBy(p => p.x)

hooks = foreach p in positions
  height = p.radius * 3
  yield cylinder(p.radius, height).translate([p.x,0,0])

show hooks
```

## foreach

Это выражение, возвращающее список значений или коллекцию геометрии.
Отступ — два пробела; тело заканчивается одним `yield`. Скобки вызовов
остаются на строке последнего аргумента.

```text
values = foreach i in 0..<10
  x = i * 2
  continue if x == 2
  break if x >= 8
  yield x
// values: [0,4,6]
```

Локальные `name = expression` неизменяемы и не выходят из блока.
`continue if` пропускает элемент, `break if` завершает текущий цикл.
Они проверяются в порядке объявления: пропущенный элемент не достигает
последующих проверок. Можно писать `where condition` в теле для фильтрации.
Безусловное завершение/пропуск записывается `break if 1` / `continue if 1`.

Короткая форма и фильтры заголовка:

```text
sizes = foreach x in 0..<8 let size = x + 1 where size > 3 => size
parts = foreach (i,x) in enumerate(sizes)
  yield sphere(x).translate([i*20,0,0])
```

Вложенные циклы:

```text
parts = foreach x in 0..<3
  yield foreach y in 0..<2
    yield box([2,2,2]).translate([x*5,y*5,0])
show parts
```

Для чисел вложенный `yield foreach` сохраняет вложенные списки; `.flatten()`
снимает один уровень. Для геометрии вложенные коллекции дают отдельные части.
`yield [sphere(1), box([2,2,2])]` создаёт несколько частей за итерацию.
Можно присвоить результат, вернуть его из функции или написать `foreach`
на верхнем уровне вместо `show`: этот цикл становится текущим выводом сцены.
Если выводов несколько, действует последний; объединяйте их явно через `show`.
Внешней мутации, побочных эффектов и произвольных imperative-блоков здесь нет.

## Лямбды и цепочки

```text
result = [4,5,6]
  .where((value,index) => index > 0)
  .select((value,index) => value + index)
  .sum()
// 12: после where индексы начинаются заново

sum = [1,2,3].aggregate(10, (acc,x) => acc + x)
// 16
```

Фильтры, проекции, ключи и предикаты допускают `x => …` или
`(x,index) => …`. Индекс относится к входу данной операции.
`aggregate` / `reduce` / `scan` принимают ровно `(acc,x)`.
Предикаты поддерживают `&&`, `||` и `!`, с коротким замыканием.
Лямбды захватывают лексическое окружение; объявленную лямбду можно передать
по имени. Используйте `at(list,index)` или `.elementAt(index)` для доступа
к элементу, `.field` — к полю записи.

| Операции | Семантика |
| --- | --- |
| `where(predicate)`, `filter(predicate)` | Фильтрация с сохранением порядка |
| `select(selector)`, `map(selector)` | Одно значение на элемент; допускается геометрия |
| `selectMany(selector)`, `flatMap(selector)` | Объединение списков результата; допускаются геометрические коллекции |
| `orderBy(key)`, `orderByDescending(key)` | Стабильная сортировка; ключ вычисляется один раз на элемент |
| `thenBy(key)`, `thenByDescending(key)` | Дополнительный ключ сразу после сортировки, до 8 ключей |
| `take(n)`, `skip(n)` | Первые n / пропуск n; n неотрицательное целое |
| `takeWhile(predicate)`, `skipWhile(predicate)` | Работа с начальным непрерывным участком |
| `chunk(n)`, `window(n)` | Непересекающиеся пачки / скользящие окна; n положительное |
| `reverse()`, `flatten()` | Разворот / снятие одного уровня вложенности |
| `concat(other)`, `append(x)`, `prepend(x)` | Соединение / добавление элемента |
| `distinct()`, `distinctBy(key)` | Первое вхождение каждого значения/ключа |
| `union(other)`, `intersect(other)`, `except(other)` | Операции над наборами, без повторов, с сохранением порядка первого входа |
| `zip(other)` | Пары `[left,right]`; длины обязаны совпадать |
| `enumerate()` | Пары `[index,value]` |
| `groupBy(key)` | Записи `{key, items}`; порядок групп и элементов — порядок первого появления |
| `join(inner,outerKey,innerKey,result)` | Соединение по равным ключам; результат `(outer,inner) => …` |
| `groupJoin(inner,outerKey,innerKey,result)` | Результат `(outer,matches) => …`; включает пустые matches |
| `count(predicate?)`, `length()` | Количество элементов |
| `any(predicate?)`, `all(predicate)` | 0/1; предикат прекращается после известного ответа |
| `contains(value)` | Проверка наличия по значению |
| `first(predicate?)`, `last(predicate?)`, `single(predicate?)` | Поиск; отсутствие результата — ошибка, у single ошибка и при нескольких совпадениях |
| `firstOrDefault(value?)`, `lastOrDefault(value?)` | Значение по умолчанию, без аргумента — 0; фильтр пишите отдельно через where |
| `defaultIfEmpty(value?)` | Одноэлементный список для пустого входа, по умолчанию `[0]` |
| `elementAt(index)`, `at(index)` | Нулевой индекс, ошибка при выходе за границы |
| `sum(selector?)`, `min(selector?)`, `max(selector?)`, `average(selector?)` | Числовые агрегаты с проверкой единиц |
| `aggregate(initial,callback)`, `reduce(initial,callback)` | Свёртка слева |
| `scan(initial,callback)` | Список последовательных аккумуляторов, без initial |
| `toArray()` | Явное завершение цепочки; списки уже вычисляются как массивы |

На пустом списке `sum()` даёт безразмерный 0, `any()` — 0, `all()` — 1,
`aggregate()` — initial, `scan()` — `[]`. `min/max/average` требуют элементы.
Сравнение чисел проверяет единицы, строк — регистрозависимое лексикографическое,
списков и записей — по содержимому. Геометрия и функции не являются ключами.

```text
left = [{id:1, size:3}, {id:2, size:5}]
right = [{id:2, offset:10}, {id:2, offset:20}]
matches = left.join(right, a => a.id, b => b.id,
  (a,b) => {size:a.size, x:b.offset})
show matches.select(p => sphere(p.size).translate([p.x,0,0]))
```

## Ограничения исполнения

Это ограниченный CAD-язык, а не полный LINQ из .NET. Промежуточные списки
вычисляются последовательно и материализуются. Короткое замыкание `any/all/first`
и `takeWhile` не отменяет уже вычисленный предыдущий `select`.
`join/groupJoin` сейчас используют сравнение ключей, а не хеш-индекс.
Сортировка кеширует ключи, элементы списков ссылаются на общие неизменяемые данные.

Сохраняются бюджеты: до 256 элементов списка, 16384 выделенных элементов за
вычисление, ограничение глубины и числа шагов. Это не параллельный `foreach`,
не `async`, нет IO. Ограничения геометрии (128 узлов графа и бюджет мешей)
тоже продолжают действовать. Геометрические коллекции преобразуйте внутри
`select/yield`, до их создания; сортировать или фильтровать уже созданные
меши как данные нельзя. NURBS-текст сохраняет свой отдельный набор поддержанных
выражений; эти примеры рассчитаны на основной ModelGraph/1.
