# mechanics-core: обзор экосистемы и дорожная карта фич

Дата: 2026-10-04. Метод: тематические срезы GitHub (truss solver, structural analysis,
section properties, FEA, topology optimization, browser solvers) — ~750 репозиториев
просмотрено по метаданным, 15 ключевых разобраны по README/документации.

## 0. Что уже есть в mechanics-core

| Модуль | Возможности |
|---|---|
| `lib.rs` (sections) | Площадь, центроид, Ixx/Iyy/Ixy, Wx/Wy, min_wall сканлайн, σ = Mc/I + N/A, von Mises, FoS; послойный прогон по z с weakest-link |
| `truss.rs` | Линейные 3D шарнирные стержни (только ось), ≤125 узлов / ≤400 стержней, явные нулевые закрепления, узловые силы |
| `truss_loads.rs` | Раскладка wrench (сила+момент) на узлы: равные доли + минимальная по норме пара сил |
| `print_strength.rs` | Скрининг осевых напряжений против пределов растяжения/сжатия, до 32 загружений, SF |
| `thermal_strength.rs` | Билинейная интерполяция измеренных свойств по температурам сопла/службы, без экстраполяции |
| `bonded_solid.rs` | Явный Tet4 + нулевой толщины связи shell/infill, малые деформации, скрининг инициации |

Контракты проекта: мм / Н / МПа; не сертификат прочности; не держит CAD-хендлы;
nalgebra (плотные матрицы); жёсткие лимиты входа.

## 1. Карта фич экосистемы

### 1.1 Стержневые элементы и опоры
- **Pynite** (Python, 752★): 3D стержни, P-Δ, модальный анализ, pushover, точечные и
  линейно-распределённые нагрузки на стержень, load cases + комбинации, tension-only /
  compression-only элементы, пружинные элементы и опоры (двусторонние и односторонние),
  пластины DKMQ и rect, автоматические внутренние узлы (physical members), PDF-отчёты.
  https://github.com/JWock82/Pynite
- **anaStruct** (Python, 468★): 2D рамы/фермы, шарнирные/жёсткие/пружинные опоры,
  поворотные пружины, q-нагрузки в локальном и глобальном направлениях, собственный вес,
  геометрическая нелинейность, load cases/комбинации, базы профилей EU/US/UK.
  https://github.com/anastruct/anaStruct
- **edubeam** (Vue/TS, 53★): балки Тимошенко (учёт сдвига) + осевые фермы в одной модели,
  шарниры на концах, наклонные опоры, заданные перемещения, осадка опор, равномерные и
  градиентные температурные нагрузки, трапециевидные распределённые нагрузки.
  https://github.com/janvorisek/edubeam (решатель вынесен в пакет ts-fem)
- **pycba** (Python, 128★): неразрезные балки любого числа пролётов; опоры pin/roller/
  fixed/пружины поступательные и поворотные; осадки; внутренние шарниры;
  Euler–Bernoulli, Timoshenko, непризматичные (переменный EI), балка на Винклере.
  https://github.com/ccaprani/pycba

### 1.2 Сечения
- **section-properties** (Python, 559★): полный набор — первые/вторые моменты, главные
  оси, упругие и пластические моменты сопротивления, пластический центроид, shape factor,
  радиусы инерции, **постоянная кручения J**, **секториальная постоянная Cw**,
  **центр изгиба** (упругий и по Trefftz), **сдвиговые площади**, составные сечения,
  напряжения по сечению, круги Мора, импорт DXF/3dm, библиотека стандартных профилей.
  https://github.com/robbievanleeuwen/section-properties
- **edubeam**: редактор полигонального сечения с отверстиями, главные оси и эллипс инерции.
- **pyCUFSM** (Python, 70★): конечно-полосный анализ потери устойчивости тонкостенных
  сечений (cold-formed steel). https://github.com/brookshsmith/pyCUFSM

### 1.3 Типы анализа
- Линейная статика — везде.
- **P-Δ второго порядка**: Pynite, stabileo.
- **Линейная потеря устойчивости** (геометрическая жёсткость, собственные формы): stabileo.
- **Модальный анализ** (частоты/формы): Pynite, pycba, stabileo.
- **Пластика до разрушения** (пластические шарниры, механизм разрушения): pycba; pushover
  стальных рам: Pynite.
- **Геометрическая нелинейность ферм** (инкрементальные шаги, адаптивный шаг,
  load-proportionality-factor, path plots): trusspy (63★), nfem (23★, TUM teaching).
  https://github.com/adtzlr/trusspy https://github.com/StatikTUM/nfem
- **Подвижные нагрузки, линии влияния, envelope, нормативные нагрузки мостов**
  (AASHTO HL-93, Eurocode LM1/LM71, и др.): pycba; moving loads: stabileo.
- **Кинематический анализ / детект механизмов**: stabileo (матричный ранг), edubeam
  (подсветка шарниров/опор, образующих механизм, вместо «singular matrix»), pycba
  (pre-solve mechanism detection).

### 1.4 Браузерные решатели (ближайшие соседи по архитектуре)
- **stabileo** (TypeScript + Rust→WASM, 82★): direct stiffness 2D/3D, MITC4/DKT пластины,
  sparse Cholesky, живой пересчёт, пошаговый метод жёсткости для обучения, валидация по
  NAFEMS + ANSYS Verification Manual + Code_Aster. Движок умеет больше, чем выставлено
  в UI: corotational, staged construction, cables, contact/gap, Guyan/Craig–Bampton.
  https://github.com/lambdaclass/stabileo
- **edubeam**: весь решатель в браузере, модель в URL, экспорт SVG/PNG/CSV/JSON.

### 1.5 Оптимизация и дифференцируемость
- **topy** (578★), **beso** (471★, CalculiX), **TopOpt.jl** (225★): SIMP/BESO, truss и
  continuum топоптимизация, stress constraints.
- **slientruss3d** (34★): оптимизация ферм + генерация датасетов, GA/GNN.
- **jax-fem** (767★), **torch-fem** (127★): дифференцируемый МКЭ для оптимизации.

### 1.6 AM-ниша (родная для print_strength)
- **GPUCADforAM** (20★): CAD для AM, lattice + FEA на GPU. Прямых конкурентов
  «прочность печатной детали по сечениям слоёв» почти нет — это дифференциация проекта.
  https://github.com/DESIGN4ADDITIVE/GPUCADforAM

## 2. Gap-анализ: что взять

### P0 — без смены парадигмы (плотные матрицы, тот же контракт)
1. ✅ **Реализовано** (`crates/mechanics-core/src/frame.rs`, op `frame_solve`).
   **Балочные элементы Тимошенко 3D** (12×12, локальные оси, шарниры концов через
   статическую конденсацию) рядом с truss → frame. Источник формул: Logan;
   снято главное ограничение «только ось, без изгиба».
2. ✅ **Реализовано** (там же). **Нагрузки на стержень**: точечная сила/момент по
   длине, равномерная и трапециевидная q (локальные/глобальные оси); работо-
   эквивалентные узловые (Hermite + 4-точечный Гаусс) + эпюры N/V/T/M по 21
   станции на стержень.
3. ✅ **Реализовано** (`crates/mechanics-core/src/combos.rs` + `frame::solve_envelopes`,
   op `frame_envelope`). **Load cases → комбинации → envelope** как типы данных:
   именованные комбинации с факторами (до 32 загружений / 64 комбинаций),
   min/max каждого скаляра с индексом governing-комбинации; жёсткость
   факторизуется один раз на все загружения (сборка/Чолецкий вынесены из solve).
4. ✅ **Реализовано** (`frame::Support`, op'ы `frame_solve`/`frame_envelope`).
   **Пружинные опоры и односторонние связи**: двусторонние пружины (диагональ
   жёсткости), односторонние пружины и жёсткие контакты (lower/upper) с
   итерационным активным набором (снятие по знаку реакции, включение по
   проникновению). С односторонними связями суперпозиция невалидна, поэтому
   envelope переключается на прямое решение каждой комбинации.
5. ✅ **Реализовано** (`crates/mechanics-core/src/section.rs`, главные оси — в отчёте
   op `structural_sections`, кручение — op `section_torsion`). **Главные оси и угол
   поворота сечения** из тех же контурных интегралов: I1/I2, угол, радиусы инерции
   (эллипс инерции), главные моменты сопротивления; **J**: открытые сечения Σbt³/3,
   однозамкнутые — Бредт 4A²/∮ds/t — без МКЭ.
6. ✅ **Реализовано** (`crates/mechanics-core/src/diagnostics.rs`, op'ы
   `truss_diagnose`/`frame_diagnose`, TS `structuralDiagnostics.ts`).
   **Диагностика механизмов**: при сингулярности ошибка FRAME/TRUSS_SINGULAR
   называет DOF («node 1 y unrestrained» / «in a mechanism», нормированный
   пивот); публичные `diagnose` возвращают структуру (незакреплённые DOF по
   нулевым диагоналям, DOF механизма по нуль-моду ручного LDLᵀ) плюс запас
   устойчивости (минимальный нормированный пивот) для устойчивых схем.

### P1 — новые типы анализа
7. ✅ **Реализовано** (`crates/mechanics-core/src/buckling.rs` + `frame::buckling` /
   `truss::buckling`, op'ы `frame_buckling`/`truss_buckling`, TS `solveFrameBuckling`/
   `solveTrussBuckling`). **Линейная потеря устойчивости** балок и ферм: Kg
   (EB-форма для стержней с конденсацией шарниров через то же подпространство;
   поперечная N/L·(I−ddᵀ) для ферм) из осевых сил референсного загружения;
   (K + λKg)φ = 0 через эквилибрированный Чолецкий + симметричный eigen
   (λ = 1/μ, знак λ = направление нагрузки, до 8 мод по |λ|). Односторонние
   связи отклоняются (нелинейный референс). Проверено: консоль и шарнирная
   стойка — Эйлер с точностью <0.5%, тоггл фермы — замкнутая форма 1e-6.
8. ✅ **Реализовано** (`MassModel` в `mechanics-core`, `frame::modal` / `truss::modal`,
   op'ы `frame_modal`/`truss_modal`, TS `solveFrameModal`/`solveTrussModal`).
   **Модальный анализ**: собственные частоты и формы через то же eigen-ядро, что и
   устойчивость ((K − ω²M)φ = 0 как buckling с `geometric := −M`). Балки:
   консистентная масса EB (изгиб 156/22L/54/13L над 420, ось ρAL/6, кручение
   ρ(Iyy+Izz)L/6) и сосредоточенная; фермы: изотропная ρAL/6·[[2I,I],[I,2I]] и
   lumped по узлам. Проверено: консоль 4 элемента — f1 = 279.77 Гц (две изгибные
   моды), кручение 775.3 Гц, ось 1250 Гц; масштабирование /√2 по плотности точное.
9. ✅ **Реализовано** (`frame::collapse` в `mechanics-core`, op `frame_collapse`,
   TS `solveFrameCollapse`). **Пластический шарнир / collapse**: инкрементальный
   анализ пропорционального загружения — упругое решение → первый конец
   стержня, достигший Mp (`plasticMomentsNMm`, null = упругий стержень) →
   изгибный шарнир (release ry/rz, кручение остаётся) → повтор до механизма.
   Моменты накапливаются по шагам (момент в шарнире держится на Mp);
   одновременные шарниры группируются с допуском 1e-6. Статусы:
   mechanism / hingeLimit (бюджет до 256) / elasticUnlimited. Шарниры только
   на концах стержней — при распределённых нагрузках мельчить сетку, где
   ожидается пролётный шарнир. Проверено на классике с точными значениями:
   консоль λ = Mp/(P·L), propped cantilever λ = 6Mp/L (первый шарнир
   16Mp/3L), fixed-fixed λ = 8Mp/L (4 шарнира одновременно).
10. ✅ **Реализовано** (`section::thin_walled_open` в `mechanics-core`, op
    `thin_walled_section`, TS `thinWalledOpenSection`). **Тонкостенное сечение
    полностью**: центр изгиба, Cw и сдвиговые площади по срединной линии из
    полос (ветвление I/H через автоматическое разбиение в T-узлах, снаппинг
    концов 1e-9·span; граф — одно дерево, петли отклоняются). Сдвиговые потоки
    q=0 на свободных концах с консервацией в узлах, в главной центральной
    рамке; центр изгиба из момента потоков, сдвиговые площади V²/∫q²/t ds,
    секториальная ω от центра изгиба со средней нормировкой, Cw = ∫ ω̄² t ds —
    все интегралы аналитические по прямым рёбрам. Проверено: двутавр (центр
    изгиба = центроид, Cw = Iy·h²/4, As₂ ≈ 0.9·A_стенки), швеллер
    (e = 3b²/(h+6b), Cw = t·b³h²/12·(2h+3b)/(h+6b) — точно), уголок (центр
    изгиба в углу, Cw ≈ 0).
11. ✅ **Реализовано** (`frame::influence` в `mechanics-core`, op
    `frame_influence`, TS `solveFrameInfluence`). **Линии влияния / подвижная
    нагрузка**: точное решение для силы `forceN` в каждой позиции (member,
    atMm; до 1024) — без приёмов взаимности, поэтому пружины и шарниры ведут
    себя как в `frame_solve`. Цели: перемещение/поворот узла, реакция
    (только закреплённый DOF), результант сечения в точной точке (не
    интерполяция сетки эпюр): axial/shearY/shearZ/torsion/momentY/momentZ.
    Проверено: двухопорная балка — линия реакции 1−x/L, треугольник момента
    в середине a·b/L = 250, прогиб по Бетти—Максвеллу x(3L²−4x²)/(48EI).

### P2 — стратегические
12. ✅ **Реализовано** (`truss::solve_nonlinear` в `mechanics-core`, op
    `truss_nonlinear`, TS `solveTrussNonlinear`). **Геометрическая нелинейность
    ферм**: коротационная формулировка (большие повороты, малые деформации,
    N = EA·(L−L₀)/L₀ в текущей конфигурации), Ньютон по касательной
    (EA/L₀·nnᵀ + N/L·(I−nnᵀ)) с нагрузочными инкрементами и адаптивным
    делением шага; глобальный бюджет итераций (20k) гарантирует остановку у
    предельной точки. LPF в ответе; за предельной точкой — `converged: false`
    с последним равновесием (arc-length вне объёма); механизм на старте
    возвращает диагностированную TRUSS_SINGULAR. Проверено: тоггл Мизеса по
    точной кривой P(y) (v = 10 мм при P = P(20) точно), линейный предел =
    truss_solve, snap-through на 400 Н стопорится у λ ≈ 0.52.
13. **Базы стандартных профилей** (EU/US/ГОСТ) — связать с mechanical-core profiles.
14. **Топологическая оптимизация ферм** (ground structure + SIMP) поверх trussScreening.
15. **Benchmark-сюита в CI**: textbook problems + NAFEMS/ANSYS Verification Manual
    (как stabileo/Pynite) — обязательный фундамент под пункты 1–9.

## 3. Предлагаемый первый шаг
Модуль `frame.rs`: балка Тимошенко 3D + шарниры + q-нагрузки + эпюры, с тестами на
классические балочные задачи (консоль, двухопорная, рама) из edubeam/Pynite verification.
Это одновременно самый запрашиваемый класс задач и фундамент для P1 (buckling, modal,
plastic hinge работают на тех же матрицах).
