# 3D по фотографиям: собственный Rust/WASM

В интерфейсе появился раздел **«3D по фотографиям»** под редактором. Это экспериментальное восстановление наблюдаемой геометрии; оно не является заменой зрелому фотограмметрическому пакету по качеству и устойчивости.

## Использование

1. Добавить 6–12 соседних резких JPEG, PNG или WebP неподвижного текстурированного предмета. Поддерживается 2–24 снимка за запуск.
2. Проверить для каждого изображения эквивалентное фокусное расстояние для кадра 35 мм. JPEG EXIF используется как подсказка. Для известных полнокадровых Canon, включая R8, допускается фактическое фокусное расстояние; для неизвестной камеры требуется ручное значение. 50 мм в пустом поле — начальное значение, не определённая калибровка.
3. Запустить восстановление камер; по желанию — глубины и поверхности. Интерфейс остаётся доступным, отмена завершает отдельный Worker. Уже полученное разреженное облако остаётся при отказе плотного этапа.
4. Сравнить цветное облако с поверхностью без текстуры. Для отзывчивости облако в просмотре ограничено 6000 равномерно выбранными точками; экспорт PLY содержит весь результат. Цвет отображается пакетами материалов имеющегося WebGPU-рендерера, без нового графического движка.
5. Скачать полный PLY. Добавить упрощённую копию поверхности в документ OpenSCAD можно только после проверки замкнутости, ориентации и связности рёбер имеющимся Rust polygon-ядром. Для открытых или некорректных сеток вставка недоступна: CAD принимает твёрдые тела. На проверенном Monstree вставка заблокирована; доступны просмотр и PLY. Копия для документа строится кластеризацией вершин на сетке 24 ячейки по максимальной стороне, с удалением вырожденных и повторяющихся граней; это потеря деталей, а не точный перенос. Для добавления требуется явно задать известную полную ширину **всей реконструкции** по X в миллиметрах. Если в скан попал фон, это не ширина предмета. Ширина используется для масштабирования, а не как доказательство точности. Документ ModelGraph не принимает вставку синтаксиса OpenSCAD.

Результат просмотра центрируется и нормализуется только для показа. Исходные координаты PLY не меняются. Фотографии и результаты находятся в памяти вкладки, не сохраняются автоматически между перезагрузками — используйте выгрузку. Нет сетевой загрузки снимков, серверов обработки, телеметрии или внешних бинарников.

## Реализация

- `crates/photogrammetry-kernel`: стандартная библиотека Rust, **нет зависимостей**.
- `crates/photogrammetry-ffi`: только два локальных workspace-модуля — ядро выше и уже существующий `value-codec`.
- WASM-модуль не имеет импортов; это проверяет сборочный скрипт. COLMAP, OpenMVS, OpenCV, Python, CUDA, новые npm/crates.io-библиотеки не используются.
- JPEG/PNG/WebP декодирует браузер; интерфейс и жизненный цикл Worker реализованы на существующем Vue/TypeScript. Собственная математика фотограмметрии выполняется в Rust/WASM на CPU.
- Фото передаются в линейную память как RGB-байты; миллионы пикселей не превращаются в объекты Value. Лимит сессии WASM: 24 изображения / 96 MiB RGB; браузер уменьшает длинную сторону до 960 px. Нативный API принимает до 200 изображений при явно отключённой совместной оптимизации и до 64 при включённой; встроенных JPEG/HEIC-кодеков нет.

Стадии: Harris трёх масштабов, ориентированные дескрипторы, взаимное сопоставление; восьмиточечный RANSAC, относительная поза, PnP и триангуляция. Ограниченные повторные старты используют общий кэш признаков и сопоставлений. После фильтрации повторно проверяется поддержка каждой камеры.

Собственная совместная оптимизация камер и точек использует Huber + LM и исключение блоков точек по Шуру. Одна поза и исходный масштаб фиксированы; intrinsics пока не оптимизируются. Отмена транзакционная. Плотная матрица по всем точкам не строится.

Плотный этап перебирает 64 обратные глубины, выбирает источники по общим наблюдениям и базису, проверяет глубину, обратную проекцию и нормали. Согласованные наблюдения разных камер сливаются; повторяющиеся грани удаляются. Глобальной замкнутой поверхности это ещё не гарантирует: возможны отверстия и частичные перекрытия. Карты — 128/192 px в интерфейсе; рабочий набор планируется с пределом 512 MiB отдельно от входного RGB.

Доступна выгрузка JSON с причинами отказов кадров, стартовыми попытками, BA, глубиной и временем. Импорт, просмотр, экспорт и Worker разделены. Готовая полная поверхность сохраняется при отказе необязательного упрощения для CAD.

## Текущая проверка после архитектурной переработки

45 Rust-тестов и 25 Vitest-тестов проходят; типы, сборка и проверка dist также прошли. В отдельной production-сборке Chrome Dev проверены:

| Набор | Камеры | Плотные вершины / треугольники | RMSE |
| --- | --- | --- | --- |
| Monstree, 6 JPEG | 6/6 | 16 092 / 12 110 | 0,302 px |
| Раковина, 12 JPEG | 8/12 | 10 027 / 5224 | 0,583 px |

PLY, JSON, просмотр, отмена и блокировка открытых сеток для CAD проверены. Поверхности по-прежнему фрагментарны. На отдельном одинаковом нативном наборе шести PPM медиана полного времени снизилась с 2,46 до 1,66 с при 6/6 камер. Ошибка проекции снизилась с 0,65 до 0,52 px, но плотная поверхность стала меньше из-за более строгих проверок. Это локальные результаты, не доказательство точности формы или универсальное сравнение скорости.

## Сохранённые результаты до архитектурной переработки

На Apple M4 Max, Chrome Dev проверены реальные исходные фотографии, не готовые камеры или модели из датасетов:

| Набор | Путь выполнения | Результат |
| --- | --- | --- |
| Раковина, edanvoye, первые 6 JPEG, уменьшение Pillow до 960 px только в тестовой подготовке | Нативный Rust, ранний прогон | 6/6 камер; 467 разреженных точек; RMSE 0,624 px; 12 754 плотные точки, 9572 треугольника |
| Раковина, первые 12 JPEG, браузерное декодирование | Rust/WASM через UI | 5/12 камер; 9368 плотных точек; 6329 треугольников; RMSE 0,61 px |
| Monstree, AliceVision, первые 6 JPEG iPhone 7 | Rust/WASM через UI | 6/6 камер; 17 669 плотных точек; 13 349 треугольников; RMSE 0,32 px |

Нативный и браузерный прогоны не являются идентичным сравнением производительности/качества: различаются подготовка пикселей и этап развития алгоритма. Числа фиксируют отдельные наблюдения. Цветное облако Monstree узнаваемо, но поверхность фрагментарна. Раковина остаётся неустойчивым случаем, большинство кадров расширенной серии не зарегистрировано. **Количество треугольников и ошибка проекции не доказывают полноту, правильную форму или миллиметровую точность.**

В зафиксированной браузерной сборке также проверены экспорт полного PLY, отмена обработки, сохранение снимков при изменении размера окна и отсутствие внешних сетевых запросов. Первоначальная попытка вставить открытый Monstree в CAD была отклонена ядром; теперь такая вставка блокируется до изменения документа.

Rust-тесты проверяют линейную алгебру, восстановление позы с выбросами, известную глубину, сопоставление с известным сдвигом, отмену и отказ на некорректном вводе. Vitest проверяет настоящий WASM, отсутствие выдуманной геометрии на пустых снимках, экспорт и неизменность исходных координат при нормализации просмотра.

Источники тестов: [раковина](https://github.com/edanvoye/photogrammetry_example_seashell) — CC BY-NC 4.0; [Monstree](https://github.com/alicevision/dataset_monstree) — лицензия в исходном репозитории не указана. Фотографии и производные модели не добавлены в репозиторий.

## Ограничения и дальнейшая работа

Нет оценки дисторсии, автоматической калибровки неизвестной оптики, масок фона, обработки RAW/HEIC, слияния карт глубины в замкнутую сетку, UV-атласа или текстурирования поверхности. Разные фокусные расстояния поддержаны интерфейсом и моделью камеры, но смешанный реальный набор Canon R8 + iPhone ещё не проверен. Блестящие, белые гладкие, прозрачные и повторяющиеся поверхности проблемны. Съёмка одного объекта после переворота без масок/совмещения не поддержана специально.

Следующие приоритеты: устойчивые признаки и минимальные pose solvers, калибровка оптики, маски, более плотные карты глубины, глобальная сетка и текстурирование. До этого результат следует считать экспериментальным, а не готовым точным сканером.

## Команды

```sh
npm run build:photogrammetry
cargo test --locked --release --manifest-path crates/photogrammetry-kernel/Cargo.toml
node node_modules/vitest/vitest.mjs run tests/photogrammetry.test.ts
```

Обычная `build:geometry` также собирает новый WASM. Он вынесен в отдельную сборку, поэтому для проверки ядра не требуется пересобирать CAD-компилятор. Нативный пример для подготовленных P6 PPM:

```sh
PHOTO_REPORT=1 PHOTO_DENSE=1 cargo run --release --manifest-path crates/photogrammetry-kernel/Cargo.toml --example reconstruct -- result.ply FOCAL_IN_PIXELS photo1.ppm photo2.ppm
```
