# Manifold — план развития: 100 пунктов

Дата: 2026-10-25. База: manifold-core (check / repair Conservative+Full / metrics / vertex links), manifold-ops (гарантированные булевы), ABI (`abi_manifold_check/repair/metrics/boolean`), TS-обёртки (`src/services/geometry/manifoldAnalysis.ts`), property-тесты, rbench-бенчмарк. Каждый пункт — самостоятельная проверяемая работа с критерием готовности.

## A. Ядро: корректность и контракты (1–10)

1. **Публичная спецификация термина manifold.** Зафиксировать в docs точные определения: строгое 2-многообразие, многообразие с краем, вершинные веера, ориентируемость. Критерий: каждый пункт check-отчёта ссылается на формальное определение.
2. **Документированные инварианты check.** Описать сложность (O(V+F) по памяти/времени), детерминированность порядка дефектов, поведение на пустом меше. Тесты на детерминированный порядок выдачи.
3. **Классификация неориентируемых компонент.** Отдельный флаг в отчёте для компонент, где BFS-ориентация осциллирует (бутылка Клейна и т.п.), вместо общего orientation_edges. Позволяет отличать «не чинится» от «не ориентируемо».
4. **Валидация входных индексов.** Явный отказ с кодом ошибки на выходящих за диапазон индексах, NaN/Inf координатах, неподходящих размерах буферов — до начала анализа, а не в середине.
5. **Политика вырожденных треугольников.** Разделить «совпадающие индексы» и «нулевая площадь при разных индексах» в отчёте; настройка порога площади.
6. **Изолированные вершины: режимы.** Опция удаления неиспользуемых вершин при repair с компактным remap-отчётом для вызывающей стороны.
7. **Счётчик компонент по многообразию.** Опция группировки компонент не по связности графа граней, а по связности через многообразные вершины (веерный критерий).
8. **Стабильные EdgeKey.** Публичная гарантия каноничности (min,max) и порядка сортировки; тесты на совпадение с mesh-topology EdgeUses.
9. **Обработка самопересечений: детекция.** Отдельный диагностический проход (BVH + точные предикаты) с отчётом пар пересекающихся граней, без repair. Это вход в пункты 41–50.
10. **Версионирование контракта ядра.** Номер схемы отчётов check/repair/metrics + тесты на обратную совместимость полей, чтобы ABI/TS не расходились молча.

## B. Repair: новые режимы и качество (11–20)

11. **Кооперативный repair.** start/step/cancel по образцу BVH/semantic-edges: большие меши не блокируют воркер, отмена освобождает scratch.
12. **Бюджеты repair.** Лимиты на число сплитов, зашитых треугольников, время/работу; при исчерпании — частичный результат с явным residual вместо зависания.
13. **Weld с пространственным хэшем.** Ускорение epsilon-weld на больших координатных диапазонах; контроль ложных склеек на малых epsilon.
14. **Weld с атрибутами.** Режим склейки только при совпадении нормалей/UV/face-id, чтобы repair не разрушал визуальные швы.
15. **Сохранение face-id при repair.** Сквозной маппинг исходных граней в результирующие (для истории моделирования и выделения).
16. **Зашивка несимпл-петель.** Обработка самокасающихся граничных петель: разрезание на простые петли с отчётом; сейчас такие петли остаются в residual.
17. **Зашивка с сохранением плоскости.** Для почти планарных петель — проекция на наилучшую плоскость с контролем отклонения; отказ при превышении допуска вместо порчи геометрии.
18. **Удаление дубликатов граней.** Режим дедупликации совпадающих треугольников (с учётом ориентации) до булевых операций.
19. **Починка ориентации по объёму.** Глобальный выбор знака нормалей компоненты по знаку объёма (outward) с отчётом о перевёрнутых компонентах.
20. **Итеративный repair до неподвижной точки.** Контролируемый цикл Full→check→Full с верхним лимитом итераций и детекцией осцилляций; отчёт по каждой итерации.

## C. Метрики и анализ (21–30)

21. **Метрики с атрибутами плотности.** Масса, центр масс, тензор инерции при заданной плотности для замкнутых многообразий.
22. **Толщина и зазоры.** Минимальная/максимальная толщина стенки (по BVH ray-cast) — ключевая метрика для 3D-печати.
23. **Диагностика самопересечений в metrics.** Флаг + счётчик пар пересечений в общем отчёте (использует пункт 9).
24. **Статистика качества треугольников.** Минимальные углы, aspect ratio, площадь по квантилям; выявление «плохих» граней для булевых.
25. **Детекция плоских регионов.** Сегментация компланарных граней для последующей упрощающей обработки (связь с пунктом 46).
26. **Кривизна и острые рёбра.** Отчёт по двугранным углам: острые/почти вырожденные кромки, полезные для визуализации и упрощения.
27. **AABB/OBB и диагональ.** Габариты и ориентированный bounding box (PCA) для проверки допусков и упаковки.
28. **Потоковые метрики.** Режим инкрементального пересчёта при локальных правках меша вместо полного прохода.
29. **Метрики в формате JSON-schema.** Стабильная сериализация всех метрик с версией схемы для экспорта отчётов.
30. **Сравнение двух мешей.** Хаусдорфово расстояние (приближённое, по сэмплам) и разница объёмов — для регрессий repair/boolean.

## D. Булевы и manifold-ops (31–40)

31. **Кооперативные булевы.** start/step/cancel и бюджеты BSP-работы, как в пункте 11; отмена без полурезультатов.
32. **Настраиваемые допуски.** Проброс Options (tolerance, work budget) через ABI с дефолтами; валидация диапазонов.
33. **Пакетные булевы.** Цепочки операций над N операндами (union всех, difference по списку) с одним pre-check и суммарным отчётом.
34. **Булевы с сохранением материалов.** Перенос face-id/групп операндов в результат, чтобы UI мог красить грани по исходному телу.
35. **Обработка касаний.** Специальные тесты и политика для соприкасающихся граней/рёбер/вершин (нулевой объём пересечения) — типовой источник нестабильности BSP.
36. **Режим «строго без repair».** Опция отклонять не-многообразный вход вместо автоматического Full-repair — для диагностических сценариев.
37. **Симметричная разность.** Четвёртая операция XOR с той же гарантией многообразия.
38. **Разбиение без объединения.** Split A по B: возврат двух частей A (внутри/снаружи B) без булева слияния.
39. **Отчёт о потерях.** Сравнение объёма результата с аналитическим ожиданием (например, для union ≤ суммы) как runtime-assert в debug/CI.
40. **Регрессионный корпус булевых.** Набор из ≥100 пар с эталонными объёмами/числом компонент; прогон в CI, включая вырожденные конфигурации.

## E. Покрытие manifold-3d (41–50)

41. **convex_hull.** Быстрый 3D-hull (quickhull) с гарантией многообразного выхода и метриками; базовая операция семейства.
42. **simplify / decimation.** QEM-упрощение с запретом топологических разрушений: после каждой серии коллапсов — check; цель по числу треугольников или ошибке.
43. **refine / subdivision.** Линейное и Loop-подразбиение с сохранением многообразия и атрибутов.
44. **slice.** Сечение плоскостью → замкнутые 2D-контуры (полигоны с дырками) в заданной плоскости.
45. **project.** Проекция меша на плоскость → 2D-полигон(ы) с учётом видимости/объединения контуров.
46. **Упрощение компланарных регионов.** Слияние компланарных треугольников в полигоны и ретриангуляция без потери формы (связь с пунктом 25).
47. **offset / shell.** Утолщение поверхности внутрь/наружу на заданную величину с честными отказами при самопересечении офсета.
48. **hull по точкам и по мешу.** Отдельные входы: облако точек (после weld) и многообразный меш; единый выходной контракт.
49. **min_gap и clearance.** Минимальный зазор между двумя телами и внутри одного тела; интеграция с BVH из mesh-query.
50. **Деформации с контролем.** Трансформации (поворот/масштаб/сдвиг/зеркало) с сохранением многообразия и корректным переворотом ориентации при отражении.

## F. Производительность и масштабирование (51–60)

51. **Базовая линия бенчей в CI.** Хранение медиан check/repair/metrics/boolean на фиксированных фикстурах; алерт при деградации >15%.
52. **Сравнение с manifold-3d.** Сьют `tools/manifold-bench` (`npm run bench:cpu`): одинаковые фикстуры, отчёт скорость/память/корректность.
53. **Профилирование аллокаций.** Учёт пиковой памяти check/repair на мешах 1M+ треугольников; устранение лишних Vec-копий.
54. **Параллелизм ядра.** Rayon для независимых фаз (подсчёт рёбер, компоненты, метрики) под native; детерминированный вывод независимо от числа потоков.
55. **SIMD/пакетная обработка.** Векторизация геометрических ядер (площади, объёмы, нормали) с побитовой сверкой результата против скалярной версии.
56. **Потоковый ввод.** Анализ меша без полной материализации f64-позиций (чанки), снижение пиковой памяти WASM.
57. **Инкрементальная топология.** Переиспользование EdgeUses/компонент при повторных вызовах на неизменном меше (кэш по хэшу буферов).
58. **Нагрузочные фикстуры.** Набор мешей 100k/1M/10M треугольников с задокументированными бюджетами времени и памяти.
59. **Масштабирование hole-filling.** Ограничение O(n²) ear-clipping на больших петлях; продвинутая триангуляция или честный отказ по бюджету.
60. **WASM-оптимизация размера.** Аудит вклада manifold-кода в размер kernel_bg.wasm; вынос редких путей, проверка отсутствия лишних зависимостей.

## G. ABI / WASM / TypeScript (61–70)

61. **Кооперативный ABI-протокол.** Единый start/step/cancel для manifold-операций с хендлами задач и освобождением по одному контракту.
62. **Типобезопасные сгенерированные байндинги.** Генерация TS-сигнатур из одного источника (список экспортов), чтобы kernel.ts не расходился с Rust вручную.
63. **Потоковая передача больших буферов.** Чанкование upload/download с контролем memory.grow; тесты на рост памяти во время вызова.
64. **Переносимость результатов.** Гарантия копирования всех TypedArray перед освобождением хендла; тесты с принудительным memory.grow.
65. **Единый код ошибок.** Таблица кодов manifold-операций (вход/бюджет/ядро) с документированными действиями для UI.
66. **Проверка версии ABI.** Хэш/версия экспорта при инициализации воркера; понятная ошибка при старом ядре с новым TS.
67. **Отмена на стороне TS.** Прерывание по AbortSignal во всех долгих manifold-вызовах с освобождением ресурсов в finally.
68. **Поддержка f32/f64 одинаково.** Тесты на идентичную семантику обоих форматов, включая предельные координаты.
69. **Минификация транспорта.** Оценка бинарного вместо value-codec для массивов метрик; цель — меньше копий и меньше GC.
70. **Смоук-тесты артефакта.** Автотест: собранный geometry-kernel.wasm содержит все manifold-экспорты и отвечает на эталонный тетраэдр (уже есть как ручной смоук — перевести в CI).

## H. Интеграция в приложение (71–80)

71. **Repair при импорте.** STL/OBJ/OFF: check → repair по выбранному режиму, диалог отчёта (сварено/удалено/зашито/остаточные дефекты).
72. **Метрики в панели измерений.** Объём, площадь, χ Эйлера, род, watertight, число компонент для выделенного mesh-тела.
73. **Гарантированные булевы в mesh-редакторе.** union/intersection/difference через manifold-ops с отображением pre-repair и причин отказа.
74. **Индикатор «не многообразие».** Значок дефектов в дереве объектов с расшифровкой по категориям (края/вершины/ориентация/вырожденные).
75. **Подсветка дефектов в 3D.** Отрисовка boundary/non-manifold рёбер и пinched-вершин из check-отчёта поверх модели.
76. **Команда «Починить меш».** Действие над выделенным телом с Undo/Redo и записью операции в историю документа.
77. **Проверка перед 3D-печатью.** Гейт слайсера: watertight + ориентация + отсутствие самопересечений; понятные сообщения о мешающих дефектах.
78. **Экспорт метрик.** JSON/CSV-отчёт по выделенным телам (объём/площадь/род/компоненты) для внешнего анализа.
79. **Фоновые задачи с прогрессом.** Все долгие manifold-операции в UI — с прогрессом, отменой и освобождением воркеров.
80. **Пользовательские настройки.** Дефолты weld-epsilon, режим repair, допуски булевых — в настройках с валидацией и безопасными значениями.

## I. Тестирование и CI (81–90)

81. **Property-тесты в CI.** Регулярный прогон всех property-кейсов с фиксированным и случайным сидом; печать сида при падении.
82. **Расширение property-наборов.** Новые инварианты: идемпотентность Full, сохранение объёма при weld=0, симметрия булевых union/intersection.
83. **Fuzzing входного транспорта.** Случайные/битые буферы в ABI: отсутствие паник и утечек хендлов, корректные коды отказа.
84. **Корпус реальных дефектных мешей.** Коллекция STL/OFF с известными дефектами и эталонными исходами repair; лицензионно чистые источники.
85. **Дифференциальные тесты против manifold-3d.** Сравнение булевых/метрик на общем корпусе в допуске, с оформлением расхождений как багов.
86. **Тесты отмены и бюджетов.** Кооперативные задачи: отмена на каждой фазе, отсутствие зомби-джобов и растекания памяти.
87. **Регрессии производительности.** Автоматический сравнительный отчёт rbench к baseline с блокировкой деградаций.
88. **TS-интеграционные тесты.** Вызовы всех manifold-обёрток на собранном ядре в воркере: метрики тетраэдра, Full-зашивка, булево объединение.
89. **Матрица окружений.** Прогон ключевых тестов на wasm32 и native, разные f32/f64 пути; отчёт о расхождениях.
90. **Политика «зелёного» мастера.** Обязательные проверки: manifold-тесты, ABI-смоук, property, TS-интеграция, без пресуществующих исключений.

## J. Документация и релизный процесс (91–100)

91. **Руководство пользователя.** Описание check/repair/metrics/boolean с примерами и ограничениями (self-intersections, несимпл-петли).
92. **Руководство разработчика.** Архитектура зависимостей mesh-topology → manifold-core → polygon-core → manifold-ops; куда что добавлять.
93. **Каталог кодов ошибок.** Все отказы manifold-операций: смысл, причины, рекомендуемые действия.
94. **Политика допусков.** Когда epsilon=0, когда >0; влияние weld на геометрию и на последующие булевы.
95. **Документация бенчмарков.** Как запускать rbench и manifold-bench, как читать медианы и ограничения методики.
96. **Changelog библиотеки.** Версионирование manifold-core/ops, записи об изменениях контрактов и ABI.
97. **CI-матрица сборки ядра.** Воспроизводимая сборка geometry-kernel.wasm с нативным wasm-opt; проверка экспортов и смоук на артефакте.
98. **Песочница-пример.** Минимальный пример «загрузил меш → проверил → починил → посчитал объём → булева операция» в одном файле.
99. **Схема расширения плагинами.** Точки подключения новых операций (hull/simplify/slice) без изменения ядра транспорта.
100. **Дорожная карта квалификации.** Критерии production-ready для каждой новой операции: контракт, property-тесты, бенч, ABI, TS, UI, документация — единый чек-лист Definition of Done.
