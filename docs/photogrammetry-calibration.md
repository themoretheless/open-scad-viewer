# Измеренная калибровка для восстановления по фото

Добавлен импорт измеренных параметров объектива и исправление фотографий перед восстановлением камер и поверхности. Автоматической калибровки по шаблону, подбора параметров по обычным фотографиям и оптимизации внутренних параметров в BA здесь нет. Без импортированной и назначенной группы программа использует прежнюю подсказку фокусного расстояния.

1. Получите измеренные параметры для конкретной камеры, объектива, фокусировки, режима и обработки изображения. Подойдут результаты отдельной калибровки с известным шаблоном, если они описывают именно указанную ниже модель. EXIF и значение «35 мм эквивалент» не являются такой калибровкой.
2. Подготовьте JSON по [примеру](./qualification/photogrammetry/calibration-example.json). **Все числа примера относятся к синтетическим камерам 320×240; это не калибровка Canon R8 или iPhone.** Тот же шаблон можно скачать кнопкой в панели.
3. Нажмите «Импорт измеренной калибровки JSON». Для каждого снимка выберите нужную группу либо примените одну группу ко всем. Импорт не угадывает соответствие камеры по имени файла или EXIF. При замене JSON прежние назначения сбрасываются.
4. Запустите восстановление. Снимки с измеренной калибровкой проходят исправление один раз в Rust; одинаковые исправленные RGB и выходная камера используются и в sparse, и в dense. Кнопка остановки завершает отдельный Worker; исходные фотографии сохраняются.
5. Скачайте отчёт JSON. `inputs[].calibration` содержит исходные параметры и размер оригинала. `sparse.calibrations[]` содержит фактически применённую группу, выходную K, увеличение focal, углы поля зрения и признак повторной выборки пикселей. Эти сведения сохраняются и при последующей неудаче регистрации камер.

## Координаты и модель

`coordinateSystem` должен быть `oriented-pixel-centers`. Координата `(0,0)` — центр верхнего левого пикселя **после применения ориентации EXIF**, ось x направлена вправо, y — вниз. `imageWidth/imageHeight` — размеры исходного ориентированного растра до уменьшения для реконструкции, а не размеры датчика. `fx/fy/cx/cy` заданы в пикселях этого же растра; перекос осей равен нулю:

```
K = [ fx  0  cx ]
    [  0 fy  cy ]
    [  0  0   1 ]
```

Для нормализованного идеального луча `(x,y)` используется Brown–Conrady:

```
r2 = x*x + y*y
radial = 1 + k1*r2 + k2*r2*r2 + k3*r2*r2*r2
xd = x*radial + 2*p1*x*y + p2*(r2 + 2*x*x)
yd = y*radial + p1*(r2 + 2*y*y) + 2*p2*x*y
u = fx*xd + cx
v = fy*yd + cy
```

Имена коэффициентов заданы явно, поэтому порядок в стороннем массиве не нужно угадывать. Fisheye, rational distortion, ненулевой skew и произвольные цифровые деформации этим форматом не описываются. Если телефон или редактор уже исправил оптику, нужны параметры именно полученного файла; нельзя повторно применять профиль для необработанного сенсора.

Группа привязана к геометрии растра, не только к модели устройства. Поворот, зеркальное отражение, обрезка, другое разрешение или изменение фокусировки могут потребовать другой группы. Проверка размера выявляет несовместимый растр, но сама по себе не доказывает верность профиля: поворот на 180° сохраняет размеры. Измеряйте калибровку в той же ориентации и обработке, что и сканируемые фотографии.

Уменьшение снимка выполняет существующий декодер. Rust пересчитывает параметры по центрам пикселей: `cx' = (cx + 0.5)*sx - 0.5`, аналогично для y; `fx'=fx*sx`, `fy'=fy*sy`. Независимое округление размеров на один пиксель разрешено, а скрытая анизотропная деформация отвергается. Пользователь не должен заранее уменьшать значения K для размера 960.

## Выходное изображение и ограничения

Выход сохраняет размер подготовленного RGB, имеет одинаковые `fx=fy=focal` и `cx=width/2`, `cy=height/2`, поэтому существующий `Image` и геометрические алгоритмы не меняются. Прямое отображение луча в измеренный снимок позволяет исправлять изображение без численной инверсии дисторсии для каждого пикселя. Используется билинейная выборка.

Недопустимые края не заливаются чёрным. Алгоритм ограниченно увеличивает выходной focal относительно `sqrt(fx*fy)`, затем проверяет каждый выходной пиксель, границы и локальную невырожденность отображения. Если полностью валидный прямоугольник не найден в пределах четырёхкратного увеличения, изображение отклоняется. `zoom` сообщает именно этот множитель focal, а не процент сохранённой площади. Доступное поле зрения уменьшается; скрытые края этим не восстанавливаются.

Ограничены размеры, число вычислений и выходная память; отмена проверяется между поисковыми шагами и строками. Native-вызов транзакционен: на ошибке или отмене вход не меняется. WASM получает профиль через существующий бинарный MGV1, хранит пиксели и provenance вместе только после успешного исправления; конфликт параметров одного group id отклоняется.

## Проверка

В [машинном отчёте](./qualification/photogrammetry/calibration-validation.json) сохранена отдельная проверка калибровочного этапа. Сравнительный тест рендерит 25 неплоских ориентиров через две разные Brown-камеры. Координаты измеряются по центроидам RGB до/после исправления и триангулируются с известными внешними параметрами. Это проверка калибровки и RGB-преобразования, не полный blind SfM и не измерение качества реального скана.

Для повторения после сборки WASM:

```sh
cargo test --offline --manifest-path crates/Cargo.toml -p photogrammetry-kernel calibration::
node scripts/build-photogrammetry.mjs
npx vitest run tests/photoCalibration.test.ts tests/photoCalibrationKernel.test.ts
```

Также проверяются identity без изменения пикселей, смешанные группы, масштабирование, неверный размер, лимиты, отмена и настоящий WASM через TS-адаптер. Общие результаты интеграции и сравнения находятся в [отчёте изменений](./photogrammetry-improvements.md).
