# Измерение и инверсия длины кривой в Rust

Три нативных API `curve_measure::length`, `point_at_length`, `divide_by_length` используют исходное рациональное определение без повторной подгонки или тесселяции. Поддерживаются 2D/3D, неединичные домены, рациональные веса, несколько knot spans, углы и остановки. Это операции над длиной геометрического пути с учётом повторного прохождения участков, не над длиной объединённого образа кривой.

## Гарантия интегрирования

Каждая ячейка находится внутри одного исходного knot span. `curve_jets` извлекает интервальные однородные контрольные данные и производные до третьего порядка с outward rounding. Локальная координата ячейки x принадлежит [0,1], поэтому длина ячейки равна интегралу `|C'(x)|` без дополнительного множителя параметрического интервала.

Интервал нормы первой производной задаёт нижнюю/верхнюю границы интеграла. Расстояние между интервальными концами даёт дополнительную нижнюю границу. Если нижняя граница скорости положительна, используется также трапециевидная формула с остатком `max |speed''| / 12`. Из

```
speed'' = (|C''|² - (unit_tangent · C'')²) / speed
          + unit_tangent · C'''
```

следует достаточная оценка `|speed''| <= |C'''| + |C''|² / min speed`. Нормы, остаток и границы вычисляются интервально с outward rounding. При нулевой или неотделённой от нуля скорости остаётся базовая интервальная граница; гладкость нормы в точке остановки не предполагается.

Ячейка с наибольшей неопределённостью делится пополам. Суммы границ округляются наружу, а перед возвратом заново суммируются по активным ячейкам. `bounds` заключает истинную длину исходной рациональной кривой, определённой записанными binary64 контрольными данными как вещественными числами. Это не сертификат отличия этих данных от идеальной аналитической фигуры, из которой они были построены.

## Контракты

- `LengthReport::value` — середина интервала. `error_upper` включает интегрирование и округление; `within_tolerance` проверяет запрошенную абсолютную погрешность в модельных единицах.
- `point_at_length` ищет параметр с ограниченным остатком между префиксной длиной и заданным расстоянием. Отрицательные и нечисловые расстояния отклоняются, расстояния выше верхней границы полной длины также отклоняются. Если запрос лежит в неопределённом интервале полной длины, гарантируется только явно возвращённый остаток до конца, не утверждение, что запрос меньше точной длины.
- `LengthPoint::point` — обычное binary64 вычисление координат. `point_bounds` отдельно заключает точную исходную рациональную точку при возвращённом binary64 параметре. `prefix_bounds`, `target_bounds` и `residual_upper` описывают гарантию длины; низкая скорость может делать параметр неединственным, поэтому точность параметра не обещается.
- `divide_by_length` ищет станции на долях i/segments истинной полной длины. Даже вычисление доли i/segments окружено интервалом. Остаток каждого префикса ограничивается относительно интервала истинной доли, без подмены полной длины её средней оценкой.
- Станции 0 и 1 фиксируются на исходных концах домена. Их целевая и префиксная длины тождественно совпадают, поэтому остаток равен нулю даже при широком интервале полной длины. Это явно учитывает корреляцию, которую независимое вычитание интервалов потеряло бы.
- Глобальный бюджет — 1..100000 построений ячеек; заменённые ячейки тоже учитываются. В inverse/division бюджет общий для полной длины и всех запросов. Начальное число активных spans сверх бюджета возвращает ресурсную ошибку.
- Деление допускает 1..1024 сегмента, inverse — не более 128 шагов. `Tolerance`, `WorkLimit`, `PrecisionLimit`, `IterationLimit`, `TargetUncertainty` различают причины остановки. `within_tolerance` всегда нужно проверять. Деление может вернуть частичный список станций при исчерпании бюджета.
- Допуск конечный и положительный. Для inverse/division он должен оставаться положительным после деления на 8. Сохраняются численные лимиты Curve; потеря отделимости рационального знаменателя от нуля и overflow возвращают численную ошибку.

## Проверки

Девять независимых тестов в `crates/nurbs-core/tests/curve_measure.rs` прошли:

```
cargo test --manifest-path crates/Cargo.toml -p nurbs-core --no-default-features --test curve_measure --quiet
```

Проверены прямая с весами 1,4 и независимой рациональной формулой инверсии, длина и ожидаемые координаты равномерного деления ломаной 5+12, окружность с неединичным доменом и аналитической длиной, четыре круговых четверти, cusp, постоянная кривая, аналитическая длина параболы, явное исчерпание бюджета, тождественное совпадение целевых/префиксных длин на концах и некорректные запросы. Для доказательства интервальной гарантии используется приведённая оценка и интервальная арифметика; конечная выборка тестов сама по себе не заменяет эту оценку.

Пример без transport:

```
cargo run --manifest-path crates/Cargo.toml -p nurbs-core --no-default-features --example curve_measure
```

WASM/TypeScript/Rush bindings в этом пакете не добавляются; Rust API доступен напрямую.

Пример выполнен без transport: длина ломаной заключена в [19.999999999999947,20.000000000000043], точка на расстоянии 15 равна [10,5,0], пять станций равномерного деления приняты. Окружность радиуса 3: [18.849520504793915,18.849719903437542], error_upper 0.00009969932181519427, 1958 построений ячеек. Эти результаты относятся к данной контрольной геометрии, не являются универсальной оценкой скорости или стоимости операций.

Финальный полный прогон с transport: 383 unit-теста, 9 измерительных интеграционных тестов, 12 тестов нативного редактирования и 2 doctest прошли (`cargo test --manifest-path crates/Cargo.toml -p nurbs-core --quiet`). Отдельный нативный прогон измерений без features: 9 тестов прошли. rustfmt и целевой diff --check прошли; аудит каталога — 99 реализованных возможностей, 101 planned в приоритетном наборе 200, ошибок нет. При частичном делении последняя возвращённая станция может быть непринятой; её within_tolerance и остаток доступны для диагностики.
