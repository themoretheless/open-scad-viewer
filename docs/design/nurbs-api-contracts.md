# Контракты новых NURBS API

Аудит охватывает семь модулей рубежа 160 и связанные проверки. Это этап согласования контрактов, а не изменение алгоритмов. Актуальный код включает также `curve_surface_agreement::verify_exact`; его точное тождество отделено от проверки с допуском.

## Совместимость допусков

| API | Смысл допуска | Область / предпосылки |
|---|---|---|
| function_surface::approximate | Верхняя граница пространственного отклонения аппроксимации | Полный прямоугольник; корректные интервалы oracle и глобальные нормы вторых производных |
| curve_pullback::project | Пространственное отклонение C(t) от S(P(t)) | Полная согласованная параметрическая трасса; не ошибка UV и не уникальность обратного отображения |
| curve_surface_agreement::verify | Пространственное отклонение C(t) от S(P(t)) | Нормализованная трасса, при необходимости обратный обход; исходная рациональная геометрия |
| shared_tessellation::tessellate | Допуск согласования швов и граница ошибки сетки | Полные прямоугольные charts и явно заданные швы; отдельные проверки швов и треугольников |
| curve_offset_wire::bevel_wire | Ошибка представления смещённого профиля | Односторонние нормальные offset-сегменты и bevel; не правильность региона |
| curve_self_intersection::inspect | Допуск, используемый ветвями анализа контуров | Это не разрешение игнорировать близкие пересечения; итог Present/Absent/Unresolved |
| surface_self_intersection::inspect | Пространственного допуска нет | Достаточное доказательство инъективности либо точное отражение homogeneous controls |
| curve_surface_agreement::verify_exact | Допуска нет | Точное тождество в поддержанной области; неподдержанный случай отделён от Different |

Пространственные значения следует интерпретировать в единицах координат вызывающего кода. Само наличие `f64` не задаёт миллиметры. Имена `error_upper_mm` в offset API требуют отдельного решения о единицах адаптеров; этот этап не меняет их семантику и не вводит скрытого пересчёта. UV-допуск, угол, кривизна и пространственное расстояние не взаимозаменяемы.

## Бюджеты

| API | Ограничения входа | Что измеряется |
|---|---|---|
| function_surface | max_cells 1..256; максимум 16 интервалов на ось | Ячейки итоговой сетки; evaluations — вызовы oracle |
| pullback | max_segments 1..256; max_iterations 1..64; agreement_cells 1..1_000_000 | Сегменты предложения, итерации поиска и общий бюджет сертификатов; отдельная verify ограничена 100_000 |
| curve self-intersection | max_cells и max_pairs 1..100_000 | Ячейки доказательства и пары участков; не треугольники сетки |
| surface self-intersection | max_spans 1..100_000 через injectivity | Исходные spans проверки инъективности |
| agreement::verify | max_cells 1..100_000 | Ячейки непрерывной проверки композиции |
| shared tessellation | 1..16 патчей; до 64 швов; segments 1..128; max_cells 1..100_000; agreement cells 1..1_000_000 | Ячейки сетки и общий бюджет согласования швов раздельно |
| offset wire | max_cells 1..65_536 через offset | Бюджет аппроксимации исходного offset; отдельные bevel могут добавляться |

Одинаковое имя `cells` не означает одинаковую вычислительную стоимость. Нельзя переносить бюджет одного алгоритма в другой без явной политики. Лимит входного параметра также не гарантирует, что алгоритм достигнет именно этого размера: действуют ограничения представления и ветвей поиска.

## Результаты и остановка

- `WithinTolerance` означает полученный сертификат; `Mismatch` — свидетельство нарушения; `Unresolved` — недостаточное доказательство. Это контракт agreement, а не универсальная семантика любой геометрической проверки.
- `Absent` и `Present` в self-intersection относятся к свойству пересечения; их нельзя механически переименовывать в успех и ошибку.
- `within_tolerance=false` в function_surface сохраняет построенную поверхность. Оно само по себе не отличает ограничение сетки от большой неопределённости oracle.
- Pullback публикует pcurve только после admission. Отсутствие pcurve и последний agreement сами по себе не дают единой точной причины остановки.
- Shared tessellation может вернуть сетку с недостаточной точностью; при непрошедшем согласовании швов сетка не публикуется. Эти исходы различны.
- Offset wire возвращает `Result<Wire>`; ошибка ресурса не является отрицательным сертификатом топологии.

Не следует получать `BudgetExhausted` только из равенства счётчика лимиту или из `within_tolerance=false`. Причину необходимо записывать в точке выхода алгоритма.

## Принятое направление реализации

Сохранять специфические отчёты и старые сигнатуры. Пока не вводить общий `Report`, общий `Status` или единый бюджет: аудит выявил разные семантики.

Первое совместимое расширение — отдельные enum причин остановки для каждого алгоритма, заполняемые в его ветвях выхода. До добавления полей в публичные структуры проверить внешние struct literals: новые поля могут нарушить исходную совместимость. Безопасный вариант — новые расширенные функции/отчёты и прежние wrappers.

После этого выделять общие валидаторы только для совпадающих инвариантов (finite positive distance, диапазон счётчика). Проверки диапазонов бюджетов остаются у алгоритма. Ни один helper не должен назначать универсальный допуск, конвертировать единицы или превращать Unresolved в доказанный исход.

Для каждого расширения проверять четыре исхода: неверный вход, подтверждённый результат, свидетельство нарушения где поддержано и исчерпание/неподдержанная область. Дополнительно проверять сохранение геометрии при неполной точности и общий бюджет вложенных сертификатов.

## Реализованное расширение: function_surface

`function_surface::approximate_detailed` возвращает `DetailedReport` с исходным `Report`, `GridStop` и `CertificateOutcome`. Прежняя `approximate` является wrapper и возвращает прежний тип. Геометрия, критерии разбиения, границы ошибок и ограничения входа сохранены.

`GridStop` фиксируется непосредственно в ветви завершения разбиения: достигнута граница интерполяции, недостаточно бюджета следующего разбиения или достигнут предел интервалов осей. При текущих ограничениях max_cells последний вариант перекрывается проверкой бюджета, но сохранён как отдельная причина внутреннего ограничения.

`CertificateOutcome` отдельно объясняет итоговый bound: WithinTolerance, InterpolationBoundTooLarge, SampleBoundTooLarge, BothBoundsTooLarge, CombinedBoundTooLarge. Последний случай означает, что каждое слагаемое отдельно не превышает допуск, но их сумма превышает. SampleBound включает неопределённость oracle и округление записанных контролей; это не утверждение о неправильности oracle. Превышение верхней границы не доказывает превышение истинной геометрической ошибки.

Расширение пока относится только к function_surface. Остальные API сохраняют прежние отчёты; их причины остановки требуют отдельной инструментализации ветвей.
