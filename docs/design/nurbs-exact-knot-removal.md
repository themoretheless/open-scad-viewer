# Exact one-knot removal

`nurbs_core::editing::exact_knot_removal::remove(source, knot, max_work)` proposes removal of one existing interior knot. It admits the existing degree1..25, 2D/3D and <=256-control Curve limits, positive conditioned weights and finite source data. Storage must be clamped and nonperiodic. Endpoint/absent knots and invalid budgets refuse input; the complete absolute domain and parameter clock must be retained.

The proposal reverses one Boehm insertion in homogeneous coordinates, copies unaffected controls/weights, and checks the actual resulting Curve against existing validation. Floating operations in this proposal are **not** assumed exact. The original source and actual emitted binary64 candidate are then supplied as two literal nominal definitions to `rational_bspline_restriction_identity`, with zero translation and the same complete domain. Exact original-knot blossom restrictions and polynomial identity must establish equality over every source/candidate overlap. No samples, small residual threshold, previous insertion history or caller proof authorizes an edit.

The distinction matters for rational insertions: rounded Cartesian poles can already change the nominal represented curve. A curve produced by an earlier floating insertion is not silently identified with its historical pre-insertion curve. Literal candidate values describe only the proposed output; they are not relabeled as an exact construction of the source. Complete identity is checked independently for those actual output bits.

On any failure, the report contains an unchanged source clone, `removed=false`, charged work and an explicit refusal. It does not emit an approximate edit. One proposal is not an exhaustive search of all possible exact representations. An invalid or different proposal does not establish that no other candidate exists. Precision/work exhaustion remains inconclusive. Source-arena setup, bounded validation and copies are outside the arithmetic ledger; every proposal floating operation is charged before execution, then the exact predicate receives only the remaining caller budget. No iteration or phase resets it. max_work stays1..=1,000,000; degree/control/weight limits are unchanged.

An accepted edit preserves the complete nominal real-valued parameterized geometry, including domain, traversal and endpoints. Binary64 evaluators may round differently after a representation change. The report is not a source-history, regularity, injectivity, B-rep, material or volume certificate. Consumers must rebuild source bindings and independently discharge their owner obligations. JSON, WASM, Rush, editor and STEP integration are not provided by this native API.

Independent public contracts cover analytic polynomial/rational laws, repeated cubic knots, 3D placement on a nonunit domain, nonuniform rational clocks, tiny and subnormal residuals, rounded rational insertion refusal, exact shared-work boundaries, invalid/periodic/unclamped input and the existing degree25 work ceiling. The upper-degree safety case permits an explicit work refusal rather than increasing the ceiling or returning an unproved edit.
