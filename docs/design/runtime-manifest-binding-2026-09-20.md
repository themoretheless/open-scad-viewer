# Runtime Manifest Binding Gap

## Reproduction

Source baseline: `c87b39ef`. Run `npm run audit:runtime-manifests` after building
the geometry kernel. This read-only diagnostic performs real mesh and B-rep
cube builds in a fresh Node process. It decodes and hashes the embedded artifact,
explicitly compiles those bytes through the existing compiler hook, requires
one shared geometry kernel load, and compares the runtime descriptors with the
selected manifests. It also compares embedded and public artifact bytes.
It publishes no qualification evidence and exits 1 on a binding mismatch.

## Cause And Consequences

`qualifiedRuntimeManifestVersion` in `src/core/geometryExecution.ts` selects an
older qualified archive when the current catalog entry is baseline-pending.
`GeometryBuildEngine` gives providers identity fields from that archive, then
checks those same fields at registration. `planGeometrySourceExecution` uses
the same archive for planned/runtime descriptors. The checks are internally
consistent but do not attest executed code.

`src/services/geometry/kernel.ts` loads current generated bytes, or a module
returned by the optional host compiler. Selecting an older manifest neither
loads its historical binary nor verifies the current one. This is manifest
fallback, not executable rollback. A valid archived digest and a successful
geometry operation do not establish a runtime artifact binding or qualification.

This is separate from the nine existing qualification tests: changing their
expected hashes would not fix runtime attribution. The audit intentionally
reports `qualificationClaim: none`, even when every byte binding matches.
Its two cubes are smoke probes, not the qualification corpus or browser proof.

## Required Correction

1. Keep historical manifests, records and frozen plans immutable.
2. Give a development build its actual artifact identity, distinct from archived
   qualification. Do not implicitly borrow qualified status from an older binary.
3. Make admission explicit: either an opted-in unqualified development mode,
   or refusal until the exact artifact has a qualified record. Preserve strict
   qualified admission and revocation rather than weakening them globally.
4. Bind both embedded and optional/network compilation paths. A generated hash
   describes packaged bytes but cannot alone attest an arbitrary compiled module
   supplied by a host. That boundary needs a verified artifact contract.
5. Update execution descriptors, worker protocol admission, MCP engine resources
   and any identity-dependent caches together. Test mismatched packaged/network
   artifacts, pending builds, revocation and actual historical rollback.
6. Separate immutable archive tests, refresh-generator fixtures and current
   runtime/qualification gates. Do not skip failures or regenerate historical
   archives merely to obtain a green CI run.

The audit exposes this defect; it does **not** repair runtime admission or claim
completion of these six steps. The choice between development admission and
strict refusal is user-visible and should be explicit before changing defaults.

## Verification

Four audit tests and 19 GeometryBuildEngine tests pass. The audit tests cover
matching pending artifacts without upgrading qualification, mismatched qualified
artifacts, each descriptor identity field, tampered manifests and planned-only
evidence. A child-process test executes both real providers and checks the exit
code against the report without requiring the existing defect to remain.
Strict TypeScript checking with the repository's HarfBuzz/WebGPU declarations
passes. The existing read-only qualification drift audit test also passes.
No qualification archive, runtime policy or production kernel was modified.
