# Exact common polynomial factor cancellation

`nurbs_core::editing::rational_factor::cancel(source,max_work)` simplifies one nonperiodic clamped rational Bezier Curve while retaining its complete original parameter law and absolute domain. This is cancellation of a common **variable polynomial** factor in all homogeneous numerators and the denominator, separate from constant weight gauges, knot removal and inverse degree elevation. For example, degree2 controls `[0,0.5,1]` with weights `[1,2,4]` represent `x(t)=2t/(1+t)`; removing `(1+t)` gives degree1 controls `[0,1]` and weights `[0.5,1]`. Merely dropping the middle control with endpoint weights `[1,4]` changes the clock.

The proposal lifts original binary64 coordinates and weights to exact rational products, converts Bernstein coefficients to power polynomials, finds their common Euclidean gcd and verifies exact division/reconstruction. It converts the quotients back to Bernstein. Starting with the primitive polynomial degree, it tries lower-than-source storage degrees until there is an exactly representable positive-weight Curve. A constant primitive uses the existing valid degree1 representation. Primitive degree2 can require degree3 storage to obtain positive weights and exactly representable Cartesian controls; a tested source still drops from degree4 to degree3. No per-control gauge or approximate control is permitted.

One global gauge clears weight denominators, removes their common integer gcd and scales the complete net by a power of two. Every output Cartesian coordinate and weight must round-trip exactly through binary64. Mixed-sign weights, an unrepresentable coordinate such as `1/3`, failed output validation, failed identity or exhausted resources emit the unchanged source with a reason. All existing coordinate, weight, conditioning, degree and control limits remain unchanged.

The independent original-definition predicate checks the ACTUAL emitted Curve, not a rounded construction history or a set of sampled points. Accepted identity preserves the complete nominal curve and clock. Evaluator bit identity, regularity, topology, trimmed-body/material certificates and reuse of old source-bound evidence are not claimed. A changed definition needs downstream revalidation. Absence of a common factor is not a general irreducibility result: knot removal and ordinary degree reduction remain separate operations.

The input class is a validated degree1..25 single clamped Bezier segment with 2D or 3D Cartesian controls and positive weights. Valid periodic, multispan and unclamped storage is explicitly outside this operation, rather than silently approximated. Invalid source/unsupported layout/budget is an input error. All mathematical refusals are atomic.

A single1..=1,000,000 ledger is shared by the rational proposal and the existing exact final predicate. Explicit rational/integer arithmetic is charged by operand words; source conversion and output conversion are charged. Fixed bounded validation, binomial constants and allocation are not a wall-time guarantee. Proposal coefficients are limited to4096 bits per numerator/denominator or integer; an operation has at most two bounded operands before its result is checked. The predicate's expansion/work limits are not raised.

For complete clamped one-span comparisons, the predicate can use the original Bernstein net directly instead of rebuilding it through de Boor blossoms. It still admits all original inputs and checks the requested range, applies one common homogeneous normalization across the entire net and retains the original cropped-range algorithm otherwise. Tests cover nonconstant degree25 nets, translation, one-ulp differences, range admission, an invalid tail weight, large finite homogeneous products, cancellation/deadline and resource refusals.

The native contracts cover rational clocks, a 3D embedding, a negative monic factor, positive elevated storage, unrepresentable and mixed-sign proposals, constant/max-degree sources, one-ulp perturbations and invalid input. The independent Python Fraction oracle reads actual Rust output from both feature modes and compares complete polynomial cross-products, including two deliberately incorrect clock/weight-sign examples. This is native-only work; WASM, JSON, Rush, editor, exchange and whole-workspace qualification remain separate.
