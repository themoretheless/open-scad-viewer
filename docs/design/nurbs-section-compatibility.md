# Согласование базиса сечений в Rust

`sections::compatible(&[Curve]) -> Result<Vec<Curve>>` принимает 2..32
валидных кривых одинаковой размерности (2D или 3D) и возвращает
сечения с едиными степенью, узлами и числом контрольных точек.
Каждое исходное активное сечение обрезается по своему домену и
clamped-нормализуется на [0,1], затем степень повышается до максимальной
и вставляются недостающие точные узлы с максимальной multiplicity.
Сравнение узлов точное; близкие узлы не сливаются по эвристике.
При нормализации проверяется, что различные узлы не слились в binary64.

В точной арифметике геометрия сечений сохраняется с аффинным
соответствием исходных параметров. Результат binary64 не снабжён
непрерывным сертификатом ошибки округления. Направления и фазы не
угадываются. Периодический ввод материализуется как clamped активный
период: геометрия периода сохраняется, periodic-кодирование не обещается.

Лимит Curve — 256 контрольных точек на сечение; вставка/повышение
степени может отклонить запрос при превышении лимита.
Сбор уникальных узлов ограничен входным набором; проверяются
исходные и промежуточные кривые. Возвращаются новые объекты,
исходный набор при отказе не меняется.

`surface::loft_aligned` использует этот же нативный конструктор базиса,
затем `surface::loft`. Для поверхности сечения должны быть 3D и
иметь не более 32 контролов по U; по V остаются линейные интервалы
между сечениями. Самостоятельное согласование допускает более сложные
кривые, которые не помещаются в ограничения Surface.

Проверки включают разные степени, веса, домены и внутренний узел;
независимые рациональные формулы сечений; воспроизведение сечений
поверхностью loft; 2D, несовместимые размерности и число сечений.
Native API не зависит от JSON/WASM/TypeScript/Rush.

Проверка: 2 интеграционных теста sections и 4 unit-теста
surface::construction_tests прошли с no-default-features.
Аудит каталога, rustfmt новых файлов и целевой diff --check прошли.

## Согласование направления

`sections::orient(&curves, ambiguity)` возвращает OrientedSections:
новые кривые и решения Anchor/Forward/Reversed/Ambiguous.
Первая кривая — неизменяемый ориентир. Для каждой следующей сравнивается
сумма расстояний между соответствующими концами и сумма перекрёстных
расстояний относительно первой кривой. Меньшая сумма определяет направление.
Если разность сумм по модулю <= ambiguity, результат Ambiguous,
исходное направление сохраняется. Порог конечный, неотрицательный,
в единицах координат; число сечений 2..32, размерности должны совпадать.

Это эвристика по округлённым точкам концов, без сертификата ошибки
сравнения и без обещания оптимальной ориентации для всей поверхности.
Она не сравнивает нормали, площадь или внутреннюю форму сечений.
Замкнутые сечения с совпадающими концами обычно неоднозначны;
выбор фазы замкнутого сечения — отдельная операция. Reverse сохраняет
геометрию с обратным параметром с точностью native binary64 операций.
Исходные объекты при отказе не изменяются. Согласование базисов отдельно.

Тест проверяет независимую пару пространственных отрезков с обратным
направлением, симметричный неоднозначный случай, увеличение порога
и недопустимые пороги. API возвращает решение для каждого сечения.

Расширенная проверка: все 5 интеграционных тестов sections прошли.
Периодические рациональные сечения после clamp/нормализации
сохраняют точки исходного активного периода, включая концы;
проверено и обратное направление. Согласование 64-контрольных
сечений допустимо, а loft корректно отклоняет превышение лимита Surface.
