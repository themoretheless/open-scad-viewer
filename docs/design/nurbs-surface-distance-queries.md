# Расстояние и ближайшая точка на полной поверхности

Типизированные API `nurbs_core::surface_distance::distance(a, b, tolerance_mm, max_cells)` и `nurbs_core::surface_distance::nearest_point(surface, point, tolerance, max_cells)` работают без codec с полными активными образами валидных положительно взвешенных 3D NURBS-поверхностей. Они включают внешние границы и узловые швы. Trim-области и B-rep топология не входят в контракт.

Поиск расстояния использует интервальные оболочки исходного рационального представления с внешним округлением и подразделение пар параметрических прямоугольников. Поиск ближайшей точки представляет запрос постоянной билинейной поверхностью и использует тот же глобальный алгоритм. Это поддерживает стационарные участки без требования регулярной нормали.

Интервал расстояния ограничивает глобальный минимум; найденные параметры, точки и их оболочки задают кандидатов. `converged` подтверждает допуск по расстоянию, а не точность UV или единственность решения. При остановке по работе или точности глобальные границы сохраняются. Положительная верхняя граница около нуля не является доказательством отсутствия пересечения.

Допуск положительный конечный; бюджет 1..100000. Число исходных пар узловых прямоугольников должно помещаться в бюджет, иначе ошибка. Неконечные запросы, некорректные поверхности и арифметическое переполнение отклоняются. Единицы совпадают с координатами входа; суффикс mm в историческом API не конвертирует единицы.

Три независимых теста `crates/nurbs-core/tests/surface_distance_queries.rs` прошли без default features: рациональная плоская панель с неединичными UV-доменами, внутренний минимум, угол и край с аналитическими расстояниями 3 и 5; полные совпадающие и параллельные панели в обоих порядках аргументов; бюджетная остановка, неверные допуски, бюджеты и NaN.
