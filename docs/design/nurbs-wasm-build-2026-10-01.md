# Сборка расширяемой NURBS-библиотеки

Обычный `build-geometry-kernels.mjs` сохраняет прежний Binaryen из npm.
Для установленного нативного Binaryen можно явно задать абсолютный путь:

```sh
OSV_WASM_OPT_NATIVE=/absolute/path/to/wasm-opt node scripts/build-geometry-kernels.mjs
```

`wasm-optimize.mjs` проверяет существование пути и совпадение версии с
major-версией установленного пакета Binaryen. Обе реализации получают
одинаковые флаги и снимок Cargo-входа; исходный Cargo-файл не оптимизируется
на месте. Ключ кеша включает содержимое выбранного инструмента, так что
нативные и npm-результаты не подменяют друг друга.

Совпадение номера версии само по себе не доказывает идентичность байтов
для произвольного модуля. По умолчанию выбор инструмента не меняется.
Проверка полного геометрического ядра выполняется отдельно.

В текущем проходе:

- `OSV_TEST_WASM_OPT_NATIVE=/Users/themoretheless/.cargo/bin/wasm-opt node --test tests/wasmOptimize.test.mjs tests/wasmOptCache.test.mjs`:
  10 тестов прошли. Проверены отказы неподходящим инструментам,
  сохранность входа, инвалидация кеша и равенство исполняемого тестового
  WASM между npm и нативной реализациями.
- Нативный Binaryen 116 оптимизировал снимок ядра с natural spline
  за 119.43 секунд wall time (`/usr/bin/time -p`), выход 9 768 255 байт.
  Во время измерения параллельно работал npm-оптимизатор. Это локальное
  наблюдение, не гарантия времени следующих сборок.
- npm-оптимизация этого же снимка ещё работает; равенство полного ядра
  пока не подтверждено. Нативный результат не опубликован вместо неё.

После завершения npm-сборки `cmp` подтвердил полное совпадение байтов
с нативной оптимизацией того же снимка. SHA-256 обеих версий:
`443d1e42433657befff0ba50a2db3d15dcc5c13850c9664d962361a48f8f4023`.
Длина: 9 768 255 байт. 194 интеграционных теста на опубликованном артефакте
прошли. Это подтверждение конкретного снимка, не универсальное доказательство
тождественности любых сборок Binaryen.
