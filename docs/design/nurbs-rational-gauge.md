# Exact common binary gauge for rational NURBS

`nurbs_core::editing::rational_gauge::{curve,surface}(source,exponent)` multiplies every stored rational weight by one exact common factor2^exponent. It retains every Cartesian control coordinate, expanded knot, degree, parameter domain and periodic storage alias. `normalize_curve` and `normalize_surface` choose one exponent making the global maximum weight lie in[1,2). This is representation normalization, not a fit or change of units.

The existing Curve validation used by both Curve and Surface requires weights in[1e-12,1e12] and conditioning at most1e12. All admissible weights are normal binary64 numbers. No integer exponent outside[-79,79] can map any input weight in this interval to an output in it. The implementation changes only the binary64 exponent field, preserving all52 fraction bits. Every possible shifted value in the requested range remains a normal finite binary64 value, and the original absolute range is checked again per weight. No approximate division by the largest weight, floating logarithm, subnormal rounding or new arithmetic/predicate allowance is used. Existing degree, control-count, coordinate, weight and conditioning limits stay unchanged.

For a rational curve or surface, both numerator and denominator are multiplied by the same exact constant, so the complete nominal parameter law and its derivatives remain unchanged. A surface uses one exponent across its entire tensor net, never separate row gauges: constant row images can conceal a changed surface when row denominators are independently rescaled. A tested example retains y=2/5 at the middle. Periodic aliases undergo the same deterministic bit change and retain their exact repetitions. Binary64 evaluator bit identity and reuse of old source-bound topology, regularity, material or B-rep certificates are not claimed; changed definitions require downstream revalidation.

Invalid source or exponent is an input error. If any output weight falls outside the unchanged range, the report identifies its flattened source index and emits no geometry; a late refusal never exposes a partially changed net. The complete output is validated again. Accepted identity exponent0 is valid. Source data remain borrowed and unchanged.

Independent tests cover nonconstant rational clocks and nonunit domains, decimal binary64 weights, very large valid weights, the global tensor gauge counterexample, periodic curve and surface aliases, late and boundary range refusals, invalid input, and the existing256×256 surface cap. A composition test aligns a right profile's gauge so the existing strict exact-curve merge can combine it while preserving both original clocks. Independently normalizing different curves does not guarantee matching endpoint gauges; explicit alignment is separate from automatic normalization. A Fraction Bernstein coefficient oracle verifies source/output rational identities and detects the nonzero residual from ordinary rounded max-division.

Native-only capability. JSON, WASM, Rush, editor and exchange admission are separate; no complete workspace or global geometry qualification is inferred from focused contracts.
