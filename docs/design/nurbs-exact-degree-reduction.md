# Exact degree reduction of piecewise rational Bezier curves

`nurbs_core::editing::exact_degree_reduction::reduce(source, max_work)` lowers degree by one, accepting only an independently proved equality of the actual original and emitted binary64 definitions on the full original parameter domain. The proposal is never accepted from samples, a small residual, construction history or rounded re-elevation.

Admission is explicitly limited to validated degree2..25, positive conditioned weights, 2D/3D, <=256-control, nonperiodic clamped piecewise rational Bezier storage. Every interior knot has multiplicity equal to the source degree. General smooth B-spline knot layouts, periodic/unclamped storage and degree1 inputs return an input error. Internal discontinuities of multiplicity degree+1 are outside this operation. This is an exact degree-reduction tool for explicit Bezier pieces, not a general NURBS simplifier or a minimality solver.

For each original piece, retain endpoint poles/weights and propose inverse homogeneous Bernstein coefficients using `D_i=(p*A_i-i*D_(i-1))/(p-i)`. The integer form avoids first rounding the ratio i/p. Arithmetic can still round; retained proposal numerators are not exact-construction evidence. Each proposed Cartesian pole is divided by its actual proposed weight and validated. The lower-degree pieces share the original join poles and original nonuniform break values; the new interior knot multiplicity is degree-1. Consequently output has fewer controls. An invalid positive-weight output or failed proof returns the complete unchanged source clone.

All proposal floating operations are charged before execution. The original-source rational B-spline restriction identity receives only the remainder of the same caller ledger1..=1,000,000, with existing expansion/degree/control limits unchanged. Bounded validation, copies, knot construction and source-arena assembly remain outside that arithmetic ledger. Work/precision exhaustion is an explicit refusal, not proof of irreducibility. A single proposal per piece may fail even when a different binary64 representation exists.

Success preserves nominal real-valued geometry, traversal and the complete absolute parameter clock, including each C0 join. Machine evaluator rounding can differ after a representation change. There is no source-history, regularity, topology, B-rep, material or export certificate. JSON/WASM/Rush/editor integration is separate.

Public contracts compare cubic-to-quadratic polynomial and nonconstant rational laws, retain nonunit unequal span domains, reject false zero from rounded re-elevation and a changed rational clock, enforce shared exact work boundaries and refuse unsupported knot layouts. This is one capability, regardless of degree, dimension or number of pieces.
