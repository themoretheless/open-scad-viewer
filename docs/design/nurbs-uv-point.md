# UV-точки и области с отверстиями в Rust

`TrimDomain::new(&[Vec<Curve>], tolerance_uv)` хранит заданные
рациональные 2D-контуры. `classify_point([u,v], max_cells)` использует
тот же консервативный алгоритм, что classify с точечным rectangle:
query расширяется на положительный tolerance_uv, кусок кривой
заменяется хордой только при исключении query его outward convex
enclosure. Это доказательство сохранения winding, а не проверка
по тесселяции. Точка должна быть конечной, max_cells — 1..100000.

Inside означает доказанный ненулевой суммарный winding,
Outside — доказанный нулевой. Unresolved оставляет winding=None
и причину/неопределённый кусок/число использованных cells.
Граница и её tolerance band, неподтверждённые joins, precision limit
и исчерпание бюджета не превращаются в ложные Inside/Outside.

Направления контуров задаются вызывающим кодом. Например, CCW
внешний контур и CW внутренний вычитают winding и образуют отверстие;
вложенный CCW контур возвращает остров. Вложенность сама по себе
не переключает направление. Два CCW контура дают winding 2 внутри
обоих и сохраняют Inside. Область определена nonzero winding rule.

Конструктор ограничен 256 кривыми и 4096 исходными knot spans;
кривые валидируются и обязаны быть 2D. Контуры не заменяют
TrimRegionAudit: роли внешнего контура/отверстий, простота и
взаимная непересекаемость требуют отдельных доказательств.
Классификация UV не выполняет 3D projection, sewing или Boolean.

Три интеграционных теста проверяют отверстие и вложенный остров,
все шесть границ, неверно ориентированное «отверстие», обратный
внешний контур, invalid input, бюджет и точную эквивалентность
точечного API rectangle API. Все прошли с no-default-features.
Native API не зависит от JSON/WASM/TypeScript/Rush.
