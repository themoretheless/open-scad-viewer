# Эвольвентные стороны шестерён в Rust

`nurbs_core::involute::approximate_quintic` строит NURBS степени 5 для аналитической эвольвенты, сохраняя положение и первые две производные на концах каждой полосы в вещественной арифметике. Положительные веса равны 1, домен нормализован в [0,1]. Максимум 51 полоса и 256 контрольных точек; недостаточный бюджет ошибки приводит к отказу.

Для шестой производной эвольвенты норма равна radius·hypot(5,theta). Оценка координатного endpoint-Hermite остатка объединяется в евклидову: sqrt(2)·max||P⁽⁶⁾||·h⁶/46080. Это непрерывная оценка в вещественной арифметике; бинарные вычисления sin/cos, контрольных точек и оценки кривой ей не покрываются. Поле real_arithmetic_error_estimate сохраняет это различие.

`brep_core::gear::gear_with_report` использует эту аппроксимацию для сторон внешних и внутренних зубьев, включая косозубой и шевронный варианты. Отражение и вращение ставят каноническую эвольвенту на сторону зуба; обратный ход сохраняет противоположную ориентацию. Ортогональное размещение сохраняет идеальную оценку. Прежние проверки в нескольких точках и возможность принять ошибку в 100 раз выше FLANK_FIT удалены. GearGeometry::flank_deviation теперь сообщает аналитическую оценку, а flank_rounding_certified=false явно сообщает отсутствие учёта округлений. Геометрия винтовой поверхности теперь использует отдельную непрерывную оценку в вещественной арифметике через nurbs_core::helical_sweep::approximate. GearGeometry::sweep_rounding_certified=false сохраняет отсутствие учёта округлений.

Для типовых шестерён степень 5 укладывается в текущий лимит поверхности 32 контрольные точки, сохраняя по одной грани на сторону зуба. Превышение лимита на других параметрах приводит к отказу. Корневой переход ниже базовой окружности остаётся радиальным, без профиля режущего инструмента и trochoid; работоспособность зацепления и прочность отдельно не доказаны.

Проверено: 2 теста Rust-ядра без default features — аналитические точки и конечные первые/вторые производные на положительных и отрицательных roll-диапазонах, бюджет и отказы; 5 тестов brep-core — независимое определение боков через радиус и полярный угол, обе стороны и направления, отказ при недостаточном ресурсе, замкнутая прямозубая модель и объём, косозубая/шевронная модели, внутренняя шестерня, малое число зубьев и неверные параметры. Полные наборы ядра и адаптеров после правки отдельно не запускались.

## Винтовой sweep

`nurbs_core::helical_sweep::approximate` строит поверхность S(u,v)=Rz(start_angle+twist·v)·C(u)+[0,0,height·v], сохраняя исходный U-базис и веса. Поддерживается 3D-кривая до 32 контрольных точек, максимум шесть quintic V-полос (31 колонка). При twist=0 используется ruled loft без аппроксимации вращения; малый ненулевой twist не заменяется нулём. Высота может быть отрицательной, исходный профиль — неплоским, twist — обоих знаков.

Для каждой контрольной точки шестая производная по v имеет норму radius_i·|twist|⁶. Оценка sqrt(2)·max(radius_i)·(|twist|/spans)⁶/46080 ограничивает endpoint-Hermite остаток вращения. Z-зависимость линейна, её идеальный остаток нулевой. Веса постоянны вдоль V, поэтому рациональный U-базис является положительной нормализованной комбинацией; максимальная ошибка контрольных траекторий ограничивает ошибку для всех u и v. Большой twist или слишком малый бюджет, требующие больше шести полос, приводят к отказу без ослабления допуска.

Два целевых теста без default features проверяют рациональный профиль независимой формулой, оба знака twist, отрицательную высоту, сохранение U-узлов, ruled-случай и отказы. После подключения пройдены все пять gear-тестов brep-core; число граней проверенных шестерён сохраняется. Отдельный флаг rounding_certified=false сообщает, что sin/cos, построение контрольных точек и вычисление поверхности в binary64 оценкой не покрыты.

Дополнительно прошли четыре целевых теста helical_sweep: периодический U-профиль с точным сохранением повторных рядов и весов, совпадение концов storage без параметрического wrapping для twist=0,+1,−1 и разных высот; осевой профиль не вычисляет несущественное вращение и остаётся корректным даже при переполнении суммы двух конечных углов. Эта ветвь имеет нулевую идеальную ошибку вращения, но не поднимает rounding_certified.

Полный повторный прогон nurbs-core без default features после periodic/axial sweep прошёл: 643 тестов в 48 наборах, без ошибок, включая doctests. JSON-тест curve_surface_agreement включается только при feature transport. Transport/WASM этим запуском не подтверждаются.
