# Общая поверхность S(u,v) в Rust

`nurbs_core::function_surface::approximate(Request, oracle)` принимает произвольную C2 функцию двух параметров через типизированный Rust callback. Функция не ограничена рациональными полиномами. Возвращается соответствующая поверхность NURBS степени 1×1 с сеткой, интерполирующей авторенные значения, и непрерывная верхняя граница отклонения от исходной функции.

Контракт callback: для каждого переданного binary64 (u,v) возвращаются три конечных интервала, содержащих точные координаты S(u,v). Request содержит глобальные неотрицательные Euclidean bounds ||S_uu|| и ||S_vv|| на всём прямоугольнике. Эти математические предпосылки задаёт вызывающая сторона; алгоритм не выводит их из выборки. Нельзя передавать обычный sin/cos как точный нулевой интервал без отдельной гарантии их округления.

Ошибка tensor linear interpolation не больше Mu*hu²/8 + Mv*hv²/8. Доказательство: сначала линейная интерполяция по одной оси, затем по другой; линейный оператор с неотрицательными весами не увеличивает supremum Euclidean norm. Mixed derivative bound не нужен. Максимальные фактические шаги вычисляются по авторенной сетке. Все арифметические операции оценки outward-rounded. К интерполяционной оценке добавляется максимальный interval radius относительно округлённых control points; положительная partition of unity ограничивает эту ошибку для всей поверхности. Это относится к математической поверхности заданных NURBS controls, а не к погрешности отдельного floating-point вызова evaluate.

Домены конечные и строго возрастающие; tolerance положительный и конечный. Бюджет 1..256 ячеек, до 16 интервалов на ось (17 controls, в пределах ограничений Surface). Сетка удваивается по оси с большей оценкой, насколько допускают бюджет и лимит оси. Недостаточная точность oracle, ограничение разрешения или бюджета возвращают поверхность с within_tolerance=false, а не ложный сертификат. Потеря различимости grid points и переполнение дают ошибку. evaluations — фактическое число обращений к oracle; cells — число ячеек выходной поверхности. Топологическая простота и регулярность не заявляются.

Независимые проверки: для S=[u,v,u²+v²] точный максимум ошибки равен 1/(4nu²)+1/(4nv²); он достигается в каждом центре ячейки и содержится в границе. Проверены число evaluations и валидность поверхности, budget=1, слишком строгий tolerance, шум oracle ±0.1, неверные интервалы, домен, производные, tolerance и budget. Дополнительно проверена неполиномиальная sqrt(1+u) поверхность с аналитической границей второй производной 1/4 и интервалами sqrt. Все 4 теста function_surface прошли. Типизированный API не зависит от viewer adapters.
