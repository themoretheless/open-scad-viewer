# Рациональные G1/G2-мосты между поверхностями

`nurbs_core::surface_blend::g1(A,B,Options)` и `g2` строят полосы между выбранными Boundary::UStart/UEnd/VStart/VEnd. Обе поддержки — валидные rational Surfaces с положительными весами. Options задаёт boundary pair, positive transverse gains, independent reversal of boundary parameters и max_patches=1..256. По умолчанию соединяются VEnd(A) и VStart(B), gains=1.

Параметр вдоль каждой выбранной границы независимо нормируется в [0,1], при reverse_u — разворачивается. Это явное affine correspondence, без автоматического нелинейного сопоставления или фазировки замкнутых контуров. Для U boundaries исходные оси внутренне переставляются. Поперечные gains измеряются в исходных единицах transverse coordinate на единицу output V. Знак определяется boundary: у A End положительный / Start отрицательный, у B Start положительный / End отрицательный, чтобы continuation направлялся от A к B.

Для homogeneous surface H=(wP,w) вычисляются полные boundary fields H0,H1 (и H2 для G2) из basis/first/second derivatives исходной transverse оси. Метод работает также с noninterpolating/unclamped boundaries. Глобальное положительное масштабирование весов каждой поддержки снимается как gauge normalization. Homogeneous XYW и Z fields кодируются двумя unit-weight polynomial curves; это позволяет выровнять degrees/knots, не смешивая рациональные Cartesian vector fields с несовпадающими знаменателями.

Cubic H-control rows: A, A+A'/3, B−B'/3, B. Quintic rows: A, A+A'/5, A+2A'/5+A''/20, B−2B'/5+B''/20, B−B'/5, B. Таким образом H и его первые/вторые transverse derivatives совпадают на всей boundary в вещественной арифметике. Совпадение полных U-dependent fields даёт также mixed/along-boundary derivatives под affine mapping. Деление на положительный homogeneous W сохраняет соответствующие Cartesian C1/C2 jets; это G1/G2 там, где source charts имеют требуемые регулярные производные. В source knots с меньшей continuity согласуются one-sided fields, исходный corner не становится гладким автоматически.

Report.real_arithmetic_order — порядок конструкции, не floating-point continuity certificate. Коэффициенты, normalization, basis alignment и Cartesian division округляются binary64. Истинная точность и normal/curvature qualification потребуют отдельной проверки. Положительные итоговые W-controls и Surface conditioning проверяются; при отрицательных/нулевых weights следует уменьшить gains. Surface validation и промежуточные Curve containers ограничивают numerical range; resource/conditioning failures возвращаются явно.

U-fields выравниваются через sections::compatible (внутренний Curve limit 256 controls), затем режутся на общие polynomial spans. Каждый Surface patch имеет degree U исходного общего basis и degree V=3 или 5; output U сохраняет соответствующий нормированный subdomain, V=[0,1]. max_patches не допускает частичного результата. Output periodic storage, original trim ownership, global regularity/self-intersection, watertight/solid topology и автоматическое исправление опор не создаются.

Проверка 2026-10-14: пять integration groups прошли offline/locked, no-default-features. Проверены разные degrees и несепарабельные weights с ненулевым W''; positions, first/second/mixed Cartesian jets с gains и reversed correspondence; unclamped supports; обе U boundaries и обе V boundaries; patch budget/invalid scales. Независимый analytic oracle y=2v/(1+v) проверяет ненулевую Cartesian second derivative даже при линейном homogeneous profile.
