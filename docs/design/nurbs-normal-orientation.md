# Проверка ориентации нормалей оболочки

Нативный API `brep_core::volume_validity::inspect` возвращает ориентацию каждой оболочки (orientations), её ожидаемую роль и независимые отчёты по предпосылкам. Он подтверждает глобальный знак только после доказательства корректной границы (точное edge/lift agreement, trim, инъективность граней и контакты) и согласованности вложенности. Одна удачная normal/ray выборка без этих предпосылок не является доказательством ориентации оболочки.

Внешняя оболочка должна иметь outward=true; внутренние оболочки полостей — outward=false. Проверяется последняя сертифицированная точка пересечения луча с оболочкой и интервальная нормаль с учётом FaceUse. На связной вложенной регулярной оболочке ориентация постоянна. Неподтверждённая boundary/nesting stage, касание/совпадение луча, исчерпание budget или неопределённая нормаль оставляют outward=None/proven=false. Периодические поверхности допускаются только при доказанных предшествующих стадиях. Никакой приблизительный объём или triangulation не используется как замена этому доказательству.

Вход: валидная B-rep топология, непустые closed shells, конечные NURBS; tolerance_uv и ограничения наследуются от отдельных стадий. Limits задаёт exact predicate work, trim, injectivity, pair contacts, nesting и orientation independently. Orientation cells 1..1_000_000, domain cells 1..8_000_000, spans 1..100_000; общие orientation counters включают все попытки и оболочки. Источник не изменяется.

Проверки: куб с наружной ориентацией доказан; глобальный разворот FaceUse определяется как inward; бюджет 1 сохраняет корректную boundary proof, но не выдаёт orientation certificate; полость внутри куба требует inward у inner shell, исправленная outward полость отклоняется; исходник сохраняется. Нулевые/сверхлимитные orientation budgets и нулевые spans дают ошибки. Все три целевых теста volume_validity прошли. Для неподдержанного/неразрешённого входа результат остаётся неопределённым — это предусмотренный контракт проверки, не отсутствие нормалей.
