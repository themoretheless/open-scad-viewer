# Структура Rust NURBS API

Первый этап реализован: `nurbs_core::domains` предоставляет десять тематических пространств имён через реэкспорт существующих модулей. Старые пути API сохранены, типы и алгоритмы не менялись. Файлы реализации пока остаются на своих местах.

| Пространство | Ответственность |
|---|---|
| geometry | Кривые, поверхности, численная основа и вычисления |
| curves | Построение кривых, формулы и инженерные профили |
| surfaces | Построение поверхностей, loft, sweep и сечения |
| editing | Редактирование и преобразования |
| joining | Сопряжения и непрерывность |
| offsets | Смещения и соединение смещённых профилей |
| queries | Измерения, дифференциальный анализ, расстояния и пересечения |
| parameterization | UV, периодические области, trim и работа с контурами |
| validation | Проверка свойств и сертификаты |
| meshing | Тесселяция и согласованные вершины швов |

Пример нового пути: `nurbs_core::domains::surfaces::function_surface::approximate`. Прежний `nurbs_core::function_surface::approximate` остаётся действительным и обозначает ту же функцию. Модуль с несколькими задачами сейчас имеет один основной раздел: например, `primitives` включает также поверхности, а `formula` обслуживает разные виды геометрии. Это навигационная классификация существующих модулей, а не окончательная декомпозиция их содержимого.

Оболочки, тела, ориентация и операции с топологией принадлежат `brep-core`. `domains` не реэкспортирует B-rep и не добавляет зависимостей. Транспорт остаётся под существующими feature gates. Физическое выделение транспорта в отдельный crate требует самостоятельного анализа совместимости.

## Карта и контроль расширения

[Карта всех 200 пунктов каталога](nurbs-api-map.md) содержит API, статус, ссылки на evidence и оставшуюся квалификацию. Planned пункты также сохранены; структура не повышает их статус. Реестр разделов: `nurbs-api-domains.json`.

`node scripts/map-nurbs-api.mjs --check` проверяет отсутствие пропущенных/дублированных публичных модулей, соответствие реэкспортов реестру и актуальность карты. После изменения каталога карта обновляется той же командой без `--check`.

## Контракты дальнейшего развития

Построение, проверка и тесселяция сохраняют отдельные результаты. Создание геометрии не подтверждает её регулярность, отсутствие самопересечений или корректность тела. Наличие сетки не заменяет геометрический сертификат.

При новых API явно описывать единицы допусков, область параметров, предположения, бюджет, причину остановки и смысл результата. Не заменять существующие специфические отчёты универсальным результатом. Отдельно различать неверный вход, доказанный отрицательный результат и отсутствие достаточного доказательства. `Unresolved` не становится положительным результатом.

Следующий этап: сравнить существующие типы допусков и бюджетов, составить таблицу совместимости и добавлять общие типы только там, где совпадают математический смысл и единицы. Затем возможен перенос реализаций по папкам с сохранением старых реэкспортов. Сквозные примеры должны связывать построение профиля, поверхности, проверку, B-rep и сетку, явно показывая границы каждого шага.

## Аудит контрактов

[Таблица допусков, бюджетов и результатов](nurbs-api-contracts.md) фиксирует различия новых API и безопасную последовательность их согласования. Единый Status/Report и универсальный бюджет пока не вводятся: одинаковые названия полей скрывают разные математические смыслы.
