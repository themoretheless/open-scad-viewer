# Первый шаг слайсера: индексированные сечения mesh

Статус: реализован Rust API `polygon_kernel::section::MeshSectionIndex`.
Это вычисление ориентированных замкнутых контуров, ещё не полный этап
`SectionGraph → RegionSet2` из [целевой архитектуры](native-geometry-architecture.md).
Browser/WASM dispatch, планировщик слоёв, интерфейс и G-code пока не подключены.
Существующая операция `section::slice` сохраняет свой контракт.

## Использование

```rust
use polygon_kernel::{cad, section::MeshSectionIndex};

fn main() -> Result<(), polygon_kernel::Error> {
    let mesh = cad::cube([20.0, 30.0, 10.0], false)?;
    let index = MeshSectionIndex::new(&mesh)?;
    let section = index.section(0.1)?;
    // Переиспользуем тот же индекс для следующих плоскостей, в любом порядке.
    let next = index.section(0.3)?;
    println!("{} {}", section.contours.len(), next.contours.len());
    Ok(())
}
```

Вход — авторитетный mesh в миллиметрах с применённым размещением детали.
Индекс владеет отдельной копией координат/связей и не зависит от renderer,
камеры или изменяемого входного mesh. `Mesh::validate` ограничивает размеры
входа и проверяет индексы/конечность координат; корректность solid не доказывает.

## Контракт

- Дерево интервалов Z строится один раз. Запрос обходит подходящие узлы,
  пересекает только треугольники с `min_z <= z < max_z` и сообщает их число
  через `candidate_triangles`. Это счётчик работы, не измерение времени.
- Вершины точно на плоскости относятся к нижней стороне. Горизонтальные
  треугольники не порождают сегментов. Поэтому нижнее сечение куба включено,
  верхнее пусто. Высота плоскости — не толщина слоя или команда Z принтера.
- Точно совпадающие 3D-вершины объединяются по идентичным координатам;
  `+0` и `-0` считаются равными. Близкие вершины не свариваются.
- Конец сегмента идентифицируется исходной вершиной или общим ребром.
  Интерполяция общего ребра выполняется в одном порядке его концов.
- Контур замкнут неявно. Winding сохраняется из ориентации треугольников:
  у согласованного тела наружная граница положительная, отверстие отрицательное.
  `source_triangles[i]` указывает источник сегмента из `points[i]` в следующую
  точку, включая замыкающий сегмент.
- Открытые границы дают `SECTION_OPEN_BOUNDARY`; дублированные или ветвящиеся
  связи — `SECTION_AMBIGUOUS_BOUNDARY`. Контур менее чем из трёх точек —
  `SECTION_DEGENERATE_BOUNDARY`. Возвращается ошибка целого запроса, частичные
  контуры не публикуются.
- Неконечная высота даёт `SECTION_INVALID_HEIGHT`, переполнение интерполяции —
  `SECTION_NUMERIC_RANGE`, различимые топологически концы, схлопнувшиеся
  численно, — `SECTION_UNRESOLVED_EDGE`.

## Граница гарантий

Результат — набор ориентированных циклов. Самопересечения, взаимные пересечения
контуров без общих mesh-вершин, вложенность оболочек, смысл материала и полнота
геометрического описания не проверяются. Изолированные касания вершины не
публикуются как отдельные события. Копланарные области не представлены явно.
Нельзя считать результат `PrintableRegionSet` или проверенным solid.

Треугольная сетка с несовпадающими швами/T-junction может вернуть открытую
границу; автоматического ремонта нет. Вычисления используют f64, без
сертифицированной оценки ошибки. Микрозазор в тесте подтверждает конкретный
случай, а не сохранение любых сколь угодно малых особенностей.

## Проверка

```sh
cargo test --locked --manifest-path crates/Cargo.toml -p polygon-kernel
cargo check --locked --manifest-path crates/Cargo.toml -p polygon-kernel --target wasm32-unknown-unknown
```

Регрессии: куб на/вокруг критических высот, полый профиль, остров внутри
отверстия, цилиндр относительно исходного многогранника, экватор октаэдра,
точные швы triangle soup, зазор `1e-10` мм, координаты около `1e12` мм,
открытая сетка, дубли/ветвления, пустой/некорректный вход и численное переполнение.
На 100 разнесённых по Z кубах (1200 треугольников) непустое сечение имеет
8 кандидатов; повторные запросы используют один индекс.

Следующий шаг: ограниченный план слоёв с раздельными `z_bottom`, `z_top`,
`sample_z`, нормализация/проверка областей с отверстиями, затем worker-протокол
и просмотр слоёв. G-code будет потребителем будущего плана траекторий.
