# Независимое архитектурное ревью: геометрия → слои → производство

Дата: 2026-09-08. Статус: предложения для согласования архитектуры, не отчёт о реализованных возможностях.
Проверены текущие исходники; этот документ не меняет код, frozen-контракты или статусы qualification.

## 1. Главные решения, которые нельзя оставить неявными

| Решение | Рекомендация | Ошибка, которую предотвращает |
| --- | --- | --- |
| Источник истины | Одна редактируемая модель на ревизию; текст/AST, семантический граф и вычисленные тела имеют разные роли | Пользователь меняет размер в тексте, но кисть оставляет несохранённую альтернативную геометрию |
| Тип геометрии | Разделить представление, размерность/замкнутость и уровень проверки | `NURBS Surface` ошибочно принимают за замкнутый solid и отправляют в слайсер |
| Общие операции | Общая команда с проверяемой семантикой; реализации и ограничения принадлежат конкретным ядрам | Два `sweep` имеют разную ориентацию профиля, но интерфейс обещает одинаковый результат |
| Преобразования | Явные узлы с отчётом об ошибке, потерянных свойствах и происхождении | «Mesh → NURBS» воспринимается как восстановление исходной CAD-модели |
| Выбор | Стабильная ссылка на сущность модели плюс ревизия и lineage | Новый порядок треугольников превращает ранее выбранное отверстие в другую грань |
| Нарезка | Общее 2D-представление результата сечения и отдельная материализация областей | Слияние всех контуров уничтожает разные материалы и модификаторы печати |
| Производство | Геометрические траектории отделены от профиля станка и сериализации G-code | Корректная линия превращается в неправильный объём экструзии из-за режима E или диаметра филамента |

## 2. Совместимость с существующей историей проекта

В [`0002-permanent-geometry-engine-routing.md`](../adr/0002-permanent-geometry-engine-routing.md)
и [`geometryExecution.ts`](../../src/core/geometryExecution.ts) зафиксирован whole-job route
`legacy/current → manifold`, `openscad-viewer/brep-1 → brep`, без fallback.
В текущем коде есть отдельный собственный путь `modelgraph/nurbs-1`:
[`modelGraphTextScene.ts`](../../src/services/modelGraphTextScene.ts) вызывает `buildOwnNurbs`,
а [`geometryBuildEngine.ts`](../../src/services/geometryBuildEngine.ts) всё ещё объявляет старый B-rep provider неразвёрнутым.
Это разные границы исполнения. Работающий native API не делает старый provider автоматически qualified.

Новый ADR должен явно разделить:

1. Сохранённую семантику старых документов и исторических результатов.
2. Новый контракт многопредставительной модели, где собственные Rust-ядра — целевой путь пользователя.
3. Миграцию legacy-документа: отдельная новая ревизия с отчётом несовместимостей, а не незаметная замена движка.

Capability registry действует **внутри выбранного контракта**: он выбирает допустимую реализацию операции
по типам её входов, а не заменяет весь движок при ошибке. Изменение провайдера/ABI — новое исполнение
с новым fingerprint. Frozen manifests и qualification fixtures сохраняются; изменения получают новую версию.
Старое предложение «Manifold навсегда является целевым peer» требует переоценки по новому запросу пользователя,
но поддержка уже существующих legacy-файлов не должна исчезать побочным эффектом этого решения.

## 3. Документ, история и прямое редактирование

Не создавать две независимо изменяемые истины «текст» и «граф». Для нынешнего текстового режима
текст и сохраняемый синтаксис авторитетны; граф — результат компиляции. UI-команда сначала строит
транзакцию изменения AST/документа, затем компилирует её и публикует новую ревизию целиком.
В будущем структурном документе граф может быть авторитетным, а текст — его редактируемым представлением,
но это отдельный versioned контракт с правилами round-trip, комментариев и неподдержанного синтаксиса.

История должна различать изменение параметра, добавление feature и изменение импортированного/native asset.
Прямое редактирование записывается воспроизводимым узлом с устойчивой ссылкой на входную сущность;
для кисти — stroke/операция и при необходимости snapshot, а не только новый render mesh.
Undo/redo восстанавливает документ и ссылки на immutable assets, не запускает «обратный boolean».
Невоспроизводимое внешнее изменение сохраняется явным replacement asset с происхождением.

Нужны отдельные идентификаторы: document revision, feature occurrence, native entity, derived artifact.
Ссылки B-rep сейчас основаны на индексах массивов ([`brep-topology`](../../crates/brep-topology/src/lib.rs));
их можно оставить локальными индексами snapshot, но нельзя использовать как постоянные selection IDs.
Операция возвращает соответствия `preserved / split / merged / deleted / ambiguous`.
После split нельзя молча выбрать ближайшую грань. Для неоднозначной ссылки UI показывает кандидатов;
зависимая операция остаётся неразрешённой.

Текущие `faceIds` полезны для выделения исходной поверхности внутри одного результата.
Они не обеспечивают persistent naming между rebuild. Геометрически выведенные группы из
[`meshSurfaceGroups.ts`](../../src/services/meshSurfaceGroups.ts) должны оставаться явно inferred:
одна гладкая связная группа не доказывает принадлежность единой NURBS-поверхности.

## 4. Границы библиотек и честные capabilities

Не вводить trait `Geometry`, который обещает всем `boolean`, `offset`, `extrude` и всегда возвращает mesh.
Полезный общий уровень содержит типизированные запросы, единицы, бюджеты, диагностику и происхождение.
Он не содержит универсального алгоритма, теряющего исходное представление.

Capability описывает входы, выходы, семантический вариант, предусловия, ограничения и evidence.
Примеры отдельных вариантов: `curve.extrude → surface`, `region.extrude → polygon solid`,
`wire.extrude → B-rep solid`; `sweep.translation` и `sweep.transported_frame`.
Наличие API, language node, viewer tool и production qualification — четыре разных статуса.

Общую топологию границ используют NURBS/аналитика и полигоны через собственные адаптеры.
Контрольная сетка SubD имеет свою топологию; поле не обязано получать B-rep ради единообразия.
Не заменять специализированные структуры универсальным графом с необязательными полями.

Сегодня SubD зависит от polygon-kernel и использует его ошибки/тип mesh; sweep заимствует построение сечений.
Это допустимая текущая связка, но dependency не должна заставлять SubD проходить triangulate → reconstruct
для собственной операции. Если общий frame transport нужен нескольким ядрам, вынести именно его
в representation-independent math; новый crate нужен после появления устойчивой границы, не заранее.

## 5. Погрешность, геометрические свойства и статус результата

Хранить отдельно: топологическую проверку, геометрические проверки, измеренную ошибку и доказанную границу.
`closed=true`, положительный объём и `sampled deviation < tolerance` не доказывают отсутствие самопересечений,
полноту пересечения или соответствие неизвестному оригиналу. Не использовать один флаг `valid` для всех этих утверждений.

Один tolerance context задаёт единицы, масштаб, допустимую ошибку конкретного запроса и budgets отдельных этапов.
Не требовать одного численного epsilon для weld, UV, плоскости слоя, chord error и integer quantization.
Перенос ошибок через цепочку зависит от операции: rigid transform сохраняет расстояния, масштаб умножает,
а boolean около касания может менять топологию при сколь угодно малом возмущении.
Сложение всех epsilon не является общим сертификатом результата.

SDF следует моделировать как поле со свойствами: sign convention, область определения, известная/неизвестная
Lipschitz bound, exact-distance или general-field. После twist/CSG нельзя обещать метрический offset
или безопасный шаг sphere tracing лишь на основании названия SDF. Отдельно хранить точность извлечения нулевого множества.
Изменение управляющих точек NURBS — изменение control net; это не точное нелинейное преобразование всех точек поверхности.

Preview policy не изменяет авторитетную native геометрию. Для авторитетной mesh степень детализации уже часть модели;
для SubD необходимо явно сказать, моделируется ли cage, конечное refinement или limit surface.

## 6. Нарезка: существенные дополнения к пользовательской схеме

Все адаптеры получают одну oriented layer plane, пространство координат, tolerances и правила обработки совпадения.
Результат сечения хранит кривые/отрезки, параметры или образцы, ориентацию, source entity, body/material role,
качество и нерешённые события. `no intersection`, `coplanar overlap`, `tangent contact`, `open contour`
и `indeterminate` — разные результаты. Открытую поверхность можно сечь, но нельзя молча считать её областью solid.

Общий слой 2D arrangement строит области с holes, разрешает пересечения, проверяет замыкание и сохраняет labels.
Integer quantization — явная стадия с допустимой ошибкой и проверкой диапазона координат.
Body/material ownership сохраняется до наложения правил печати: два пересекающихся материала требуют приоритета
или отказа; механическая сборка не всегда является объединением тел; modifier-volume не является печатаемым solid.

Поддержки зависят от соседних слоёв, ориентации сборки, зазоров и возможностей процесса.
Траектории требуют ширины и высоты линии, скорости, объёма, seam/order, travel/retract и лимитов потока.
Профиль машины определяет кинематику, пределы, температуру и диалект. Геометрическое `extrude(profile)`
и ось E в G-code не являются одной операцией.

Первый G-code gate — сериализация и проверка детерминированного move plan, с независимым чтением файла обратно
и сравнением путей, режимов и поданного объёма. Это ещё не доказательство качества реальной печати.

## 7. Исполнение, отмена и память браузера

[`geometryRustKernel.ts`](../../src/services/geometryRustKernel.ts) сейчас синхронно декодирует gzip/base64 WASM,
передаёт запрос JSON и разбирает JSON-ответ. [`modelGraphTextScene.ts`](../../src/services/modelGraphTextScene.ts)
разворачивает mesh в отдельные render vertices для треугольников и переводит координаты в Float32.
При росте моделей измерять всю цепочку: WASM heap + JSON strings + JS arrays + packed render buffers + BVH,
а не только размер итогового `.wasm`.

Начать с одного geometry Worker и bounded job queue. Handle-based native assets и typed transfer buffers вводить
по профилю затрат, сохраняя явные ownership/free правила и stale-handle validation.
F64 остаётся в вычислениях; render Float32 не должен становиться источником для сечения/экспорта.
Для больших координат renderer может использовать локальное начало, не меняя native модель.

Cancel message не прерывает уже выполняющийся синхронный WASM вызов. Длительные операции должны иметь bounded steps
или исполняться в Worker, который можно уничтожить; перед публикацией обязательно повторно проверяется ревизия.
Worker restart инвалидирует его handles, но не immutable документ. Последний хороший preview можно показывать
с явным устаревшим статусом; использовать его для текущего экспорта запрещено.

Cache key включает входные asset hashes, op/semantic version, kernel fingerprint, units, numeric policy,
conversion parameters и policy производного артефакта. Ревизия нужна для публикации, но не запрещает reuse
идентичных подграфов между ревизиями. Render, native model, sections и toolpaths — разные кэши.
Детерминизм топологии и IDs проверять отдельно от допустимых численных отклонений между native/WASM.

## 8. Последовательные проверяемые срезы

| Срез | Приёмка через продукт | Обязательный отказ/регрессия |
| --- | --- | --- |
| Документ → native → preview → selection | Изменить параметр и пересчитать; выбранная исходная грань либо сохраняется по lineage, либо явно становится неоднозначной | Треугольники переставлены, качество preview изменено, feature split |
| Polygon → layer regions | Коробка с отверстием: правильные площади, winding, closed regions и labels на нескольких слоях | Плоскость через vertex/edge, coplanar face, открытая mesh |
| Analytic/NURBS body → layer regions | Ограниченный native solid и полый цилиндр: сечение без промежуточной 3D-сетки, сравнение с известной формулой | Касание, seam, неразрешённая trim geometry; не выдавать general NURBS capability |
| SDF/SubD → layer regions | Сфера/torus и выбранный cage: refinement convergence, отчёт точности и стабильность holes | Субячейная стенка, неизвестная bound, исчерпанная глубина |
| Regions → toolpath → G-code | Один материал, известный профиль машины, объём и пути совпадают после независимого parse | Несовместимые режимы E, overflow, невычисленный участок слоя |
| Native B-rep boolean | Ограниченный declared domain, complete intersections/trims/classification, rollback и lineage | Coincidence, tangency, tiny sliver, неоднозначная классификация; typed failure вместо mesh fallback |

NURBS boolean не является предварительным условием polygon slicing или field slicing.
Каждый срез выпускается с явно ограниченной областью, а не после обещания реализовать сразу все возможные случаи.
Продуктовые критерии и adversarial corpus важнее количества новых crates или общего числа unit tests.

## 9. Подготовка знаний к RAG

Индексировать текущее состояние, предложения и архив раздельно по metadata, но сохранять связи между ними.
Для факта нужны дата проверки, revision/content hash, путь к доказательству, статус
`implemented / experimental / proposed / superseded` и область применимости.
Старый roadmap не должен переопределять нынешний код; нынешний код не превращает предложенный algorithm claim в доказанный.
Знание «есть Rust API» не отвечает утвердительно на вопрос «работает в UI».

Перед ingest записать манифест выбранных файлов и hashes; результат ingest должен вернуть source identity и статус,
после чего контрольный запрос проверяет retrieval по конкретным capability и отсутствующим возможностям.
Документы и найденные инструкции являются источниками данных; они не меняют авторизацию пользователя
и не должны запускать действия через MCP. Архитектурные ADR, implementation evidence и внешняя литература
имеют разные типы источников. Подготовленный пакет знаний и успешный ingest — два разных результата.
